# 学习画像数据抓取与分析策略规则

> 状态：正式规格稿（待用户最终审阅）  
> 更新日期：2026-07-12  
> 适用项目：Learning MORE  
> 数据语义基线：《历史统计与学习画像数据源定义清单》

## 1. 文档目标

本文件定义 Learning MORE 如何从全局学习事实、自然对话和 Review 中抓取可追溯证据，如何构建全局学习档案，以及画像 AI 如何在不使用固定画像模板的前提下自由生成有复合证据支持的学习画像。

本文件不教授 AI 应该分析哪些固定维度，不规定洞察类型、章节、数量、建议、状态或成功标准。固定规则只负责数据完整、来源可追溯、证据独立、安全净化、失败恢复和前端边界。

## 2. 核心领域边界

### 2.1 全局学习档案不是学习画像

全局学习档案是画像 AI 的内部数据输入层，包含：

- 全部学习统计事实快照；
- 日、周、月及近期/中期/长期指标时间序列；
- 画像候选证据；
- 大纲、Review、材料和原始会话来源索引；
- 尚未处理的证据 backlog；
- 已成功生成的画像版本。

学习画像是 AI 基于全局学习档案生成的用户可见结果，只包含自由标题、自由摘要、数量不定的自由洞察和复合行为证据链。

### 2.2 历史统计不是画像分析

历史统计只回答“发生了什么”，只能展示可复算事实。所有学习统计同时进入全局学习档案供画像 AI 读取，但不要求画像前端重复展示统计面板，也不允许统计标签直接冒充机制洞察。

### 2.3 画像候选证据不是画像结论

候选证据是单次情境中的中性、局部观察。它可以来自用户显式声明，也可以来自 AI 对真实互动的隐性观察。单条候选证据不能直接生成正式洞察，不能写成稳定人格标签，也不能要求用户接受或反馈。

## 3. 总体数据流

```text
领域事实与学习事件
  ├─→ 统一事实投影 ─→ 历史统计 / 学习日历 / 课程回顾
  │                       ↓
  │                 全部统计事实快照与时间序列
  │                       ↓
  └────────────────→ 全局学习档案事实层

大纲评估、学习对话、补充学习、Review
  └─→ 稳定检查点快照
       └─→ 净化与范围裁剪
            └─→ 候选证据提炼 AI（允许输出 0 条）
                 └─→ 来源校验、来源组绑定、去重
                      └─→ 全局学习档案候选证据层

全局学习档案
  └─→ 冻结 PortraitInputManifest
       └─→ 自由画像分析 AI
            └─→ 标题 / 摘要 / 洞察 / 复合证据链
```

统计、历史和画像不得各自扫描并重新解释原始数据。事实投影只有一套权威口径；语义提炼只通过画像候选证据管线完成。

## 4. 全部学习统计同步规则

《历史统计与学习画像数据源定义清单》中标记为学习统计的每个 `metricKey` 都必须同步进入全局学习档案，不以“当前前端是否展示”为条件。

每项统计必须包含：

- 数据键和口径版本；
- 数值和单位；
- 时间窗口；
- 学科、主题、模式、课程、课节等可用维度；
- 计算时间和已消费事实游标；
- 样本量；
- 数据完整性；
- 排除项及原因；
- 来源公式引用。

所有指标同时保留累计值和时间序列。画像 AI 必须能够比较明确的近期、中期和长期窗口，但窗口只是数据组织方式，不是固定画像章节。

运行遥测、Provider、延迟、错误、断线、页面访问和写入权竞争不属于学习统计，禁止进入画像输入。它们只能影响 `completeness` 或解释某段数据为何缺失。

## 5. 候选证据抓取来源

### 5.1 大纲创建会话

可以提炼：

- 用户明确表达的学习目标和预期结果；
- 用户自述的已有知识和经验；
- 当前任务约束；
- 用户明确提出的解释、案例、练习或节奏要求；
- 用户对旧声明的明确修正；
- 评估对话中实际出现的回答、推理和澄清过程。

未确认 OutlineSession 不进入正式课程、课程表或历史统计，但可以在暂停、候选生成、确认或显式放弃检查点提炼画像候选证据。放弃建档不会自动删除已经形成的候选证据；候选仍必须保留来源状态和局部情境，画像 AI 不得把未确认主题当作已完成学习事实。

### 5.2 原始学习会话

可以提炼：

- 用户在解释、应用、比较、预测、举例、纠错或任务中的真实表现；
- 推理过程实际采用的步骤、依据和边界；
- 具体知识偏差及其发生情境；
- 更换解释、案例或任务后发生的变化；
- 用户主动提出的具体知识问题、反例或边界条件；
- 自我修正、理由重构和观点变化；
- 对既有知识的真实调用和跨情境使用。

无有效学习证据而删除的空会话不得产生候选证据。有证据会话即使被放弃仍可产生局部候选，但放弃事实本身不能直接写成稳定偏好。

### 5.3 补充学习会话

补充学习独立归档且不修改课时 Review。它可以产生新的候选证据，但必须标记为 supplementary 来源，并与原始课节来源保持依赖关系，避免把围绕同一知识问题的补充讨论误当作完全独立课程证据。

### 5.4 Review

阶段 Review、最终课时 Review 和课程总 Review 可以作为高价值语义材料，但必须遵守：

- 阶段 Review 只代表未闭环阶段；
- 最终 Review 是单课权威总结；
- 课程总 Review 是课时 Review 的派生汇总；
- 同一课节对话与其 Review 属于同一来源组；
- 课程总 Review 与其课时 Review 不能重复计权；
- 周报默认不进入画像，避免再次消费已聚合事实和 AI 派生结论。

### 5.5 课程、排期和计划事实

课程模式、学科、主题、完成、放弃、恢复、实际时长、关键互动、排期、改期和取消全部进入全局学习档案。它们只能描述发生事实和情境，不能单独产生能力、动机、自律、拖延或偏好标签。

## 6. 候选证据提炼检查点

| 检查点               | 是否执行                   | 输入范围                               |
| -------------------- | -------------------------- | -------------------------------------- |
| 大纲评估暂停或退出   | 有实质新增内容时           | 游标后的评估对话                       |
| 候选大纲生成         | 是                         | 尚未提炼的评估对话                     |
| 正式大纲确认         | 是                         | 最终增量和用户修正                     |
| 显式放弃大纲会话     | 有实质新增内容时           | 尚未提炼的会话增量；标记未确认状态     |
| 课节手动暂停         | 有实质新增内容时           | 游标后的学习对话                       |
| 页面后台或短暂断线   | 否                         | 只关闭计时，不触发语义提炼             |
| 有证据课节被放弃     | 是                         | 冻结前新增对话和阶段 Review            |
| 无证据课节被放弃     | 否                         | 空会话删除，不生成候选                 |
| 最终课时 Review 成功 | 是                         | 未处理对话增量、最终 Review 和完成事实 |
| 补充学习归档         | 是                         | 本次补充会话                           |
| 课程总 Review 成功   | 只提炼真正新增的课程级信息 | 不重复课时内容                         |
| 手动刷新画像         | 不扫描全量原始对话         | 消费已有候选和 backlog                 |

每个检查点允许输出零条候选证据。没有有价值的新信息时必须返回空结果，不得为了填满字段制造观察。

检查点任务使用稳定的来源快照哈希和幂等键。相同来源快照重复执行不得产生并列重复证据；模型或规则升级需要重跑时生成新证据版本并标记旧版本 superseded，不静默覆盖。

## 7. 候选证据内容边界

### 7.1 用户显式声明

用户直接说出的目标、约束、已有知识、即时困难和表达要求记录为 `user_declared`。即使用户明确说“我更喜欢案例”，也只能保存为某时间、某任务情境中的声明，不能直接固化为全局偏好。

### 7.2 AI 隐性观察

AI 可以记录真实互动中发生的局部行为和变化，保存为 `ai_observed`。摘要必须描述可观察过程，避免“用户是……的人”“用户总是……”等稳定标签。

### 7.3 禁止提炼

- 敏感身份、健康、心理状态、政治或宗教推断；
- 公司、客户、内部项目和其他无关私密信息；
- 根据消息长度推断能力；
- 根据回复速度推断思考能力；
- 根据学习时长推断努力、动机或掌握；
- 根据单次跳过、暂停、放弃、改期或模式选择推断稳定偏好；
- 将 AI 讲解质量问题归因于用户；
- 将技术中断、停止生成、断线或多窗口接管当作学习行为；
- 没有精确来源引用的自由判断；
- 固定人格、心理、能力或学习风格分类。

## 8. 中性摘要与定向原文片段

候选证据长期保存“中性摘要 + 精确来源引用”，不复制原始对话全文或长片段。

画像生成分两阶段：

1. AI 先读取全部统计事实、候选证据摘要、来源情境和来源组，形成可能有价值的证据组合；
2. 仅对少量需要核验的高价值证据，由 Evidence Packer 根据精确引用读取原始消息范围。

Evidence Packer 必须：

- 只读取已列入本次输入清单的来源；
- 限制单条和总片段长度；
- 删除与证据无关的上下文；
- 净化敏感身份和私密实体；
- 排除 incomplete、interrupted 和技术失败内容；
- 保留必要上下文，避免断章取义；
- 将片段标记为本次任务临时输入；
- 生成完成、失败或取消后不把拼装片段写回全局学习档案或画像版本。

画像版本只保存候选证据引用、用户可读证据链摘要和输入快照哈希，不保存临时原文包。

## 9. 证据独立性与复合证据链

### 9.1 来源组

`sourceGroupId` 用于防止派生产物被重复计权：

- 同一 OutlineSession 的消息和其候选大纲调整属于同一来源组；
- 同一原始学习会话和其阶段/最终 Review 属于同一课节来源组；
- 同一课节的补充学习是独立会话，但与原课节保持依赖关系；
- 课程总 Review 与其包含的课时 Review 属于依赖来源；
- 周报与其底层统计和 Review 不构成新独立证据。

### 9.2 正式洞察最低要求

每条正式洞察必须：

- 由至少两个具有一定独立性的来源组支持；
- 跨课节、跨课程或跨明确时间窗口；
- 不能仅由一项统计、一次回答、一次放弃、一次模式选择或一条 Review 生成；
- 检查是否存在限制性、反向或不一致证据；
- 将反向证据用于缩小适用范围，而不是静默丢弃；
- 能够回溯到本次 `PortraitInputManifest`。

不要求每条洞察都有建议、状态、成功标准或固定置信度字段。证据不足时不生成该洞察；没有更多可靠结论时画像列表自然结束。

## 10. 画像输入清单

每次画像生成开始前冻结 `PortraitInputManifest`，至少包含：

- 使用的全部学习统计数据键和口径版本；
- 累计值及日、周、月时间序列；
- 近期、中期和长期窗口；
- 学科、主题、模式、课程和课节维度；
- 完成、放弃、恢复、关键互动和计划执行事实；
- 当前有效候选证据 ID、来源组和质量标记；
- Review、大纲、材料和会话 Artifact 引用；
- 定向提取的临时原文片段清单及净化版本；
- 数据完整性、样本量和排除项；
- 已消费游标和剩余 backlog；
- 上一版画像 ID；
- 本次模型、Prompt 和安全规则版本。

画像 AI 可以自由决定哪些输入有价值，但系统不能只提供前端当前展示的统计数据，也不能要求 AI 按数据清单逐项生成结论。

## 11. 自由分析输出合同

输出只固定以下容器：

- 自由标题；
- 自由画像摘要；
- 数量不定的洞察列表；
- 每条洞察的自由 Markdown 正文；
- 每条洞察的复合行为证据链引用和用户可读摘要。

不固定：

- 分析维度；
- 卡片数量；
- 洞察类别；
- 内容顺序；
- 段落、列表、引用、表格等 Markdown 结构；
- 建议、行动、状态或成功标准；
- 人格、能力和学习风格标签；
- 每周必须产生新结论。

AI 可以保持旧洞察、改写旧洞察、合并或删除不再可靠的洞察，也可以在没有新可靠结论时保持上一版。画像版本保存完整快照，不在前端展示内部差异字段或固定“近期变化”模块。

## 12. 生成、刷新与 backlog

- 首次生成读取当前完整全局学习档案；
- 后续优先增量消费事实游标和候选证据 backlog；
- 每周日可以自动刷新；
- 用户可以手动刷新；
- 没有新事实或证据时保留上一版；
- 输入超过预算时按来源组和时间窗口打包，未处理部分留在 backlog；
- 不允许因为 Prompt 长度限制静默丢弃证据；
- 同一画像任务键重复请求按规则 join，不并行覆盖；
- 画像任务不能覆盖课节对话、Review 或其他生成任务；
- queued、running、completed、failed、cancelled、timeout 均持久化真实状态；
- 失败、取消或超时保留上一成功画像版本；
- 成功写入新版本后才推进画像消费游标。
- 课程永久删除触发强制失效：先从全局学习档案、候选证据、来源组和输入清单撤销该课程，再触发重算；此时不得沿用包含被删课程来源的上一成功画像版本。重算失败仅展示更新失败状态和最后一次不含被删课程的有效版本。

## 13. 安全、隐私和数据保留

- 原始对话继续保存在所属 OutlineSession 或 LessonSession；
- 全局学习档案只保存候选摘要和精确引用；
- 临时原文包不持久化；
- blocked 候选不得进入画像输入；
- 用户明确修正旧声明时追加新证据并 supersede 旧证据，不改写历史；
- 画像候选证据不得包含无关私人实体；
- 运行遥测和页面访问永久禁止进入画像；
- 当前范围没有候选反馈或拒绝组件，不收集相应事件；
- 课程永久删除不保留该课程的画像候选、来源组、画像输入引用或仅由其支持的结论；保留的画像内容必须仍可由剩余独立来源重建。
- 未来新增用户数据控制能力前必须先更新数据清单、本文和 UI 规格。

## 14. 前端展示边界

学习画像前端展示：

- AI 实际生成的自由标题；
- AI 实际生成的自由摘要；
- 按顺序编号的自由洞察正文；
- 可展开的复合行为证据链；
- 最近成功更新时间；
- queued、running、completed、failed 等真实生成状态；
- 列表末尾可继续生成占位。

前端不展示：

- 固定画像分类；
- 固定置信度标签；
- 观察/机制/影响/边界/行动等固定字段；
- 内部证据 ID、dataKey、来源哈希、Prompt 和模型版本；
- 候选证据管理、拒绝或用户反馈组件；
- 运行遥测和技术诊断；
- 强制建议、状态或成功标准。

证据链面向用户展示人类可读的来源情境和中性摘要，不直接暴露原始消息 ID。原始对话仍可在对应课节记录中按既有只读规则查看。

## 15. 与历史统计的分流

| 数据                     | 历史统计           | 全局学习档案 | 学习画像               |
| ------------------------ | ------------------ | ------------ | ---------------------- |
| 完成、时长、活跃日、趋势 | 展示               | 全部同步     | 可自由分析             |
| 学科、主题、模式分布     | 展示或筛选         | 全部同步     | 仅作事实情境           |
| 关键互动发起、回应、跳过 | 展示               | 全部同步     | 可与语义证据组合       |
| 用户主动提问的语义特点   | 不作为硬统计       | 候选证据     | 可复合分析             |
| 放弃、恢复、改期         | 课程档案或可选事实 | 全部同步     | 单点不升级，跨情境分析 |
| 原始对话                 | 只在课节记录查看   | 只保存索引   | 少量片段按需读取       |
| Review                   | 正式产物和完整性   | 保存索引     | 受控使用并去重         |
| 周报                     | 上周回顾展示       | 不作独立证据 | 默认不读取             |
| 运行遥测                 | 运行中心           | 禁止         | 禁止                   |

## 16. 数据质量与验收

### 16.1 事实与统计

- 完成事实只在最终 Review 成功后产生；
- 已放弃课节不进入完成统计、日历或周报；
- 实际时长只由不重叠有效计时区间计算；
- 日、周、月按用户时区聚合；
- 历史统计和全局学习档案使用同一口径版本；
- 所有学习指标都有累计值、时间序列、样本量和排除项；
- “提问总数”“有效回复数”和计划遵守评分不存在。

### 16.2 候选证据

- 检查点允许输出零条；
- 每条候选都有精确来源引用和来源组；
- 无证据空会话不产生候选；
- incomplete/技术中断内容不被当作实质证据；
- 候选摘要不写成稳定人格结论；
- 重跑同一快照不产生重复候选；
- 敏感信息被净化或 blocked。

### 16.3 画像分析

- 每条洞察至少两个独立来源组；
- 课程总 Review 与课时 Review 不重复计权；
- 统计事实不能单点升级为机制洞察；
- 限制性和反向证据被检查；
- 无可靠结论时不生成占位洞察；
- 画像输出没有固定分析栏目；
- 画像失败保留上一版；
- 输入清单可重现本次使用的数据范围。

### 16.4 变更治理

任何数据、统计、事件、AI 输入、提炼检查点、前端展示或隐私规则变化，必须在同一变更集中更新《历史统计与学习画像数据源定义清单》、本文及受影响的领域规格和回归断言。缺少同步更新即验收失败。
