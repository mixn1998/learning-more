# Learning MORE 全页面控件交互闭环与视觉统一改造设计

> 日期：2026-07-13  
> 适用目录：`docs/UI视觉预览`  
> 状态：待用户确认后进入实施计划

## 1. 设计目标

本轮改造覆盖 `docs/UI视觉预览` 中全部 27 个当前 HTML 样稿，解决三类问题：

1. 控件存在但点击无反应、跳转丢失、状态不联动或被浮层遮挡；
2. 静态样稿中的 AI、文件解析和持久化操作缺少可观察的模拟反馈；
3. 字号、行高、留白、白底内容层和滚动容器不统一，导致文字粘连、遮挡和视觉失衡。

目标不是把静态样稿变成生产应用，而是让每个样稿成为可完整体验、可验证目标行为的交互规格。正式应用仍由 React + TypeScript 重写。

## 2. 已确认原则

- 所有可交互控件必须产生可观察结果，不允许无效 `href="#"`、点击无反应或只改变鼠标样式。
- 前端本地状态操作必须形成完整闭环，包括筛选、选择、弹窗、步骤切换、排期、取消排期和计划流确认后的状态变化。
- 真正依赖 AI、文本解析或持久化的数据操作使用明确的模拟状态：`处理中 → 成功`，必要时提供可恢复的模拟失败；不得假装已经真实写入后端。
- 九种模式使用独立入口展示文案；这些文案只影响 UI，不作为隐藏 Prompt、课程模块或教学方法约束。
- 主页周历和学习日历中的课节内容块统一白底；模式色只作用于外层日期卡、选中状态和身份标识。
- 状态色与玩法色继续分离：成功、警告、错误、已放弃和只读使用全局状态色。
- 已确认的课程、Review、放弃恢复、历史和运行服务业务规则不得因样稿模拟而改变。
- `01–07` 功能域中的产品页面只呈现真实产品界面，不显示“样例说明”“使用提示”“方案标题”或调试场景工具；说明文字进入 README、设计文档或验收矩阵。只有 `00-设计系统` 可以保留组件教学说明。

## 3. 方案选择

采用“共享样稿交互运行层 + 功能域控制器”。

不采用逐页零散补丁，因为它会继续复制 Toast、弹窗、加载态和状态切换逻辑；不提前重写 React，因为当前阶段仍在确认产品规格，过早引入生产框架会扩大改造范围。

### 3.1 共享交互运行层

新增 `00-设计系统/assets/sample-interactions.js`，仅服务静态样稿，提供：

- `showToast(message, tone)`：普通、成功、警告、错误反馈；
- `runSimulation(options)`：统一管理按钮禁用、处理中、成功和失败恢复；
- `openDialog(dialog)` / `closeDialog(dialog)`：按钮、遮罩和 Escape 行为一致；
- `navigate(href)`：样稿内安全导航，拒绝空目标；
- `setPressed`、`setExpanded`、`setBusy`：同步 ARIA 状态；
- 页面级模拟状态存储，刷新页面后允许恢复默认样例，不伪装持久化。

共享层只管理交互机制，不理解课程、课节或计划流业务。

### 3.2 功能域控制器

复杂页面分别使用小型控制器：

- 主页：模式选择、动态入口文案、上传模拟、周历与课节导航；
- 建档与大纲：对话模拟、调整、确认创建、修改发布和版本记录；
- 课程规划：日期/栏位筛选互斥、排期、改期、取消和预览；
- 计划流：四步状态机、课程筛选选择、策略单选、完整预览和确认管理；
- 课节学习：发送、流式模拟、停止、暂停、放弃和状态返回；
- Review 与档案：Tab、会话切换、周报展开和只读导航；
- 历史与画像：筛选、月份切换、记录导航、画像设置和刷新模拟；
- 运行中心：Provider、服务状态、自愈、版本同步和跨页面状态。

控制器只操作所属页面，不建立跨功能域的隐藏全局状态。

## 4. 控件结果契约

每个控件必须属于且只属于以下一种结果类型：

| 类型 | 点击后必须发生的结果 |
| --- | --- |
| 导航 | 跳转到存在的当前样稿，并落到正确页面或 Tab |
| 选择 | 选中态、ARIA、汇总数字和相关内容同步变化 |
| 筛选 | 列表、结果数量、空状态和互斥条件同步变化 |
| 弹窗 | 打开正确内容；关闭按钮、遮罩和 Escape 行为一致 |
| 本地编辑 | 页面内数据立即更新，可执行反向操作恢复 |
| 模拟异步 | 显示处理中，完成后显示成功结果；失败时恢复按钮并保留旧状态 |
| 不可用 | 控件明确禁用并说明原因，不保持可点击外观 |

链接不得使用 `href="#"` 充当占位。按钮若暂时不能实现目标，必须改为禁用状态或接入模拟反馈。

## 5. 按功能域的交互闭环

### 5.1 设计系统

- “次要操作”展示普通 Toast；
- “主操作”展示处理中到成功；
- “危险操作”打开确认弹窗，取消与确认均有结果；
- 九模式身份页只展示 Token，不增加伪业务动作。

### 5.2 主页与九模式入口

- 九张模式卡切换标题问题、输入示例、辅助说明、CTA、色系和阅读上传区；切换不清空用户已输入主题。
- 各模式入口展示文案：

| 模式 | 标题问题 | 输入示例 |
| --- | --- | --- |
| 标准模式 | 你想系统学习什么？ | 我想系统提升游戏设计能力，学会设计有持续吸引力的核心循环 |
| 头脑风暴 | 这次想打开什么可能性？ | 怎样设计一款成年人愿意每天打开的学习产品 |
| 论证交锋 | 你想检验哪个主张？ | 远程办公究竟提高还是降低知识工作生产率 |
| 案例研习 | 你想研究什么真实情境？ | 为什么有些产品增长很快却留不住用户 |
| 商业洞察 | 你想看懂什么价值或机会？ | 中国小众香水行业还有什么新机会 |
| 流程拆解 | 你想把什么事情理清并推进？ | 怎样从游戏创意推进到可玩的第一版原型 |
| 决策分析 | 你正在面对什么选择？ | 我是否应该离职转向独立产品开发 |
| 交叉探索 | 你想换几个角度重新理解什么问题？ | 为什么 AI 时代写作反而变得更重要 |
| 阅读研讨 | 你想怎样阅读这份材料？ | 建立《系统思考》的全书框架，并用于分析团队反复救火的问题 |

- 阅读研讨“选择文件”使用真实本地文件选择器，限制 PDF、TXT、MD；选择后显示文件名、模拟解析状态和移除入口。
- 提交主题后进入对应建档样稿；阅读研讨允许材料存在而主题为空，并在建档对话中继续澄清。
- 周切换、返回当周、日期选择和今日课节导航继续联动；周历课节块统一白底。

### 5.3 建档、修改大纲与正式课程大纲

- 对话发送：把用户输入追加为右侧气泡，显示 AI 生成中，再追加无框 AI 模拟回应；空输入不发送。
- “继续调整”聚焦输入区并展示当前候选大纲等待调整，不直接改写课程。
- “确认并创建课程”显示原子创建模拟，成功后进入正式课程大纲。
- 修改大纲“确认并发布 v2”显示发布模拟，成功后回到正式课程大纲并体现版本已更新提示。
- “大纲版本记录”改为真实弹窗，展示 v1、v2、发布时间和当前版本；不再使用 `href="#"`。
- 课程关闭前的主题总结保持禁用，并解释“课程关闭后可查看”。

### 5.4 课程规划

- 左侧七天日期卡整体点击，筛选右侧该日期课节；日期和栏位筛选继续互斥。
- “点击安排学习日期”打开日期选择弹窗；确认后卡片转为已安排并显示“改期 / 取消排期 / 预览”。
- 改期使用同一弹窗，确认后更新日期卡和课节列表。
- 取消排期必须二次确认；确认后恢复“待规划”，同时更新左侧日期内容。
- 排期、改期、取消均显示成功 Toast；模拟失败不改变旧日期。
- 预览沿用课节导航结构，只显示核心知识点和关闭按钮。
- 日期栏标题与说明上下分块，避免“今日起 7 天点击日期筛选右侧课节”粘连。

### 5.5 计划流

计划流继续是课程规划上的固定大弹窗，不变成独立业务页面。

- 删除页面最外层“计划流：固定大弹窗四步向导”及其 sample 使用说明；补齐标准 `doctype / html / head / body` 和统一设计系统依赖。
- 结构固定为头部、步骤栏、唯一滚动内容区、底部操作栏。
- 筛选工具栏进入第二步内容的正常文档流，位于课程网格上方；不使用覆盖课程卡的粘性浮层。
- 课程超过四门时使用双列网格，由内容区统一滚动；筛选栏不拦截课程卡点击。
- 第一步：学习日、日期、时长和策略开关实时更新摘要。
- 第二步：搜索、领域筛选和“只看已选”联动；整体课程卡可选；至少选择一门才能继续。
- 第三步：三种策略严格单选；“按优先级”时显示可调整课程顺序。
- 第四步：根据当前模拟状态重建完整自然日预览，不截断日期；显示超目标、固定排期和预计完成信息。
- “上一步 / 下一步 / 点击步骤”遵守校验：第一步要求有效开始日期、至少一个学习日和正时长；第二步要求至少一门课程；第三步始终有且只有一种策略；只能无条件返回已完成步骤，不能越过未通过的前置步骤。错误原因显示在底部操作附近。
- 关闭或取消返回课程规划，不改变排期。
- “确认生成计划流”显示写入模拟；成功后关闭向导并展示活动计划流管理卡，汇总课程数、课节数、学习日、每日目标和预计完成日期。
- 管理卡的暂停、恢复、重新排剩余和删除均形成可逆前端状态；删除使用危险确认。

### 5.6 正式课节学习

- “发送”追加用户气泡并模拟渐进式 AI 输出；生成中可点击停止。
- 暂停停止样稿计时并改变按钮和状态；恢复继续累计。
- 结束本课打开未闭环确认；“继续学习”关闭弹窗。
- “确认放弃课节”显示冻结/阶段 Review 模拟结果，再返回正式课程大纲并显示已放弃状态。
- AI 发送、Review 生成和持久化只做明确模拟，不改写权威业务规则。

### 5.7 Review、课节记录与上周回顾

- 课时 Review 弹窗继续只有“返回课程大纲”和“查看课节记录”；Escape 等效返回。
- 课节记录双 Tab 和内部会话列表均可切换；只读内容不显示编辑按钮。
- 上周报告标题栏整体可点击，`+ / −`、`aria-expanded` 和正文状态一致。
- 上周日期筛选与标签筛选互斥；课节卡整体点击进入课节记录。

### 5.8 历史统计、学习日历与学习画像

- 历史统计筛选必须实际改变趋势、分布或课程列表，不只改变按钮颜色；无结果显示空状态。
- 学习日历月份箭头切换月份、标题和日期网格；已完成课节只出现在实际完成日期。
- 日期选择更新右侧详情；课节卡整体点击打开课节记录。
- 学习画像“画像设置”打开设置弹窗；“刷新画像”显示 AI 模拟生成过程，成功后更新时间和样本窗口，不伪造新的具体画像结论。

### 5.9 运行中心

- 删除页面最外层“统一运行中心”说明、subtitle 和可见调试场景切换栏；故障场景改由 URL 查询参数或自动化测试注入，不占用用户界面。
- 两个全局胶囊继续进入正确 Tab；所有 Provider、诊断、自愈和版本按钮必须有处理中与结果。
- 关闭返回来源页面；无法确定来源时返回主页。
- 模拟运行遥测不进入学习统计或学习画像。

## 6. 统一排版与视觉规则

### 6.1 排版令牌

在 `base.css` 增加统一排版变量：

- 正文：14px / 1.65；
- 次级说明：12px / 1.55；
- 控件文字：13px / 1.35；
- 小标题：18–20px / 1.35；
- 页面标题：28–36px / 1.2；
- 仅状态辅助信息允许 11px，不再使用 7–9px 承载必要内容。

中文标题避免过度负字距。标题、正文、标签和控件分别使用固定层级，不在页面中任意缩放。

### 6.2 间距与控件

- 基础间距使用 4、8、12、16、24、32px；
- 桌面按钮和输入控件最低 42px，主要操作最低 44px；
- 卡片正文内边距不低于 16px；
- 相邻标题和说明至少保留 6px，说明与下一组件至少 12px；
- 长中文允许自然换行，不使用固定高度裁切正文。

### 6.3 白底内容层

- 周历和学习日历中的具体课节块统一 `#fff`，使用浅边框区分层级；
- 外层选中日期允许使用模式浅色；
- 课程卡、课节卡和对话正文不随玩法使用整块高饱和背景；
- 玩法色用于边框、图标、徽标、用户气泡和局部进度。

### 6.4 滚动规则

- 页面不得同时出现无必要的双层内部滚动；
- 计划流只允许内容区滚动，头部、步骤栏和底部保持可见；
- 课程规划桌面端左栏无内部滚动，七张日期卡等分铺满；右侧内容超出时内部滚动；
- 移动端恢复自然单列和页面滚动。

## 7. 错误与模拟反馈

- 模拟异步默认 500–900ms，足以表达状态但不制造等待感。
- 处理中禁用重复提交；完成后恢复或进入下一状态。
- 失败反馈必须说明“这是样稿模拟”，并保留原状态。
- 禁止使用浏览器原生 `alert`；统一使用 Toast、内联错误或确认弹窗。
- 任何错误不得让控件永久禁用、遮罩无法关闭或页面失去返回路径。

## 8. 交互验收矩阵

新增 `docs/设计文档/UI全页面控件交互验收矩阵.md`，每个控件记录：

- 页面与控件名称；
- 初始状态；
- 操作；
- 预期视觉变化；
- 预期数据或导航变化；
- 反向操作；
- 桌面、移动端和键盘结果；
- 自动化验证状态。

验收不以“页面无报错”为完成标准，而以每个控件的目标结果实际发生为完成标准。

## 9. 自动化与人工验证

### 9.1 静态检查

- 所有本地 `href` / `src` 目标存在；
- 无 `href="#"`；
- `01–07` 的每个 HTML 均具有完整文档结构，且不存在产品壳之外的 sample 标题、说明或调试控件；
- 非展示按钮必须具有控制器绑定或明确禁用原因；
- 无废弃术语和重复当前稿。

### 9.2 浏览器交互检查

- 对每个可用控件执行点击、输入或选择；
- 验证 URL、Tab、弹窗、列表、汇总、Toast 和状态变化；
- 验证关闭、取消、恢复和删除等反向路径；
- 检测遮挡：目标控件必须可点击且点击点不被其他元素截获；
- 检测控制台错误和未处理 Promise。

### 9.3 视觉检查

- 1440×1000、1024×768、390×844 三种视口；
- 检查横向溢出、文字粘连、不可读小字、遮挡、双滚动、按钮被裁切和卡片高度异常；
- 重点截图对比主页、课程规划、计划流、正式课程大纲、正式学习、Review、学习日历和画像。

### 9.4 键盘与焦点

- 可点击卡片使用原生按钮或链接，Enter 与 Space 行为一致；
- 弹窗打开后焦点进入弹窗，Tab 不离开弹窗，关闭后焦点回到触发控件；
- Escape 只执行已定义的安全关闭或返回行为；危险确认不得由 Escape 误触发；
- 选中、展开、处理中和禁用状态同步 `aria-pressed`、`aria-expanded`、`aria-busy` 与 `disabled`。

## 10. 实施顺序

1. 建立共享交互层、排版令牌和验收矩阵；
2. 修复主页动态文案、白底课节块和文件上传模拟；
3. 重构课程规划与计划流，先消除遮挡和核心交互失效；
4. 接通建档、大纲、学习与 Review 控件；
5. 接通历史、日历、画像、设计系统和运行中心控件；
6. 执行逐控件自动化、三视口视觉回归和文档同步；
7. 只在矩阵无未验证项后结束本轮改造。

## 11. 非目标

- 不接入真实 AI、文件解析服务或 Repository；
