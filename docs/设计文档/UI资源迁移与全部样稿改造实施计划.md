# UI 资源迁移与全部样稿改造实施计划

> **For agentic workers:** 按任务顺序在当前工作区直接执行；每个任务完成后必须通过对应静态检查和浏览器检查再进入下一任务。

**Goal:** 将现有平铺、混合职责的 UI HTML 样例迁移为按功能域与课程生命周期分类的唯一当前稿，并完成主页九模式入口、九模式全宽建档工作台、渐进式视觉身份和完整课时 Review 弹窗。

**Architecture:** 静态样稿继续使用原生 HTML/CSS/JavaScript，但把跨页面视觉令牌、九模式主题注册表和通用样例壳集中到 `00-设计系统/assets`。不同产品路由拥有独立 HTML；同一路由的状态变化保留在同一交互样例中。迁移过程先建立新结构并验证，再删除旧混合文件。

**Tech Stack:** HTML5、CSS Custom Properties、原生 JavaScript、Python `http.server`、浏览器自动化检查。

## Global Constraints

- 所有文件位于 `D:\workspace\Growth OS\Learning MORE\docs\UI视觉预览`。
- 只保留一个当前有效样例，不保留“新版”“修改版”“最终版 2”。
- AI 内容无消息框和发送者标签；用户回答使用右侧气泡。
- 标准模式与八大玩法共用结构；模式层不提供方法清单或固定课程结构。
- 模式色与成功、警告、错误、已放弃、只读状态色严格分离。
- 课时 Review 弹窗展示完整权威 Markdown，只提供“返回课程大纲”和“查看课节记录”。
- 新结构全部验证前不删除旧样例；验证完成后必须删除旧混合目录。
- 当前目录不是 Git 仓库，因此计划不包含提交步骤；变更证据由文件清单、静态扫描和浏览器验证输出构成。
