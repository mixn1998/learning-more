# Learning MORE 2.0：功能设计层

## 1. 产品目标与边界

Learning MORE 2.0 的目标不是替用户播放一套预制课程，而是把“想学什么—如何拆课—实际学习—复盘—继续安排—跨会话认识自己的学习方式”连成可恢复、可追溯的闭环。

当前产品假设是单用户、本地优先、无云同步。所有重要学习产物都保存为本地事实或不可变文档；AI 负责生成、解释和归纳，但不能绕过领域状态机直接改变课程完成、Review 提交或画像证据状态。

## 2. 用户能力地图

### 2.1 创建与修订课程

用户通过课程创建对话描述目标、背景、时间和偏好，系统生成候选大纲。候选大纲可继续对话修订，确认后成为正式课程版本。

大纲修订遵守以下规则：

- 历史版本保留，可查看但不继续作为当前学习入口。
- 每次修订上下文包含两部分：过去版本的大纲生成对话压缩，以及过去版本中已完成课时的大纲概要。
- 已完成课时在上下文中明确标记为“用户已完成”，其课时身份、标题/概要等课义和课程表记录被冻结。
- 新版大纲必须包含这些已完成课时；语义重复的新课时不会再次进入新版课程表。
- 明确重复时自动移除；部分重叠或判断不确定时标记为“需要确认”，由用户决定保留为新增还是删除。
- 未完成部分可以重排、改写或替换，但不能借修订改写已经发生的学习历史。

这使“大纲可变”和“已完成学习事实不可变”同时成立。

### 2.2 正式学习

正式学习会话绑定课程版本和课时。会话进入后，由教学代理流式输出 Markdown，并通过隐藏结构化指令推动状态机。

当前教学阶段包括：

1. warmup：建立本课入口。
2. knowledge_point：逐步教学核心知识点。
3. comprehensive_application：综合应用。它是一项可参与、可跳过的跨知识点迁移邀请，不是检测。
4. discussion：讨论与答疑。
5. summary：总结。
6. ready_to_close：满足关闭条件。

讨论结束采用语义意图识别，不要求用户输入固定短语。状态机同时约束：当前阶段、答疑关闭确认 `closureInquiry` 和总结交付状态 `summaryStatus`。只有受到当前会话事实支持的组合才可显示或提交，避免仅靠一条自然语言命中就越过总结或关闭门槛。

教学回复与会话账本分开处理：回复可以优先流式展示，随后持久化；若写入失败，恢复机制会根据任务、消息修订和账本状态对账，而不是让用户重复完成整段学习。

### 2.3 自适应教学

知识点后的提问是非强制互动邀请。知识点只有在必要讲解已完成、互动已回应或被明确跳过、且当前没有未处理疑问或理解障碍时才可推进；回答正确次数不参与门禁。首次讲解并发出互动邀请的同一轮不能直接完成该知识点。

每轮教学会根据阶段和交互复杂度选择推理强度：开场、简单知识点和总结倾向低强度；综合应用、讨论和实质性连续追问提高到中或高强度。

个性化输入来自压缩后的全局学习档案，只提供少量、可追溯、适用于当前教学的稳定观察或用户明确偏好。它不能被用来推断人格、能力等级或当前课时掌握程度。

对明确需要数学图形的请求，能力路由可选择绘图工具；工具输出属于解释材料，不替代教学状态推进。

### 2.4 暂停、放弃、恢复与关闭

课时生命周期区分未开始、进行中、完成和放弃。进行中的会话受租约与版本约束，避免两个写入者并行推进同一会话。

- 暂停保留现场和累计时长，之后可恢复。
- 放弃是明确的终态，不进入后续规划，也不伪装为完成。
- 完成通过可恢复关闭事务提交：最终 Review、会话终态、事实、统计和后续投影要么完成对账，要么保留可恢复状态。
- 服务重启会扫描处于 committing 的关闭事务并继续恢复。

### 2.5 Review

课时 Review 的后端文档完整保存知识图谱、核心思想、学习表现、证据引用和可选附加模块。前端不直接逐块照搬原文，而投影为更短的阅读版本：

- **知识图谱**：一张凝练的关系图式，只保留节点、关键关系和一条主链。
- **核心思想**：先回答“本课要解决什么问题”，再回答“用什么核心思想或方法解决”。
- **学习表现评价**：合并同类项，呈现“你做得好的地方”和“接下来的判断”两个区块。
- **课程邻接探索**：只有本课实际涉及相关探索时才显示，作为灵活附加模块。

前端精简不改变后端 Review 文档，也不删除证据引用。课程总 Review 与课时 Review 各自不可变，不能互相覆盖。

### 2.6 补充学习

课时完成后，原始会话、完成状态和 Review 保持只读。用户若继续追问，可从课时记录创建独立补充学习会话。

补充学习支持连续对话、流式生成、停止、失败重试、消息修订、重命名和归档。它不会把原会话重新打开，也不会重写原 Review。补充会话可成为档案和画像的一个来源，但必须保留自己的来源类型与会话边界。

### 2.7 课程规划与下一课

规划使用当前有效大纲、学习状态和日程事实形成实时状态。它不是把旧的 `unscheduled/future/today/...` 文本标签当作领域真相，而是从课时生命周期与计划记录推导展示状态。

规划遵守：

- completed 与 abandoned 均不再进入待安排集合。
- 当前有效大纲顺序是默认推进顺序；即使没有显式先修关系，也不能随意跳过前序未完成课时。
- 计划命令采用幂等写入，避免重复点击产生两条安排。
- 下一课推荐可由 AI 提供解释，但计划事实本身仍由确定性领域规则写入。

### 2.8 首页、历史与周报

首页汇总当前课程、下一步学习、课程规划和上周回顾。无相关数据变化时，系统通过源修订号、静态快照和 ETag 直接复用已有结果；只有 catalog、learning 或 schedule 对应源发生变化才重建汇总。

历史区域提供：

- 课程和课时历史。
- 课时原始会话、补充会话与 Review。
- 学习统计、课程汇总和周汇总。
- 学习日历和周报。

历史统计与日历仍由多个读模型组合，不等同于一次性加载全部原始文件；前端按页面需要请求并保留已获得数据。

周报针对已结束的自然周后台生成，协调器可在启动时补偿遗漏任务，并在失败后延迟重试。

### 2.9 学习笔记与全局用户档案

课堂右侧提供本课笔记区。每次保存形成一条独立笔记，自动快照学科、课程、课节和时间；同课既有笔记持续可见，并可逐条编辑或删除。首页的“学习笔记”入口按学科、课程自动整理全部笔记。笔记自身保存课程元数据，因此源课程删除后仍可查阅。

全局用户档案作为上游数据层继续分层形成：

1. **学习事实**：课程、会话、Review、规划、交互等可审计记录。
2. **原始行为片段**：只描述一次具体行为，不直接成为跨会话结论。
3. **会话聚合维度**：在一个会话内把相关行为归纳为可比较维度。
4. **候选证据**：带来源组、依赖、强度、正反证据和适用边界。
5. **跨会话分析**：只有来自多个独立会话或用户明确偏好的材料才可进入稳定观察。

当前版本不提供学习画像页面、画像生成任务或教学个性化消费；上游档案事实、推理 Episode、语义核心和证据候选继续保留。

### 2.10 永久删除课程档案

删除课程是明确的永久操作，级联覆盖课程及其课时、会话、补充学习、Review、计划关联、事实和读模型引用。删除事务完成后，全局统计、学习档案和候选证据必须同步失效或重建，不能继续引用已删除课程；已经保存的学习笔记保留其课程元数据快照。

删除不是普通归档，不提供“从历史版本恢复”的语义；执行前必须向用户清楚说明范围。

## 3. 核心状态与不变量

### 3.1 课程与大纲

- 同一课程只有一个当前有效大纲版本。
- 候选大纲未确认前不成为正式课程表。
- 已完成课时跨版本保留，身份与课义冻结。
- 历史大纲只读；修订只能产生新版本。

### 3.2 学习会话

- 一个正式课时只有一条原始正式学习主线。
- 完成或放弃后，原会话不可继续写入。
- 补充学习必须使用独立 sessionId，并明确关联原课时。
- 生成停止不等于会话关闭；失败不等于放弃。

### 3.3 Review 与关闭

- 最终 Review 在成功关闭时提交，并成为不可变产物。
- Review 失败不得把课时错误标记为完成。
- 重试必须复用关闭事务和幂等标识，不能生成两份正式 Review。
- 页面精简投影不得反向覆盖完整 Review。

### 3.4 事实、证据与画像

- 事实层只记录已发生且可追溯的事件。
- 原始单会话行为不能直接升级为稳定人格或能力结论。
- 跨会话洞察必须保留独立来源、正反证据检查、适用边界和置信说明。
- 删除来源后，所有下游投影都必须失效、修复或重建。

## 4. 当前不支持与限制

- 不支持多用户、账号、权限或云同步。
- 通用附件、网页与外部资料尚未形成统一资料域。
- AI 输出仍可能需要语法修复或质量回退；领域规则不能假设模型永远返回完美结构。
- 画像能描述重复出现的学习行为，但当前证据通常不足以判断长期迁移效果、知识掌握程度或稳定能力。
- 性能优化目前集中在汇总快照和条件刷新；随着数据规模增长，历史读模型、备份时间和投影重建仍需持续量化。

## 5. 功能验收原则

一次功能改动至少要证明：

1. 用户可见行为与状态机一致。
2. 命令幂等，失败后可恢复。
3. 原始事实与不可变产物没有被展示投影覆盖。
4. 缓存命中与缓存失效都正确。
5. 删除、放弃、版本修订等边界不会留下下游幽灵引用。
6. AI 失败、停止、重试和 Provider 切换不会破坏领域不变量。
