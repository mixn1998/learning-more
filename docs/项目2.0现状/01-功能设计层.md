# Learning MORE 2.0：功能设计层

## 1. 产品定位

Learning MORE 是面向单个学习者的本地优先 AI 学习闭环。它不是一次性生成课程正文的工具，而是把学习方向逐步转化为可确认课程、真实学习会话、可复算事实、Review、排期、历史统计和学习画像。

当前主闭环为：

```text
学习方向或材料
→ 起点评估对话
→ 候选大纲
→ 用户确认正式课程
→ 确定性排期
→ AI 实时教学
→ 课节 Review / 课程 Review
→ 历史、统计、周报、画像
→ 下一课推荐与后续学习
```

核心分工是：AI 负责理解、生成、教学、观察、总结和建议；程序负责状态机、权限、版本、排期、事实、证据边界、幂等、不可变产物和恢复。

## 3. 九种课程模式

课程创建有一个标准模式和八个体验模式：

1. 标准模式 `standard`
2. 头脑风暴 `brainstorm`
3. 论证交锋 `argument_clash`
4. 案例研习 `case_study`
5. 商业洞察 `business_insight`
6. 流程拆解 `process_decomposition`
7. 决策分析 `decision_analysis`
8. 交叉探索 `cross_explore`
9. 阅读研讨 `reading_seminar`

模式只表达整体学习体验偏好和视觉身份。九种模式共用同一套课程、课节、排期、Review、历史和画像状态机，不创建九套业务模型，也不强制 AI 使用固定步骤、固定章节或固定教学模板。阅读研讨额外开放 PDF、TXT 和 Markdown 材料入口。

## 4. 课程创建

### 4.1 创建前状态

`OutlineSession` 是正式课程之前的可恢复对话。主页提交学习方向后，第一条用户消息被保存，AI 进行起点评估。默认需要至少三轮完整的“用户消息 + AI 回复”后才能请求候选大纲；达到三轮后仍可继续对话。

草稿与正式课程严格分离：

- 草稿不会出现在“继续学习”中；
- 草稿可恢复或永久删除；
- 候选大纲确认前不创建正式 `Course`；
- 同一会话同一时刻最多一个候选生成任务；
- 取消、超时、Provider 中断和候选合同不合格具有不同失败语义；
- 用户输入和已生成的部分 Markdown 在失败时保留。

建课草稿中的思维行为不直接进入长期统计。只有用户确认候选并正式创建课程后，系统才冻结 `authoring_candidate_confirmed` 检查点，追溯该建课会话中的可用用户/助手来源，提取可追溯的思维行为 episode；从未确认或被删除的草稿不贡献这类统计。

### 4.2 候选大纲与确认

候选大纲是可比较、可继续调整的版本化快照。新课程候选的机器合同要求：

- 课程标题来自大纲标题；
- 标题后提供 50–100 字的显式课程摘要；
- `disciplineTag` 只能是学科或领域大类，例如“数学”“商业”“计算机科学”；
- 课节有目标、核心知识点、前置依赖和预计时长；
- Markdown 正文保留自由结构，不强制所有模式使用相同模块数量。

确认是显式按钮动作，并以原子事务一次性创建课程、确认版大纲和稳定课节。确认不可逆；后续调整产生新的不可变大纲版本，不改写旧版本。

### 4.3 课程摘要与课节摘要

课程摘要和课节摘要是两条独立规则：

- **课程摘要**只读取 H1 后显式的 50–100 字课程摘要；旧大纲没有合格摘要时使用课程标题生成中性兜底句，不从排期、目标列表或后续普通段落猜测。
- **课节摘要**继续使用课节自身 `objective` 和核心知识点，不复用课程摘要解析器，也不把课程级排除规则套到课节上。

历史细粒度 `disciplineTag` 在页面展示和筛选时做确定性大类归一化；当前明确覆盖商业/创业→“商业”、数学/微积分→“数学”。新课程则从生成合同源头限制为大类。

## 5. 课程规划与计划流

### 5.1 单课节排期

- 规划页进入时不默认选中今日；
- 未排期课节归入待安排区；
- 点击日期字段使用行内原生日历选择；
- 选择有效日期后立即保存；
- 移动失败时恢复服务端权威日期并在当前行提示错误；
- 课节可移动、调整结束时间、锁定和删除；操作完成后页面立即使用返回结果更新，不依赖手工刷新。

### 5.2 计划流

计划流接收结构化约束：课程范围、开始日期、学习日、每日目标时长、课程排序策略和是否保留已有排期。预览阶段不写正式排期；用户确认后才一次性提交。计划流由确定性程序规则生成，不调用 AI。

确定性规则包括：

- 保持同一课程内课节顺序和前置依赖；
- 一个课节不可拆分；
- 单课节超过每日目标时仍作为原子课节安排，并标记超目标；
- 可用较低优先级课节填充当天剩余目标；
- 避让已有冲突；
- 保留手动锁定项；
- 平衡、专注、优先三种策略产生不同课程顺序；
- 相同输入产生相同输出；
- 预览过期或基础排期版本变化时拒绝确认并要求重算。

## 6. 正式课节学习

### 6.1 进入、教学分层与知识点推进

未开始课节先展示确认版目标和核心知识点。开始后创建唯一原始学习会话，AI 无需用户先发消息即可生成教学开场。

正式教学不是一个通用聊天调用，而是三层协作：

- **教学智能体**只负责面向用户的 Markdown：依据当前课节、知识点、真实对话、课程模式关注点和可用个性化背景，自由选择解释、案例、类比、反驳、讨论或检测方式；
- **教学观察**在完成的教学回合后提取范围关系、问题、学习证据、明确跳过和流程信号，不直接生成用户可见文案；
- **教学状态账本**以确定性 reducer 合并观察，维护当前阶段、知识点讲解/检测状态、开放问题、邻接支线和证据检查点；右侧学习路径读取该账本，不用消息数量或 AI 文案长度猜进度。

当前主流程为：

```text
课前热身
→ 当前知识点讲解与检测
→ 回答通过或用户明确跳过，并处理该知识点开放问题
→ 下一知识点
→ 全部知识点通过或跳过
→ 综合检测
→ 综合检测通过或明确跳过
→ 本课总结
→ ready_to_close
→ 用户结束本课并生成最终 Review
```

知识点只在讲解完成、观察到支持性证据且没有该节点的未解决问题时前进，用户明确跳过时也可前进；“AI 已讲解”不会被写成“用户已掌握”。相关但不属于本课的问题记为 `adjacent` 教学支线，可以自然展开，并保留与当前知识点和返回主线的关系；它不冒充本课覆盖，也不把未来课节标记为完成。明显无关请求才简短收束并邀请返回课程。

用户消息先乐观显示；请求未被接受时保留输入并标记失败。AI 回复以流式 Markdown 展示，可停止生成；刷新后可从服务端任务和帧日志恢复进行中的回复。

### 6.2 暂停、后台与计时

当前规则是：

- 手动暂停、关闭窗口、离开页面、页面进入后台或断网都会暂停学习会话；
- 只有“因进入后台而自动暂停”的会话在回到前台时自动恢复；
- 暂停后禁止新的用户输入和新的 AI 任务；
- 已经启动的 AI 任务继续在后台生成；
- 任务所属会话、任务 ID 和写入权匹配时，即使会话已经暂停，也可提交完整 AI 回复；
- 来自其他会话、其他任务或其他写入权持有者的迟到回复被拒绝；
- AI 生成等待期间关闭学习计时间隔，回复完成或停止后，仅在会话仍为活动状态时恢复计时；
- 暂停、后台、AI 等待和失去写入权的时间不计入实际学习时长。

### 6.3 多窗口与可恢复性

同一课节只有一个原始学习会话和一个写入租约。第二个页面以只读方式打开，可显式接管写入权；旧页面随后写入会被拒绝。服务重启时，开放计时间隔按最后心跳截断，进行中任务按持久化状态恢复或形成可见的中断结果。

## 7. 放弃、恢复与 Review

- 无有效证据的短会话被放弃时删除原始会话，不请求 Review；恢复后回到未开始状态。
- 已形成有效证据的会话被放弃时冻结同一原始会话，并请求阶段 Review；恢复后继续原会话。
- 课节结束前必须冻结完整教学检查点；缺少完整观察、仍有开放问题或未达到可关闭阶段时拒绝结束。
- 最终课节 Review 使用冻结的会话、消息范围和校验和生成；提交后不可变。
- 课节完成不可逆，后续补充学习只能建立独立会话。
- 课程关闭会检查所有课节；包含放弃课节时需要显式确认。课程关闭后大纲只读，并生成课程 Review。
- 永久删除课程是级联操作，会撤销课程贡献的事实和画像证据；操作不可撤销并需要确认。

## 8. 历史、统计、周报与画像

历史区包含三个同级页签：统计、学习日历、学习画像；`/profile` 当前只重定向到历史中的画像页签。

历史统计只读取结构化学习事实，不从可见文案或 AI 文本反推数据。统计、课程摘要、日历和周视图都可通过相同事实增量投影或全量重建得到等价结果。课程筛选和学科筛选使用确认课程及归一化后的学科大类。

周报使用 `Asia/Shanghai` 周界：每周日 00:00 冻结刚结束的完整七天，即“上周日 00:00（含）至本周日 00:00（不含）”。服务启动会补偿尚未生成的上一完整周；生成成功后形成不可变静态快照并展示整整一周。周报中的课节数、活跃天数、时长、记录和 AI 总结都只从冻结快照派生，不混入本周实时事实。新快照仍在生成或已经失败时，页面明确显示“本周快照生成中/失败”，不回退展示上一周报告；页面默认折叠 AI 长文。

### 8.1 学习画像与全局用户档案

两者不是同一个概念：

- **学习画像**是面向用户的功能模块和版本化产物，展示当前证据支持的学习洞察、反证与局限；
- **全局用户档案**是后台长期数据层，维护可复算事实、画像候选证据、思维行为 episode、动态维度和分析快照，为教学个性化、画像、周报等消费者提供受治理输入，不直接等同于一段用户可见画像文案。

思维倾向不使用“逻辑、关联、发散、结构、隐喻”等固定列。系统先记录开放语义的局部行为 episode，再由 AI 在指定证据窗口中动态归纳可解释维度并进行多标签分类；统计同时保留发生次数、独立来源组、自然出现/被引导分布、课程和课节覆盖。少于两个独立来源组的维度保持 provisional，不能直接成为稳定人格结论。

学习画像不是固定人格模板：

- 候选证据保持局部、中性、可追溯；
- 单一来源不能直接成为稳定画像结论；
- 支持证据和反证同时保留；
- 运行遥测、前端临时状态和 Provider 错误禁止进入画像；
- 证据不足时提交零洞察版本，不编造人格；
- 新版本成功后原子推进当前指针，失败草稿不替换上一成功版本。

## 9. AI 与确定性程序的边界

| 场景                                                       | 当前处理方式                                          |
| ---------------------------------------------------------- | ----------------------------------------------------- |
| 起点评估对话、候选大纲、候选调整                           | AI                                                    |
| 正式教学开场与回复、教学观察                               | AI                                                    |
| 阶段/最终/课程 Review                                      | AI 生成，程序冻结输入并校验提交                       |
| 周报、学习画像、下一课语义推荐、推理行为分析、画像证据提取 | AI，均受结构化输入与验证约束                          |
| 下一课在 AI 不可用时                                       | 程序确定性 fallback，只推荐符合资格的课节，不自动开始 |
| 单课节排期、计划流预览和确认                               | 确定性程序，不调用 AI                                 |
| 状态机、权限、版本、幂等、计时、事实、投影、删除和不可变性 | 确定性程序                                            |

生产场景注册表还保留 `plan-flow-preview` 和 `outline-candidate-intent` 名称，但当前生产代码没有以这两个 `taskKind` 提交生成任务，属于注册未接入，不应写成已使用 AI 的业务能力。

建课对话和正式教学使用相同的上下文装配原则：程序先把内部结构化状态投影为面向学习者的自然语言背景，再把“已知学习背景/此前真实对话”和“当前诉求｜用户原话”分区交给模型。原始 phase、轮次键、账本 ID 和策略对象不直接进入用户可见生成路径；背景也不会伪装成用户本轮刚刚说过的话。课程模式只作为可按需采用的关注重心，教学主线和状态账本只约束责任边界与推进条件，不规定模型必须采用固定文体、固定步骤或固定玩法。

## 10. 运行中心与 Provider 能力

运行中心分为 AI 接口和本地服务两部分。用户可以查看 Provider 健康、切换 Mock/API/Codex CLI、选择模型和推理强度、启动 Codex 登录、重连当前 Provider、同步前端版本、执行本地服务一键重连并生成脱敏诊断。

“同步前端版本”和“一键重连”共享同一条安全激活路径。工作区版本变化时，Host 在隔离目录构建候选，首次失败会清理本次 attempt 并自动重试一次；两次失败后保留旧活动版本和用户数据。页面只有在 Host 激活终态、Runtime readiness 和实际 served Web 的 `buildId`/协议一致后才显示本地恢复完成。“一键重连”随后刷新 AI Provider；仅 AI 刷新失败不会回滚已经成功的本地版本，但会单独提示。

运行中心显示稳定失败原因和旧版本是否仍可使用。外部端口占用、实例身份不匹配或 Host 身份不匹配时停止自动处理，不强制终止或接管未知进程。

当前事实边界：

- Mock Provider 始终存在，主要用于确定性开发和测试；
- API Provider 只有在启动环境提供 Base URL 和模型时才加入生产 Provider 列表；
- Codex CLI 只有在发现可执行文件时才加入列表；
- Codex 模型通过已登录 CLI 的 `debug models` 动态读取，只展示 CLI 标记为可列出的模型；
- 自动 fallback 可配置 Provider 顺序和最大尝试次数，但只允许在首个输出片段之前切换，已经输出内容后不会换 Provider 拼接回复。
