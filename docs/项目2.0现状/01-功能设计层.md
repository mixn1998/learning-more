# Learning MORE 2.0：功能设计层

## 1. 产品定位与边界

Learning MORE 面向单个学习者提供本地优先的 AI 学习闭环。它不是“一次输入主题，生成一篇课程正文”的内容工具，而是把学习意图逐步变成可确认课程、可恢复教学会话、确定性进度、Review、统计和长期个性化依据。

产品中的职责分工是：

- AI 负责理解学习诉求、生成大纲、实时教学、行为观察、Review、周报、画像和语义推荐；
- 程序负责状态机、版本、权限、排期、计时、任务归属、事实、证据边界、幂等、不可变提交和故障恢复；
- 用户保留候选生成、候选确认、大纲发布、学习跳过、结束课节和关闭课程等关键决策权。

## 3. 核心业务对象

| 对象 | 当前含义 |
| --- | --- |
| 大纲创建会话 | 正式课程创建前的可恢复 AI 对话；不是课程 |
| 候选大纲 | 某次手动生成得到的完整、可确认快照 |
| 正式课程 | 用户确认候选后创建的一等学习实体 |
| 确认版大纲 | 不可变大纲版本；修改产生新版本，不覆盖旧版本 |
| 课程单元 | 从确认版大纲编译出的稳定课节定义 |
| 学习会话 | 某一课节的原始教学对话及其计时、写入权和消息 |
| 教学状态账本 | 教学智能体隐藏指令的可重建投影，决定进度和闭环 |
| 教学观察 | 基于完整历史重建的行为记录，不决定教学进度 |
| Review | 对冻结教学证据生成的课节或课程产物 |
| 全局用户档案 | 跨会话语义归并后的稳定行为维度数据域 |
| 学习画像 | 消费全局用户档案、面向用户展示的版本化分析功能 |

课程状态、排期状态和教学进度是不同维度，不能互相代替：课节可以处于“学习中”但暂时没有排期；排期过期也不等于课节被放弃；教学节点完成也不等于最终 Review 已提交。

## 4. 课程模式

当前有一个标准模式和八个体验模式：

1. 标准模式 `standard`
2. 头脑风暴 `brainstorm`
3. 论证交锋 `argument_clash`
4. 案例研习 `case_study`
5. 商业洞察 `business_insight`
6. 流程拆解 `process_decomposition`
7. 决策分析 `decision_analysis`
8. 交叉探索 `cross_explore`
9. 阅读研讨 `reading_seminar`

模式提供视觉身份和可按需采用的教学关注，不创建九套课程状态机，也不要求 AI 按固定模板逐步执行。阅读研讨额外支持 PDF、TXT 和 Markdown 学习材料。

## 5. 课程创建与大纲修改

### 5.1 新课程创建

主页提交“学习方向 + 课程模式”后进入大纲创建会话。会话保存真实用户输入、AI 起点评估回复、材料和候选版本；候选确认前不创建正式课程。

当前工作流是显式两步：

```text
用户与 AI 对话澄清学习诉求
→ AI 只在左侧回复用户，不自动生成候选
→ 用户点击“生成新候选”
→ 右侧显示生成悬浮状态，可取消
→ 候选完成后显示候选大纲
→ 用户继续对话或确认候选
```

已有候选后，用户仍可继续在左侧提出调整。AI 对话回复只负责理解和回应；只有再次点击“生成新候选”才会使用完整会话历史和当前候选生成替代版本。这一规则避免“回复用户”和“生成完整大纲”争抢任务与界面状态。

候选确认是显式且不可逆的业务动作。确认事务一次性创建：

- 正式课程；
- 当前确认版大纲；
- 稳定课节定义；
- 与建课会话的来源关系。

### 5.2 候选大纲合同

新候选必须提供：

- 明确课程标题；
- 标题后 50–100 字的课程摘要；
- 只能表达学科或领域大类的 `disciplineTag`；
- 一至三个主题标签；
- 可编译的课节、目标、核心知识点、前置关系和预计时长；
- 保持课程模式自由度的 Markdown 正文。

课程摘要与课节摘要是两套独立数据来源：课程摘要只读取大纲开头的显式摘要；课节摘要来自该课节自身目标和知识点，不复用课程摘要解析规则。

历史细粒度学科标签在展示和筛选时确定性归一化，例如商业/创业归为“商业”、数学/微积分归为“数学”。新候选从生成合同源头限制为学科大类。

用户从主页“选择课程”或正式课程页“切换课程”时，均可按归一化后的学科/领域和课程来源模式组合筛选。两个条件采用交集；默认展示全部课程。课程卡片只展示实际来源模式，不再追加没有区分价值的“正式课程”字样。

### 5.3 正式大纲修改

正式课程的大纲修改页同样采用“对话与候选生成分离”：

| 阶段 | 左侧 | 右侧 |
| --- | --- | --- |
| 刚进入 | 历史对话、修改输入框 | 当前正式大纲 |
| 用户发送消息 | 历史对话、AI 思考和回复 | 当前正式大纲保持不变 |
| 用户点击生成 | 输入仍可见，操作区显示生成状态 | 候选生成悬浮状态，可取消 |
| 候选完成 | 可继续对话、再次生成或发布 | 候选大纲、版本差异和模块改动说明 |

“生成新候选”和“确认并发布 vN”位于左侧操作区。候选生成后如果又产生新对话，页面提示当前候选未包含这些对话；发布仍是用户显式决定。发布创建新的不可变大纲版本，并按照稳定课节关系沿用、替换、增加或移除课程单元。

## 6. 课程规划与计划流

### 6.1 单课节排期

- 规划页不默认选中今日；
- 未排期课节进入待安排区；
- 日期字段使用行内日历，不弹出业务模态框；
- 选定有效日期后立即保存；
- 移动、调整时长、锁定和删除均以服务端返回结果即时更新页面；
- “清空排期”一次取消当前全部有效排期，保留每条排期记录与取消原因，不删除已完成学习事实；
- 写入失败时恢复服务端权威值，并在当前操作位置显示错误。

### 6.2 计划流

计划流只消费结构化约束：课程范围、开始日期、学习日、每日目标时长、课程排序策略，以及是否保留已有排期。它由确定性程序计算，不调用 AI。

主要规则包括：

- 同一课程严格使用正式大纲课节顺序；没有先修关系也不得跳过尚未完成的前置课节；
- 一个课节不可拆分；
- 单课节超过每日目标时仍作为原子课节安排，并标记超目标；
- 避让已有冲突，保留锁定项；
- 相同输入与相同基础排期版本产生相同预览；
- 预览不写正式排期；
- 基础版本变化或预览过期时拒绝确认并要求重算。
- 首次确认和“重新排剩余”都记录最近一次批量排期前的完整快照；“撤回排期”只回滚该计划流最近一次自动排期，不影响无冲突的手工排期；若自动排期已被手工修改或恢复内容与现有排期冲突，则整批拒绝撤回。

## 7. 正式课节教学

### 7.1 三条相互独立的链路

正式教学由三条链路协作，但职责不可混用：

```text
教学智能体结构化指令 → 教学状态账本 → 前端进度与闭环判断

完整学习会话历史 → 教学观察 → Review / 学习行为 / 统计 / 画像

学习会话状态 → 写入权、计时、暂停、消息归属与任务恢复
```

教学智能体每轮生成两个区块：用户可见 Markdown，以及前端不可见的完整教学状态指令。服务端先校验并提交可见回复，再把指令应用到教学账本；教学观察随后异步读取完整会话历史重建行为记录。观察失败不能撤销已经完成的 AI 回复，也不能把观察重新变成进度裁判。

### 7.2 教学阶段与状态

教学阶段为：

```text
课前热身
→ 逐个知识点学习
→ 综合检测
→ 讨论答疑
→ 最终课程总结
→ ready_to_close
```

知识点账本状态和前端文案统一为：

| 账本状态 | 前端文案 |
| --- | --- |
| `pending` | 待讲解 |
| `learning` | 正在学习中 |
| `completed` | 该知识点已完成 |
| `skipped` | 跳过知识点 |
| 互动 `skipped` | 跳过知识点互动 |
| 综合检测 `skipped` | 跳过检测 |

教学智能体拥有判断学习者是否足以进入下一阶段的教学自主权，但必须满足以下体验约束：

- 不默认学习者已经理解；
- 提供深入透彻的理解过程、足够的思维激活和思考密度；
- 不用“正在检测”“已经通过检测”等流程话术；
- 当前知识点完成后用小结自然过渡，不生硬播报状态；
- 已完成或跳过的节点不得倒退；
- 只跳过互动与跳过整个知识点必须分别记录；
- 课程邻接探索可以展开，但不能冒充当前课节责任已经完成。

### 7.3 讨论答疑与课程闭环

综合检测通过或用户明确跳过后，必须先进入讨论答疑。教学智能体询问用户是否还有疑惑或其他讲解需求。

- 用户提出问题：完整回答，保持讨论答疑状态，并再次自然确认是否还有其他需要；用户可持续追问任意轮次。
- 用户只表达“明白了”“没有其他问题”“可以结束”：可在同一轮输出最终课程总结，并把账本推进到 `ready_to_close`。
- 用户表达“明白”但同一消息还包含新问题或其他信息：继续处理新内容，不得提前总结。
- 最终课程总结是唯一不再向用户提出问题或邀请继续输出的教学回复。

在最终总结之前，每轮回复都必须给用户留下一个自然、容易回应、与本课相关的表达入口，避免“话掉在地上”。用户跳过综合检测不影响进入讨论答疑和最终闭环，但跳过事实仍被教学观察记录，供 Review、统计和画像链路使用。

`ready_to_close` 只表示教学流程允许关闭，不会自动替用户点击“结束本课”。用户显式结束后，系统才进入最终 Review 提交事务。

### 7.4 暂停、后台、生成与计时

- 手动暂停、离开页面、页面进入后台、关闭窗口或网络中断会停止当前计时间隔；
- 页面进入后台只暂停计时和用户输入，不取消已经启动的 AI 任务；
- 会话、任务和写入权身份匹配时，AI 可在会话暂停后提交完整回复；
- 不匹配的迟到回复被拒绝；
- AI 生成等待期间暂停实际学习计时，回复完成后仅在会话仍活动且页面持有写入权时恢复；
- 第二窗口默认只读，可显式接管写入权；旧窗口随后的写入被拒绝。

## 8. 放弃、恢复、Review 与课程关闭

### 8.1 课节放弃与恢复

- 没有有效教学或互动证据的短会话被放弃时删除，不生成 Review；恢复后相当于未开始。
- 已有有效证据的会话被放弃时冻结原会话并生成或更新阶段 Review；恢复后继续同一会话。
- 暂停不是放弃，不生成 Review，也不计入行为证据。

### 8.2 Review

每个课节最多一个稳定 `reviewId`：阶段 Review 可以被后续阶段或最终课时 Review 原子覆盖；最终课时 Review 成功后不可修改。最终 Review 必须消费冻结的会话、教学检查点、观察引用和来源范围，不能根据当前页面临时状态生成。

课程总 Review 消费同一主题下的课时/阶段 Review 与会话聚合结果，形成主题级总结，但不把自己重新写成一份独立画像证据。

### 8.3 结束本课与关闭课程

用户点击“结束本课”时：

- 账本已经 `ready_to_close`：进入正常关闭事务，最终 Review 成功后课节才成为已完成；
- 账本尚未闭环：显示仍未完成的教学责任，用户确认后按放弃课节处理。

课程在所有当前有效课节均已处置后才能关闭。全部完成时可自动满足关闭条件；存在放弃课节时要求用户查看清单并显式确认。关闭后大纲只读，课程总 Review 可生成；后续深化学习必须建立新课程或补充学习会话。

## 9. 历史、统计与长期个性化

### 9.1 学习事实与统计

历史统计只消费结构化学习事实，不从 AI 文案反推数据。事实投影支持增量执行和全量重建，并形成历史列表、课程摘要、总体统计、学习日历、周视图与周报。

历史页面按当前页签分阶段读取数据：学习画像不等待历史聚合；周报只读取周报所需数据；总体统计以权威统计先完成首屏，再在后台补齐课程、课节与日历明细。某个较慢的聚合接口不得阻塞其他页签或已经可展示的统计结果。

“学习参与事实”当前只展示：

- 关键互动回应率；
- 跳过互动。

页面不展示“互动回应”绝对数量。互动提示、回应与跳过来自教学观察的结构化记录，而不是文本关键词匹配。

### 9.2 行为数据链

当前行为数据链为：

```text
原始行为层
  回答、推理、提问、纠偏、跳过与精确来源引用
        ↓
课时 / 阶段 Review
        ↓
会话聚合层
  按“学习会话 + 抽象维度”聚合
        ↓
全局用户档案层
  对不同会话中本质一致的维度再次语义归并
        ↓
学习画像 + 教学个性化隐式上下文
```

约束如下：

- 暂停学习事实在任何层都不计入行为证据；
- 原始行为层保留回答与来源，用于审计、统计和 Review；
- 同一会话的最终 Review 替代阶段 Review 的会话聚合，不增加独立来源数；
- 至少两个真正独立学习会话支持同一跨会话模式，才进入稳定画像结论；
- 支持证据、限制和反证同时保留；
- 运行遥测、页面状态和 Provider 故障不得进入用户行为档案；
- 学习画像是用户可见产物，不反向成为新的行为事实。

### 9.3 周报与学习画像

周报按 `Asia/Shanghai` 的完整自然周冻结事实快照。报告中的时长、课节数、活跃日和 AI 总结都来自同一冻结输入；生成失败时显示该目标周失败，不回退伪装成最新报告。

学习画像拥有独立生成任务和不可变版本。页面进入、离开和页签切换只读取当前成功快照，不触发证据同步或生成。系统在 `Asia/Shanghai` 每周六 00:00 定时刷新，同时保留用户显式手动刷新；两种刷新都先恢复 Review 检查点与全局行为分析，再构建受控证据清单。只有成功并通过引用校验的新版本才推进当前指针，失败不会覆盖上一成功版本。

## 10. AI 与确定性程序的边界

| 场景 | 当前责任方 |
| --- | --- |
| 建课对话、候选大纲、候选调整 | AI；候选生成由用户显式触发 |
| 正式教学开场与回合 | AI 教学智能体 |
| 知识点进度与闭环 | AI 返回结构化指令，程序校验并归并到账本 |
| 教学行为记录 | AI 教学观察，基于完整历史重建 |
| 阶段/最终/课程 Review | AI 生成，程序冻结输入并校验提交 |
| 周报、学习画像、下一课语义推荐 | AI，受结构化输入、引用和 fallback 约束 |
| 单课节排期、计划流 | 确定性程序 |
| 生命周期、计时、权限、版本、事实、删除、不可变性 | 确定性程序 |

当前 AI 场景注册表只保留有生产提交路径的场景；计划流不是 AI 场景，也不存在仅用于“是否应该生成候选”的独立 AI 意图场景。

## 11. 运行中心

运行中心分为 AI 接口和本地服务两部分：

- AI 接口：查看 Provider 健康、选择 Provider、模型和推理强度、配置 API、启动 Codex 登录、检查与重连当前接口；
- 本地服务：一键重连、同步前端版本、查看活动构建与实例身份、生成脱敏诊断。

Provider 能力是条件接入：Mock 始终存在；API Provider 需要 Base URL 和模型配置；Codex CLI 需要发现可执行文件并完成登录。Codex 模型选项来自 CLI 动态目录，不固定为文档中的几个型号。

一键重连和同步前端版本共用安全激活路径：候选构建在隔离目录完成，通过 Host/Supervisor 验证后才切换活动版本；失败时保留旧版本与用户数据。AI Provider 重连发生在本地版本恢复之后，AI 重连失败不会回滚已经成功激活的应用版本。

## 12. 当前明确限制

- API Provider 当前主要传递模型、完整 prompt、流式开关和可选 Bearer 密钥，没有通用开放 temperature、top-p、max-tokens 等参数面板。
- Runtime 配置中存在交互/后台并发字段，但当前生成运行时装配未消费这两个字段；实际并发受 Provider `maxConcurrency`、任务组、owner 和调度顺序约束。
- 周报失败可被读取和展示，但当前 HTTP 面没有公开的周报手动重试命令。
- 模型目录、Provider 健康与活动构建会随运行环境变化，不能被当作固定产品清单。
