# Learning MORE 2.0：品牌视觉规范

> 本规范记录当前 React 界面已经采用的视觉系统。设计 token 以 `packages/ui/src/styles` 中的实现为最终依据。

## 1. 品牌气质

Learning MORE 的界面应当像安静、可信、可长期使用的学习工作台：温暖但不幼稚，结构清楚但不机械，允许 AI 内容充分展开但不让页面失去节奏。

视觉关键词：纸张感、克制、温暖、清晰、可回看。

避免：高饱和科技蓝、霓虹渐变、游戏化积分堆叠、过度拟物、密集仪表盘和无意义的大面积动画。

## 3. 课程模式色

不同教学模式可替换 accent/tint，但保持同一页面结构与可读性：

- 标准：暖棕。
- 头脑风暴：黄褐。
- 观点碰撞：青绿。
- 案例学习：柔红。
- 商业洞察：棕褐。
- 流程拆解：蓝灰。
- 决策分析：绿色。
- 邻接探索：蓝色。
- 阅读研讨：紫色。

模式色是上下文提示，不是品牌重绘。页面底色、正文色和状态语义保持稳定。

## 4. 字体与排版

产品字体：`Inter, PingFang SC, Microsoft YaHei, sans-serif`。

代码字体：`Cascadia Mono, Consolas, monospace`。

当前基础规格：

- 产品正文：14px / 1.65。
- AI 正文：15px / 1.75。
- AI H1：24px / 1.35。
- AI H2：20px / 1.4。
- AI H3：17px / 1.45。
- 小标题与说明按 10–13px 使用，但关键操作不得小于可辨识尺寸。

中文长文优先保证行长、行高和段落间距。Review 与画像不通过缩小字号压缩内容，而应在信息结构层归纳。

## 5. 空间、圆角与阴影

基础间距序列：4、8、12、16、20、24、32px。

圆角：

- 小：9px。
- 中：12px。
- 大：16px。

常规卡片使用轻阴影 `0 16px 42px rgb(65 47 30 / 9%)`；对话框可使用更强但仍柔和的阴影。不要同时叠加粗边框、强阴影和高饱和底色。

页面内容最大宽度为 1600px；大屏通过留白和分栏提高阅读效率，不无限拉长正文行。

## 6. 组件表达

### 6.1 按钮

- 主按钮：accent/dark 实底，白色文字。
- 次按钮：纸面或浅底，accent 边框。
- 危险按钮：仅在永久操作中使用 danger。
- 禁用态仍保留标签可读性，不只降低到不可辨识的透明度。
- 同一操作执行中显示进行态并阻止重复提交。

### 6.2 卡片

卡片表达一个清楚的信息单元。若连续卡片只有标题不同、正文均很长，应先合并内容而不是继续增加卡片。

Review 学习表现固定归纳为两块；画像每条洞察使用可理解标题，不用“洞察 01 + 复合证据观察”的双重模板。

### 6.3 状态与提示

- 成功：绿系。
- 警告/待确认：黄褐系。
- 错误/永久删除：红系。
- 只读/冻结：灰绿色。
- 恢复中：中性底色配阶段文字和适度进度反馈。

错误信息说明发生了什么、用户能做什么；运行时内部栈、路径和密钥不得显示。

### 6.4 对话

用户消息使用较深 accent 气泡和白字；AI 内容使用纸面正文区域。输入区明确区分发送、停止和重试。

流首帧前显示“正在思考”；生成中的占位不应造成页面大幅跳动。长对话默认保持用户当前阅读位置，只有用户位于底部时才自动跟随新内容。

## 7. 关键页面规则

### 7.1 课程与大纲

- 当前版本、历史版本、已完成锚点和“需要确认”使用不同但一致的状态标签。
- 大纲差异以新增、删除、移动、内容调整和保留完成课时表达。
- 恢复到初始内容后，差异标记应按语义基线重新计算，不保留幽灵“新增”。

### 7.2 课时 Review

- 知识图谱优先用关系链和节点，不用六张解释卡。
- 核心思想有独立标题和短段落。
- 学习表现只显示“你做得好的地方”“接下来的判断”。
- 邻接探索仅有内容时出现。

### 7.3 学习画像

- 顶部总标题必须概括真实模式。
- 总摘要使用普通用户语言，并包含证据边界。
- 每条洞察有自己的具体标题。
- 证据详情默认折叠，展开后才显示来源和技术性信息。
- 刷新中保留旧快照，避免空白页。

### 7.4 运行中心

运行中心允许更偏工具化，但仍沿用纸面、暖灰和状态色。突出用户可执行动作：重连、诊断、切换 Provider、查看激活阶段；原始日志放在次级区域。

## 8. 可访问性与响应式

- 所有可交互控件有可见焦点，焦点环使用 accent 混色。
- 图标按钮提供可访问名称和 tooltip。
- 键盘可完成主要对话和表单流程；Enter 发送、Shift+Enter 换行。
- 正文和状态文本保持足够对比度。
- 320px 起可使用；窄屏将双栏变单栏，不横向压缩长文。
- 动画尊重 `prefers-reduced-motion`，不把动画作为唯一状态提示。

## 9. 文案规范

- 面向用户：说“学习方式”“这两次学习中”“目前还不能判断”。
- 面向诊断：可在展开详情中说“证据版本”“投影恢复”。
- 禁止在主界面直接显示 schema 名、analyzer、projection、source group、dimension 等工程术语。
- 标题要表达内容，不用“综合观察”“洞察结果”“结构化推理观察”等模板占位。
- 不把课程完成解释为知识掌握，也不把重复行为解释为人格。
