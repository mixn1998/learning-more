# Learning MORE 2.0：前端实现层

## 1. 前端职责

前端是 React + Vite + TypeScript 单页应用。它负责路由、交互、流式内容显示、本地页面缓存和用户友好的读模型投影；不在浏览器内复制后端状态机，也不把 AI 文本当作领域事实直接提交。

所有命令和查询通过共享合同解析。服务未就绪、构建版本不匹配或控制链正在激活时，前端进入明确的恢复状态，而不是把网络错误误显示为空数据。

## 2. 路由与页面

| 路由 | 页面职责 |
| --- | --- |
| `/` | 首页汇总、当前课程、下一步、课程规划和上周回顾 |
| `/courses/new` | 课程创建对话、候选大纲生成与确认 |
| `/courses/:courseId` | 当前课程大纲、版本状态、修订与课程级操作 |
| `/courses/:courseId/lessons/:lessonId` | 正式学习会话 |
| `/courses/:courseId/lessons/:lessonId/record` | 完成课时记录、原始会话、补充学习和 Review |
| `/lessons/:lessonId` | 旧入口兼容跳转，不承载独立业务语义 |
| `/planning` | 待安排课时、日期选择和计划状态 |
| `/history` | 课程历史、统计、日历、周报和课时记录入口 |
| `/profile` | 学习档案/画像快照、证据说明和手动刷新 |
| `/runtime` | Provider、服务健康、构建激活和诊断状态 |

路由参数只用于定位资源。资源是否可学习、只读、已完成或已放弃，以服务端返回的状态为准。

## 3. 页面数据状态

页面统一区分：

- `initial`：尚未请求。
- `loading`：首次加载，无可展示旧数据。
- `ready`：已有有效数据。
- `refreshing`：保留旧数据并后台核对更新。
- `empty`：查询成功且确实无数据。
- `recovering`：服务、构建或生成任务正在恢复。
- `error`：已确认失败，并提供可执行的重试或诊断入口。

首次加载和后台刷新不能使用同一套全屏等待体验。已有静态快照时应立即显示，条件请求确认无变化后保持原视图；只有数据修订变化才替换页面状态。

## 4. 查询、快照与刷新

### 4.1 首页汇总

首页从 `/api/v1/home` 获取已经组合好的汇总读模型。客户端保存响应 ETag：

1. 首次访问获取完整快照。
2. 再次访问先显示内存中的有效快照，同时发送条件请求。
3. 服务端源修订号未变化时返回未修改语义，前端不重新解析和替换整棵页面状态。
4. catalog、learning 或 schedule 任一源发生变化时才取得新快照。

因此“无数据更新时直接显示，有更新时再核对刷新”是当前首页的正式路径。课程规划和上周回顾作为该汇总的一部分，共享相同条件刷新边界。

### 4.2 历史、统计与学习日历

历史页的数据规模和更新频率不同，不强行合成一个巨型响应。前端分别请求目录、分页历史、统计、学习日历、课程汇总、周汇总和周报，并遵守：

- 路由内切换保留已经成功加载的数据。
- 翻页只替换目标页，不清空其他区块。
- 统计或日历刷新不强制重载课时对话正文。
- 对可用 ETag 或修订号的查询使用条件刷新。
- 后台刷新失败时保留最后一次成功结果，并显示非阻断提示。

### 4.3 学习画像

画像页读取当前静态快照，不在每次打开页面时触发 AI 生成。页面显示快照时间和刷新状态：

- 定时任务成功后，新快照替换旧快照。
- 手动刷新立即创建后台任务；旧画像继续可读。
- 生成完成后再原子替换，不显示半成品。
- 生成失败时保留旧快照，并允许查看简明失败说明或重试。

## 5. 命令交互

命令客户端统一携带请求标识或幂等键。按钮在同一命令未结束时只阻止重复提交，不把整个页面永久锁死。

典型命令包括：

- 创建课程、继续创建对话、生成/确认候选大纲。
- 修订大纲、处理“需要确认”的重复课时。
- 开始、继续、暂停、放弃、关闭学习会话。
- 发送教学消息、停止或重试生成。
- 创建、编辑、重试、停止、归档和重命名补充学习会话。
- 安排或取消学习计划。
- 手动刷新周报、画像或运行时连接。
- 永久删除课程档案。

命令成功后的页面更新优先使用命令响应或精确失效的查询，不进行无差别全站重载。

## 6. 流式 Markdown

教学、课程创建和补充学习使用流式协议。前端按帧处理：

- 文本增量立即追加到当前 assistant 消息。
- 结构化终止帧确认完成、停止或失败。
- 收到首段前显示“正在思考”，而不是空白卡片。
- 用户停止只停止当前生成，不撤销此前已经收到的内容。
- 连接中断后按任务状态恢复，不盲目再次提交同一消息。

Markdown 渲染必须转义危险 HTML，代码、列表、引用和关系链保持可读。隐藏状态指令不进入正文 DOM，也不向用户暴露。

## 7. 正式学习页面

学习页以服务端会话视图为唯一状态来源，主要区域包括：

- 课时标题与当前阶段。
- 对话消息流。
- 必要的进度/知识点导航。
- 输入框、发送、停止、重试与会话动作。
- 关闭条件和恢复提示。

“没有其他问题”“可以总结了吗”等表达通过服务端语义识别进入状态机。前端不维护结束白名单，也不根据某句文本直接隐藏输入框或提交完成。

页面收到“回复已显示但账本仍在恢复”状态时，保留已显示内容并暂时限制冲突写入；恢复完成后再开放下一轮。

## 8. 课时记录与 Review 投影

课时记录页将原始正式会话与补充会话放在同一对话页签内切换，但边界清晰：原始会话只读，补充会话可继续或归档，Review 始终指向正式课时完成时产生的不可变文档。

### 8.1 知识图谱

前端从完整 Review 中投影：

- 一条主链。
- 有限节点。
- 关键关系词。
- 必要时一个很短的支链或边界说明。

不再把每个知识点展开成长段说明，也不把“图谱”退化成普通摘要列表。

### 8.2 核心思想

核心思想固定回答两件事：

1. 本课要解决的核心问题是什么。
2. 本课用什么思想、方法或判断框架解决。

它不复述知识图谱，不代替学习表现评价，长度以几段和少量要点为上限。

### 8.3 学习表现评价

后端 performance blocks 保持完整；投影合并同类行为，只显示：

- **你做得好的地方**：最多四个归纳单元。
- **接下来的判断**：最多五个待验证判断或下一步检查点。

区块标题应描述真实学习行为，不使用“综合证据观察”“reasoning dimension”等内部概念。

### 8.4 邻接探索

当 Review 中确实存在“邻接探索”类附加段落时，页面在主 Review 后显示“课程邻接探索”模块；没有相关内容就不占位、不生成模板文案。

## 9. 学习画像投影

画像页面把后台证据结构转写为用户语言，而不是简单隐藏字段名。每条洞察至少包含：

- 一个能概括具体做法的标题，例如“你会先拆清依赖，再做选择”。
- 一段说明这个模式在哪些学习会话中重复出现。
- 一段解释它可能带来的帮助或当前限制。
- 可展开的证据链，供需要时核对来源。

总标题和总摘要也必须来自真实洞察，不能用“近期学习中的结构化推理观察”之类模板。可接受的摘要应直接告诉用户：最近反复采用了什么学习方式，在哪类任务中最明显，以及证据还不足以推断什么。

后台 schema 名称、证据版本、投影层次和生成器名称只允许出现在诊断或证据详情中，不进入默认阅读界面。

## 10. 运行时恢复体验

浏览器只打开由交互包装器负责的主页，不由 Host、Launcher 或轮询任务反复拉起新窗口。

前端通过 `43119` 控制面了解 Launcher 状态，通过 readiness 检查 `43120` 应用服务。当出现服务停止、版本激活或构建不匹配时：

1. 保留当前页面和用户输入。
2. 显示正在重连、重建、激活或回滚的具体阶段。
3. 只接受目标构建 readiness 与控制面激活记录一致的结果。
4. 恢复后重放安全查询，不重放可能产生副作用的命令。
5. 失败时提供运行中心入口和可公开的错误码，不泄漏密钥或内部命令行。

## 11. 前端验证

前端变更至少覆盖：

- 路由和资源状态。
- 条件刷新命中与失效。
- 流首帧、终止、停止、重试和断线恢复。
- Review/画像用户语言投影。
- 原始会话与补充会话切换。
- 构建身份保护和运行时恢复。
- 键盘输入、可见焦点、禁用态和错误可读性。

视觉回归只验证关键页面与状态；不为每一段动态 AI 文本建立脆弱快照。
