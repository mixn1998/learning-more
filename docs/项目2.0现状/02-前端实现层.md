# Learning MORE 2.0：前端实现层

## 1. 前端职责

前端位于 `apps/web`，负责把服务端权威状态投影为可操作工作台，并提供即时反馈、流式内容、版本保护和故障恢复。前端不自行判定课程闭环、不从 AI 文案推断学习进度，也不在本地复制课程、Review 或画像的长期事实。

当前技术栈：

- React 19；
- React Router 7；
- TypeScript 5；
- Vite 8；
- `react-markdown` 与统一 AI 内容渲染边界；
- `@learning-more/contracts` 作为跨端 Schema；
- `@learning-more/ui` 作为共享视觉组件。

架构门禁禁止 `apps/web` 直接导入服务端实现或 Node 平台模块。

## 2. 页面路由

应用使用 `BrowserRouter` 和 `useRoutes`。除主页外，业务页按路由懒加载，并由统一错误边界处理动态模块加载失败。

| 路由 | 页面 | 主要实现 |
| --- | --- | --- |
| `/` | 主页 | `features/home/home-page.tsx` |
| `/courses/new` | 课程创建工作台 | `features/course-authoring/authoring-page.tsx` |
| `/courses/:courseId` | 正式课程、修改大纲、课程 Review | `features/review/course-page.tsx`、`features/course/*` |
| `/courses/:courseId/lessons/:lessonId` | 课节入口或正式学习 | `features/learning/*` |
| `/courses/:courseId/lessons/:lessonId/record` | 课节记录与 Review | `features/history/lesson-record-view.tsx` |
| `/lessons/:lessonId` | 兼容课节入口 | 重用正式课节路由 |
| `/planning` | 课程规划与计划流 | `features/planning/planning-page.tsx` |
| `/history` | 统计、日历、学习画像 | `features/history/history-page.tsx` |
| `/profile` | 画像兼容入口 | 重定向至 `/history?tab=portrait` |
| `/runtime` | 运行中心弹层 | `features/runtime/runtime-center.tsx` |

所有路由位于统一 `AppShell`。运行中心作为模态工作区打开，关闭时返回进入它之前的页面。

## 3. 应用外壳与运行版本保护

前端启动先读取 `/api/v1/runtime/ready`，应用外壳据此进入加载、离线或已加载状态。已加载后继续保存和比较：

- `buildId`：实际 Server 构建身份；
- `protocolVersion`：前后端协议版本；
- `instanceId` 与 `identityFingerprint`：实例身份；
- Store、投影与 Provider readiness。

当页面构建与 Runtime 不一致时，版本守卫禁止业务写入，避免旧前端向新合同提交命令。恢复流程还会读取实际静态站点的 `/build-meta.json`；只有 Host 活动构建、Runtime readiness 和 served Web 三方身份一致，页面才解除版本阻断。

运行中心中的“一键重连”和“同步前端版本”共享同一个客户端恢复协调器。恢复过程中出现的瞬时探测失败不会被提前投影成最终离线；Host 已持久化的激活失败也不会因为旧 Runtime 仍可访问而被抹掉。

## 4. 客户端数据模型

### 4.1 合同优先

所有业务 JSON 在进入页面状态前通过 `packages/contracts` 中的 Zod Schema 解析。HTTP 非成功响应优先解析为统一 `ApplicationProblem`，页面依据错误码、是否可重试和关联资源决定提示、重载或重试。

### 4.2 权威状态与本地状态

项目没有全局业务状态库。状态按责任分布：

| 状态位置 | 用途 |
| --- | --- |
| AppShell / Runtime Context | 运行身份、版本守卫、恢复状态 |
| URL 路由与查询参数 | 页面选择、历史页签、课程视图 |
| 页面 reducer / `useState` | 输入、弹层、忙碌态、乐观消息和局部错误 |
| 服务端资源视图 | 课程、会话、任务、进度、排期、Review 的最终事实 |
| `sessionStorage` | 短期 Launcher capability |
| 页面实例 ID | 多窗口写入身份 |

前端可乐观展示用户消息和操作意图，但服务端响应或重新拉取的资源版本始终覆盖本地猜测。

### 4.3 写命令与并发

写请求组合使用：

- `idempotency-key`：同一用户动作重试时不产生第二次业务提交；
- `If-Match`：携带当前资源版本，拒绝过期写入；
- `x-page-instance-id`：标记当前窗口；
- `x-csrf-token`：保护本地写请求。

`useCommandAttempts` 按业务动作保留命令尝试，成功后清除。资源版本冲突时，页面先重新读取权威状态，再允许用户继续操作。

## 5. 主页

主页消费 `/api/v1/home` 聚合视图，展示正式课程、草稿、课节状态和近期排期。课程入口优先显示活动学习会话，其次显示服务端下一课推荐，并排除已放弃或已失效课节。

用户在主页选择学习模式并输入学习方向后，前端通过路由 state 把该意图交给课程创建页，避免两个页面重复录入。

主页“选择课程”和正式课程页“切换课程”共用 `course-catalog-filters.tsx`。组件从真实课程目录提取归一化学科/领域和来源模式选项，并在前端执行交集筛选；学科标签统一经过 `discipline-label.ts`，来源模式统一读取课程模式注册表。选择课程列表不再额外显示“正式课程”分组标题或卡片后缀。

## 6. 课程创建工作台

### 6.1 页面状态

`authoring-page.tsx` 使用 reducer 管理：

- 模式与初始学习方向；
- 大纲创建会话和消息；
- 材料上传；
- AI 回复任务；
- 候选生成、取消与恢复；
- 候选确认；
- 草稿保存、删除和错误恢复。

服务端 `OutlineSessionView` 是权威来源。刷新页面时，前端重新读取会话；如果存在活动任务，则根据任务 ID 续接 SSE，而不是要求用户手动刷新才能看到候选。

### 6.2 对话与候选生成分离

候选已经生成后，页面同时提供“生成新候选”和“确认此候选”。用户继续发送调整消息时：

1. 左侧立即显示用户消息；
2. AI 只完成对话回复；
3. 当前候选保持不变；
4. 用户点击“生成新候选”后才发起完整候选任务。

生成期间使用 `CandidateGenerationPending` 悬浮层展示“正在生成候选大纲”，并保留“取消生成”。取消只针对当前候选任务，不删除已有对话和上一候选。完成后页面使用返回的会话/候选状态直接更新，不依赖手工刷新。

### 6.3 候选展示与确认

候选 Markdown 通过统一 `AiContent` 渲染；结构化课程块通过大纲投影器生成。确认按钮打开显式确认弹层，成功后导航到正式课程页。候选合同失败、Provider 失败、任务取消、超时和 SSE 中断分别映射为不同恢复提示。

## 7. 正式课程与大纲修改

`course-page.tsx` 根据课程状态和查询参数组合：

- 正式课程目录；
- 大纲版本与修改工作台；
- 课程关闭状态；
- 课程总 Review。

### 7.1 课程大纲投影

`outline-markdown-projection.ts` 负责把确认版 Markdown 映射到页面：

- H1 映射课程标题；
- H1 后显式摘要映射课程摘要；
- 模块层级按实际 Markdown 结构与保存的课节关系映射；
- 课节摘要读取课节自身目标；
- 无法归属模块的真实课节进入平铺区，不虚构模块；
- 新旧版本差异由独立 diff 投影处理。

`discipline-label.ts` 对历史细粒度学科标签进行确定性归一化，供课程顶部、规划筛选和历史筛选共用。

### 7.2 大纲修改工作台

修改页是左右两栏：

- 左栏：历史对话、修改输入框、AI 回复和操作区；
- 右栏：当前正式大纲，或候选大纲与版本差异。

发送消息不会自动替换右栏。AI 回复完成后，用户点击左栏右侧的“生成新候选”才启动候选任务；“确认并发布 vN”也位于同一操作区。生成期间复用候选悬浮组件并允许取消。

候选生成后如果又产生更新对话，页面显示“当前候选未包含生成后的最新对话”，但不擅自丢弃候选或自动重生。发布成功后重新读取正式课程和版本列表。

## 8. 课程规划

规划页读取排期视图并结合课程/课节目录生成周轨道和待安排区。日期筛选初始为空，不默认今日。

单课节日期使用行内 `<input type="date">`。有效日期变更立即提交；成功后用响应中的排期项更新当前行，失败时恢复原值并显示行级错误。移动、调整时长、锁定和删除使用同一“服务端响应回填”模式。

规划页顶部提供“清空排期”。用户确认后提交带排期集合版本的批量命令，成功时用服务端返回的空排期视图和新版本一次替换本地状态；版本冲突时不做部分清空。

`PlanFlowPanel` 只采集结构化约束并展示确定性预览。约束变化使旧预览失效；确认前不写正式排期。确认后的管理区提供“撤回排期”，仅在后端存在可逆批次快照时启用；操作前明确提示手工排期不会被修改，后端返回冲突时显示整批未变更。

## 9. 正式学习页面

### 9.1 页面组合

`lesson-entry-page.tsx` 先加载课节预览和学习状态，再决定进入：

- 未开始课节说明；
- 活动学习会话；
- 已放弃课节恢复入口；
- 已完成课节记录。

`session-page.tsx` 协调命令、任务、资源版本和计时；`lesson-session-workspace.tsx` 负责三栏学习布局；`message-stream.tsx` 负责对话；`session-window-lifecycle.ts` 处理页面前后台与暂停恢复。

### 9.2 教学进度投影

右侧“本课学习线索”只读取服务端 `teachingProgress`。前端不根据消息数、关键词或 AI 文案猜测知识点状态。

投影规则为：

| 服务端状态 | 页面文案 |
| --- | --- |
| `pending` | 待讲解 |
| `learning` | 正在学习中 |
| `completed` | 该知识点已完成 |
| `skipped` | 跳过知识点 |
| 互动 `skipped` | 跳过知识点互动 |
| 综合检测 `skipped` | 跳过检测 |

路径还显示课前热身、综合检测、讨论答疑和本课总结。只有服务端账本进入 `ready_to_close` 后，“结束本课”才会走正常课节闭环；否则显示未闭环确认。

### 9.3 消息、流和恢复

- 开始会话后自动请求 AI 教学开场；
- 用户消息先乐观展示，拒绝提交时保留内容并显示失败；
- AI 回复通过 SSE 任务帧增量显示；
- 断线后按任务序号续读；
- 刷新后读取活动任务并恢复流；
- 用户可以停止当前生成，已生成部分作为中断回复保存；
- 页面进入后台不取消已经启动的 AI 任务；
- 身份匹配的后台回复完成后可写回暂停会话。

### 9.4 计时与多窗口

前端显示服务端累计时长加当前开放计时间隔。页面进入后台、会话暂停、AI 等待或失去写入权时不继续本地递增，避免服务端权威时长与浏览器秒表相互拉扯。

同一原始会话只有一个写入窗口。第二窗口以只读状态打开，可主动接管；接管后旧窗口重新拉取状态并停止写入。

## 10. 历史、Review 与学习画像

### 10.1 历史与统计

历史页用 URL 查询参数保持统计、学习日历和学习画像页签。日期或筛选变化时先清空旧结果再读取新数据，避免旧日期内容短暂冒充当前结果。

数据请求按页签拆分而不是进入页面后全量串行等待：画像页直接渲染画像工作区；周报只请求主页摘要与目标周报告；日历读取主页、历史与日历；统计页先用统计接口完成首屏，课程、课节和日历明细作为非阻塞补充请求。明细尚未返回时，顶部指标使用统计接口的权威合计，避免先显示 0 再跳变。

学习参与面板只显示：

- 关键互动回应率；
- 跳过互动。

课节记录按结构化角色展示原始会话、补充会话和 Review，不解析文本前缀。

### 10.2 Review 展示

最终课时 Review 的用户投影将后台完整文档整理为知识主链、核心思想和学习表现。该投影只改变阅读结构，不修改后台 Artifact、来源引用或不可变状态。

课程总 Review 只在课程档案页展示；课时 Review 弹层不混入课程总 Review 或下一课入口。

### 10.3 学习画像

画像位于历史页签中的 `portrait-workspace.tsx`。首次进入读取当前画像与证据，随后在同一客户端生命周期内缓存成功快照；页签切回时先立即展示该快照，只轻量检查当前画像版本，版本未变化时不重读证据，也不提交刷新任务。只有用户点击“刷新画像”才请求真实刷新任务；轮询到成功版本后替换当前快照。生成失败时保留上一成功版本和失败提示，不把失败草稿显示为正式画像。

前端只展示跨会话稳定结论、普通语言说明、来源和局限，不展示后台候选证据 ID、原始回答、分析器术语或单课局部维度。展开“这条观察从哪里来”时，每个独立来源卡直接展示服务端已经净化的具体行为摘要，不再用统一模板替换不同来源。全局用户档案没有独立产品页面。

## 11. 运行中心

运行中心周期读取 Provider 状态和动态目录，支持：

- Mock、API、Codex CLI Provider；
- API Base URL、模型与密钥句柄；
- Codex 登录和动态模型目录；
- 模型与推理强度；
- 应用配置、检查接口、重连当前 Provider；
- 一键重连本地服务、同步前端版本、生成脱敏诊断。

Launcher 控制写入使用短期 capability 并保存在 `sessionStorage`。capability 明确失效时客户端只重新获取一次。旧 Launcher 因版本切换而断开时，客户端使用新的激活 `requestId` 继续追踪，不把历史激活终态当成本次结果。

## 12. 共享 UI 与内容边界

`packages/ui` 提供按钮、卡片、字段、布局、状态条、对话框、页签、Toast、`AiContent` 和 `AiSurface`。

`AiContent` 是 AI Markdown 的统一入口，负责 GFM 表格、数学公式、HTML 清理、宽表格滚动和有限的模型输出标准化。`math-plot` 声明块通过版本化合同、数学表达式 AST 白名单和按需加载的 JSXGraph 渲染显函数、参数方程、极坐标、隐函数、离散点、三维曲线与曲面、二维向量场和微分方程相图；额外元数据会被忽略，未知协议或不安全表达式只降级当前图像。Mermaid 代码块保留安全 fallback，不执行任意脚本。课程创建、教学、Review、周报和画像共用该边界。

共享聊天组件位于 `apps/web/src/components/chat`：

- `UserMessageRow`：整行右对齐、消息状态、失败与重试；
- `UserMessageBubble`：内容宽度、最大宽度、换行和失败样式；
- `ChatComposer`：自适应 textarea、Enter 发送、Shift+Enter 换行和输入法组合态保护；
- `ConversationStream`：智能跟随底部、保留向上阅读位置、回到最新消息和无障碍播报。

这些组件共同保证短文本不纵向挤压、多行输入保留换行、用户气泡位于右侧。

## 13. 前端验证边界

当前前端测试覆盖路由、主页、课程创建、手动候选生成、候选取消与恢复、大纲投影、大纲修改、计划流、学习会话、计时、进度文案、历史、画像和运行中心。

文档不固化测试数量和构建 chunk 大小。生产验收仍以类型检查、组件测试、产品 UI 检查、Playwright、视觉测试、生产构建，以及活动实例的 `build-meta.json`/readiness 一致性为准。
