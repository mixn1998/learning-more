## 当前系统一句话概括

Learning MORE 是一个本地优先、单用户的 AI 学习闭环：用户通过对话形成可确认课程，在正式课节中接受实时互动教学，由确定性状态机管理教学进度、排期、事实、Review 和画像数据，再由运行中心管理本地版本与 AI Provider。

当前主链路为：

```text
学习方向或材料
→ 大纲创建会话
→ 用户手动生成并确认候选大纲
→ 正式课程与确定性排期
→ AI 实时教学 + 教学状态账本
→ 课节闭环与 Review
→ 历史统计、全局用户档案与学习画像
→ 下一课与后续学习
```

## 已确认的关键口径

- 候选大纲不会因为 AI 在左侧回复了用户就自动生成；创建课程和修改正式大纲都由用户点击“生成新候选”。
- 计划流是确定性排期程序，不调用 AI。
- 教学智能体同时返回用户可见 Markdown 和前端不可见的结构化教学指令。
- 教学指令推进教学状态账本；教学观察不再决定知识点是否完成，也不决定课程是否闭环。
- 教学观察基于完整会话历史重建行为记录，供 Review、学习事实、统计和画像链路消费。
- 最终课程总结之前，对话必须持续给用户留下与本课相关的表达入口。
- 综合检测完成或被跳过后必须进入讨论答疑；只有用户明确没有其他疑问，才可输出最终总结并把课节标记为可关闭。
- 暂停学习事实在任何层都不计入行为证据。
- 学习画像是用户可见功能，不是数据层；它消费全局用户档案中的跨会话稳定维度。
- 学习画像页面日常只读取当前成功快照；新画像只由每周六 00:00 定时任务或用户显式手动刷新生成，切换页签不会触发刷新。
- 一键重连与同步前端版本都经过 Host 管理的候选构建、验证、激活和失败回滚路径。

## 状态词约定

本文只使用三类能力状态：

- **已接入**：活动产品入口或 HTTP 路由可达，并进入生产装配。
- **条件接入**：实现已进入生产装配，但只有满足环境条件时才出现，例如 API Provider 或 Codex CLI。
- **当前限制**：代码中明确存在的能力缺口，不以未来设计代替当前事实。

测试夹具、仅存在的类型名、已从注册表删除的场景，以及没有生产提交路径的实验代码，不列为产品能力。

## 维护规则

- 功能规则变化只更新功能设计层；页面与状态呈现变化只更新前端实现层；模块、数据和运行机制变化只更新后端架构层。
- 当前产品范围或验收口径变化时同步更新 PRD；产品定位、主要矛盾或演进优先级变化时更新产品深度分析。
- 同一事实不在三份文档中重复展开；跨层内容使用链接或简短引用。
- 不记录提交历史、阶段计划、临时实施步骤和已经完成的迁移过程。
- 不固化容易过期的测试数量、代码行数和动态模型目录。
- 更新文档时必须先核验当前活动实例和源码，并保持 `CONTEXT.md` 中的领域术语一致。
