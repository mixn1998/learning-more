# Learning MORE 2.0 当前态产品需求文档（PRD）

> 本 PRD 描述截至基线提交 `d201b8c` 已进入产品与工程合同的需求。它不是未来路线图。

## 1. 产品定义

Learning MORE 是一套单用户、本地优先的 AI 学习系统。它帮助用户把一个学习目标转化为可修订课程，在真实对话中完成课时、记录笔记、复盘和安排，并保留跨会话的上游用户档案数据。

产品成功不以“生成了多少内容”为核心，而以以下闭环是否成立为准：

```text
目标表达 → 课程大纲 → 正式学习 → Review → 后续规划
                         ↘ 学习笔记
                           ↓
                  事实/证据 → 用户档案
```

## 2. 目标用户与使用环境

- 主要用户：希望系统学习复杂主题、愿意通过对话进行思考与练习的个人。
- 使用环境：Windows 本机、单用户、长期保留本地学习档案。
- AI 前提：用户配置至少一个可用 Provider；不同场景可使用不同模型或推理强度。
- 非目标：团队协作、学校班级管理、账号体系、云同步、内容市场。

## 3. 产品原则

1. **学习事实优先**：AI 可以解释，不得改写已经完成的课时和 Review。
2. **渐进生成**：先完成当前需要的内容，不要求一次生成整门课程的所有正文。
3. **可恢复**：服务、生成和写入失败后，用户不需要重做已确认步骤。
4. **证据约束**：跨会话档案事实必须能回到独立来源，并说明限制。
5. **用户语言**：后台状态、投影版本和分析术语不直接出现在产品主界面。
6. **本地可控**：数据、密钥、备份和运行状态均在本机边界内可诊断。

## 4. 核心用户旅程

### 4.1 创建课程

**用户目标**：把一个模糊学习意图变成可执行课程。

**需求**：

- 用户可用自然语言描述目标、背景、期望深度和时间。
- 系统保留创建对话并生成候选大纲。
- 用户可继续提出调整要求，并查看前后差异。
- 用户确认后，候选大纲成为正式课程。
- 生成失败保留对话和请求，可重试而不重复课程。

**验收**：

- 未确认候选不得进入课程表。
- 同一确认命令重复提交只产生一个正式版本。
- 历史创建对话可追溯。

### 4.2 修订课程与保护已完成课时

**用户目标**：完成部分课程后调整后续方向，不丢失已学内容。

**需求**：

- 修订 Prompt 包含过去大纲对话压缩和已完成课时概要。
- 已完成课时明确标记为完成，并原样保留在新版课程表。
- 已完成课时的身份、课义、完成记录和计划记录冻结。
- 与已完成内容明确重复的新课时自动删除。
- 部分重叠或不确定项标记为“需要确认”；用户可手动标为删除或新增。
- 模块二及后续未完成内容可使用新版大纲。

**验收**：

- 修订后，已完成课时仍在当前大纲且可打开原记录。
- 不出现“原课时成为历史只读、新版又出现同义重复课”的结果。
- 不确定重复不会阻止整个大纲发布。

### 4.3 正式学习

**用户目标**：在对话中理解、练习、追问并完成一节课。

**需求**：

- 页面流式显示教学 Markdown。
- 教学按开场、知识点、综合检查、讨论、总结和可关闭阶段推进。
- 用户可自由追问；结束答疑依赖语义意图而非固定句式。
- 状态机同时检查阶段、答疑确认和总结状态。
- 用户可停止生成、重试失败消息、暂停和恢复会话。
- 必要时可生成数学关系图，不把工具能力当作默认噱头。
- 教学可使用少量稳定学习档案做个性化，但不做人格或能力推断。

**验收**：

- “我没有其他问题了”“可以总结了吗”等同义表达能进入正确状态。
- 未交付总结时不能直接完成课时。
- 回复展示后发生持久化失败时可恢复，且不复制同一消息。
- 进行中会话只允许一个有效写租约。

### 4.4 完成、放弃和 Review

**用户目标**：可靠地结束课时并留下可回看的学习产物。

**需求**：

- 完成触发最终 Review 和关闭事务。
- Review 后端完整保存知识图谱、核心思想、学习表现、证据和可选邻接探索。
- 前端知识图谱只显示关系主链；核心思想回答问题与方法；学习表现合并为两个区块。
- 用户可放弃课时；放弃不计为完成，也不进入待规划。
- 关闭中断后自动恢复，不产生两份正式 Review。

**验收**：

- 完成状态与正式 Review 同步可用。
- 前端投影精简后，后端完整文档和引用保持不变。
- 邻接探索无内容时不显示占位模块。
- completed/abandoned 均从规划候选中排除。

### 4.5 补充学习

**用户目标**：完成课时后继续探索相关问题，同时保护原学习记录。

**需求**：

- 从已完成课时记录创建独立补充学习会话。
- 原正式会话与 Review 始终只读。
- 补充会话支持对话、流、停止、重试、消息修订、重命名和归档。
- 一个课时可保留多个补充会话，并在记录页切换。

**验收**：

- 补充消息不会追加到原正式会话。
- 归档后会话不可继续写入，但历史内容仍可读。
- 失败重试不复制用户消息或 assistant 内容。

### 4.6 规划与首页

**用户目标**：知道下一步学什么，并快速查看近期状态。

**需求**：

- 规划页只显示当前有效大纲中的可安排课时。
- 默认遵循大纲顺序，支持安排和取消计划。
- 首页显示当前课程、下一步、课程规划和上周回顾。
- 首页汇总使用静态快照与条件刷新；无源数据变化时直接复用。
- 已有快照时后台刷新不得清空页面。

**验收**：

- 同一计划命令重复提交不会产生重复记录。
- catalog/learning/schedule 未变化时，首页不重建汇总。
- 源修订变化后，下一次查询返回更新后的快照和 ETag。

### 4.7 历史、统计、日历和周报

**用户目标**：回看课程过程和近期学习节奏。

**需求**：

- 历史页提供课程/课时记录、统计、日历、周汇总和周报。
- 大数据列表分页，不一次传输全部对话。
- 不同区块独立刷新，失败时保留最后成功值。
- 周报面向已完成自然周后台生成，启动时补偿遗漏。

**验收**：

- 打开统计或日历不重新加载全部课时正文。
- 周报任务重复执行同一周只产生一个正式结果。
- 周报生成失败后不覆盖旧报告。

### 4.8 学习笔记和上游用户档案

**用户目标**：在课堂中连续记录独立笔记，并能跨课程查阅；系统同时保留可审计的上游档案事实。

**需求**：

- 原始行为先形成会话聚合维度，再进入候选证据。
- 稳定行为通常至少由两个独立会话支持；用户明确偏好可直接记录。
- 候选证据去重同源投影，保留反向证据和适用边界。
- 课堂每次保存形成独立笔记，自动快照时间、学科、课程和课节。
- 保存后既有本课笔记继续可见；保存失败保留草稿。
- 全局笔记页按学科和课程整理，并允许逐条编辑或删除。
- 当前版本不提供学习画像或档案驱动的教学个性化消费。

**验收**：

- 连续保存多条笔记不会覆盖前一条。
- 删除课程后，笔记仍可通过保存时的元数据快照查阅。
- 上游用户档案数据不因画像功能删除而丢失。
- 默认界面不出现 analyzer、projection、dimension、source group 等术语。

### 4.9 永久删除课程档案

**用户目标**：彻底移除一整套课程数据，并同步清理全局视图。

**需求**：

- 删除前展示不可恢复性质和级联范围。
- 删除课程、版本、课时、正式/补充会话、Review、计划和相关事实。
- 全局统计、档案、证据和画像同步失效或重建。
- 中断时可继续完成或恢复到一致状态。

**验收**：

- 删除后所有页面和查询都不再返回该课程。
- 不存在候选证据或画像继续引用已删除来源。
- 重复删除返回幂等成功或明确已不存在，不产生损坏。

### 4.10 本地运行与恢复

**用户目标**：关闭终端或 Codex 后，Learning MORE 仍能稳定运行；普通崩溃自动恢复。

**需求**：

- Windows Task Scheduler 在登录时独立触发 Host，不按分钟重复。
- Host 单实例守护 Launcher；Launcher 守护 Server。
- 普通 Server 崩溃采用退避重启；重启风暴进入诊断状态。
- 工作区变化触发候选构建、验证、激活；失败保持或回滚到健康构建。
- 后台进程不得反复打开新主页；只由交互包装器打开。
- 运行中心显示安全的健康、Provider、构建和恢复状态。

**验收**：

- 结束 Codex/终端不终止由任务调度器启动的 Host。
- Server 意外退出后由 Launcher 拉起。
- 新构建未通过 readiness 时不替换健康版本。
- 浏览器不会因健康轮询或 Host 重启反复打开新标签。

## 5. 非功能需求

### 5.1 数据完整性

- 关键 JSON 经 schema 和 checksum 校验。
- 文件原子替换，跨文件事务可恢复。
- 单 DataRoot 只允许一个写者。
- 读模型可重建，源聚合不可从画像反推。

### 5.2 性能

- 无变化首页请求不得遍历全部源文件。
- 有旧快照的页面刷新不得阻塞首屏。
- 历史列表分页，正文按需加载。
- AI 任务并发有界，避免耗尽本机资源。

当前实现尚未承诺固定毫秒级 SLO；性能以可重复基准和真实数据规模持续量化。

### 5.3 隐私与安全

- 默认只监听回环地址。
- 密钥不进入仓库、浏览器、普通日志或备份明文索引。
- Markdown/错误输出进行安全渲染和信息收敛。
- 删除是显式用户操作，不由维护任务自动执行。

### 5.4 可维护性

- 合同、领域、基础设施和 UI 依赖方向清晰。
- Provider 与 Repository 可替换。
- 日常测试快速，完整恢复矩阵留在合并/发布门禁。
- 动态运行值不硬编码为文档或业务常量。

## 6. 当前产品限制

- 不支持登录、多用户和云同步。
- 通用附件、网页和外部资料没有统一摄取链。
- 画像描述的是有证据的近期行为模式，不是能力测评或人格标签。
- AI 生成质量仍随 Provider、模型、Prompt 和输入证据变化。
- 本地文件方案适合当前单用户规模；更大容量的阈值尚需基准测试后决定。

## 7. 当前版本完成定义

一项需求只有同时满足以下条件才算进入当前态：

1. 共享合同已定义。
2. 模块实现遵守领域不变量。
3. 失败、重试和恢复路径明确。
4. 用户界面能区分加载、刷新、恢复、空值和错误。
5. 自动测试覆盖关键成功与边界路径。
6. 本地构建通过身份验证并可由 Host 激活。
