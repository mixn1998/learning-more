# Learning MORE 2.0 当前态产品需求文档（PRD）

## 1. 文档说明

### 1.1 文档目的

本文从 Learning MORE 当前可运行产品、主线代码和领域规则反向整理产品需求，回答：

- 产品当前为谁解决什么问题；
- 用户能够完成哪些任务；
- 每条核心业务流程应满足什么规则；
- AI、程序和用户分别拥有什么决策权；
- 当前版本怎样才算符合产品要求。

本文是当前态 PRD，不包含尚未实现的目标能力。产品缺口与演进建议见 [产品视角深度分析](./05-产品视角深度分析.md)。

### 1.2 事实基线

本文以 2026-07-18 核验的当前主线和活动实例为准。功能事实来源依次为：活动 Runtime、生产装配、跨端合同、领域模型、页面实现和自动化测试。

### 1.3 产品形态

- 本地优先；
- 单用户；
- 桌面浏览器产品；
- AI Provider 可配置；
- 学习数据与运行数据保存在本地；
- 当前不包含多人协作、教师后台、云端账号和跨设备同步。

## 2. 产品定义

Learning MORE 是一个把“我想学什么”持续转化为“我真实学了什么、理解到什么程度、接下来学什么”的 AI 学习闭环。

它由五个连续价值环组成：

```text
学习意图结构化
→ 可控课程生成
→ 实时互动教学
→ 学习结果沉淀
→ 跨会话个性化
```

产品不是静态课程生成器，也不是没有教学责任的通用聊天窗口。正式课程拥有确认版大纲、稳定课节、教学进度、学习会话、Review、排期和长期行为证据。

## 3. 目标用户与核心任务

### 3.1 核心用户

当前产品服务于具备主动学习意愿、愿意通过文字持续表达和思考的个人学习者，典型场景包括：

- 为工作或项目快速建立一个陌生领域的知识框架；
- 系统学习数学、商业、技术、设计等主题；
- 通过案例、辩论、拆解或讨论深化已有知识；
- 围绕阅读材料开展结构化研讨；
- 将分散学习过程沉淀为可回顾记录和长期画像。

### 3.2 用户核心任务（Jobs to Be Done）

| 编号 | 用户任务 |
| --- | --- |
| JTBD-01 | 当我只有一个模糊学习方向时，帮助我澄清目标并形成可执行课程。 |
| JTBD-02 | 当我不确定课程结构是否适合自己时，让我通过对话调整并显式确认。 |
| JTBD-03 | 当我正式学习时，根据我的真实回答动态讲解，而不是只输出预制长文。 |
| JTBD-04 | 当我暂停、离开或服务中断时，保留真实进度并可继续原会话。 |
| JTBD-05 | 当我完成或放弃课节时，准确记录发生过什么，不把未完成伪装成完成。 |
| JTBD-06 | 当学习积累后，让我看到可靠的统计、Review 和跨会话学习画像。 |
| JTBD-07 | 当 AI 或本地服务失效时，让我能理解状态、切换配置并恢复运行。 |

## 4. 产品目标与非目标

### 4.1 当前产品目标

1. 把自然语言学习意图变成用户可确认、可版本化的正式课程。
2. 让正式教学根据真实会话渐进生成，并保持知识责任与闭环。
3. 让计划、计时、状态、Review 和统计不依赖 AI 文案猜测。
4. 让学习记录在暂停、刷新、重启和 Provider 故障后可恢复。
5. 从可追溯学习证据中形成长期个性化依据。
6. 让用户对生成、确认、发布、跳过、结束和删除等关键动作保持控制。

### 4.2 当前非目标

- 不替代学校、认证机构或正式考试；
- 不提供多人课堂、教师排课或组织管理；
- 不自动证明用户掌握程度达到外部认证标准；
- 不提供课程交易、内容市场或公开分享社区；
- 不将九种课程模式实现为九套互不兼容的产品；
- 不让 AI 直接负责权限、版本、排期和事实一致性；
- 不在本地产品之外承诺云端备份和跨设备访问。

## 5. 产品原则

### P-01 用户保留关键决策权

AI 可以理解、建议和生成，但候选生成、候选确认、大纲发布、跳过、结束课节和高风险删除由用户显式触发。

### P-02 教学必须基于真实表达

正式教学不得默认用户已经理解。是否推进由教学智能体结合真实回答判断，并通过隐藏结构化指令同步，不在可见文本中播报内部检测流程。

### P-03 生成与业务提交分离

AI 产出先作为候选或回复，程序校验后才更新领域状态。失败、中断或不合格输出不得破坏上一有效版本。

### P-04 确定性事实优先

排期、计时、生命周期、版本、写入权、统计事实和不可变提交由程序管理。页面不得从 AI 文本反推这些状态。

### P-05 证据可追溯

Review、统计和画像必须能够追溯到真实会话、消息和冻结输入。暂停、运行遥测和 Provider 故障不属于学习行为证据。

### P-06 故障不应抹掉已完成工作

刷新、断线、后台、重启和生成失败应优先保留用户输入、已提交回复、候选、会话和上一成功产物。

## 6. 产品信息架构

| 一级入口 | 用户目的 | 核心对象 |
| --- | --- | --- |
| 主页 | 发起、恢复或继续学习 | 课程、草稿、课节、近期排期 |
| 创建课程 | 澄清需求并确认候选 | 大纲创建会话、材料、候选大纲 |
| 正式课程 | 查看和管理课程 | 确认版大纲、课节、版本、课程 Review |

| 历史 | 查看学习记录和结果 | 事实、日历、周报、课节 Review |
| 学习画像 | 查看跨会话学习特点 | 画像版本、洞察、来源与局限 |

## 7. 核心用户旅程

### 7.1 从意图到正式课程

```text
选择课程模式并输入学习方向
→ 进入大纲创建会话
→ 与 AI 澄清目标、起点、约束和偏好
→ 用户点击“生成新候选”
→ 查看候选大纲
→ 继续对话并再次生成，或确认候选
→ 创建正式课程
```

### 7.2 从课程到课节完成

```text
查看正式课程与课节目标
→ 开始本课
→ AI 主动开场
→ 课前热身
→ 逐个知识点讲解、互动与判断
→ 综合检测或用户跳过检测
→ 讨论答疑
→ 用户明确没有其他问题
→ AI 输出最终课程总结
→ 账本 ready_to_close
→ 用户结束本课
→ 最终课时 Review 提交
```

### 7.3 从学习记录到长期个性化

```text
完整会话历史
→ 教学观察与原始行为引用
→ 阶段/最终 Review
→ 会话级抽象维度
→ 跨会话语义归并
→ 全局用户档案
→ 学习画像和教学个性化上下文
```

## 8. 功能需求

## 8.1 主页与导航

### HOME-01 主页聚合

主页必须统一展示正式课程、大纲草稿、课节状态和近期排期，不要求用户在多个入口查找当前任务。

验收标准：

- 活动学习会话优先显示继续入口；
- 未确认草稿与正式课程明确区分；
- 已放弃课节不作为默认下一课；
- 推荐只提供理由和入口，不自动开始学习。

### HOME-02 创建意图交接

用户在主页选择课程模式并输入学习方向后，创建页必须直接继承该意图。

### HOME-03 可恢复导航

未知路由、页面模块加载失败或 Runtime 离线时必须提供明确恢复入口，不显示空白页面。

### HOME-04 课程目录筛选

主页“选择课程”和正式课程页“切换课程”必须同时提供学科/领域与来源模式下拉筛选。学科/领域使用归一化大类，来源模式使用课程真实模式；两个条件按交集生效并允许一键回到全部。选择课程弹窗不得重复展示没有信息增量的“正式课程”标题或后缀。

### HOME-05 统一产品识别

浏览器标签、全局应用外壳和独立工作区页头必须使用同一 Learning MORE 品牌标识。图形采用中心点、开放圆环和扩展路径构成的“知识涟漪”，产品名固定为 `Learning MORE`；页面副标题可以随路由和业务状态变化，但不得形成新的 Logo 变体。

## 8.2 课程模式

### MODE-01 九种模式

产品必须支持标准模式、头脑风暴、论证交锋、案例研习、商业洞察、流程拆解、决策分析、交叉探索和阅读研讨。

### MODE-02 统一业务模型

九种模式共用课程、课节、排期、学习会话、Review、统计和画像状态机。模式只能调整视觉身份和教学关注，不得绕开通用课程不变量。

### MODE-03 阅读材料

阅读研讨必须支持 PDF、TXT 和 Markdown 材料进入大纲创建上下文。材料失败不得删除已存在会话内容。

## 8.3 大纲创建会话

### AUTH-01 会话先于课程

用户开始创建时必须先建立可恢复的大纲创建会话。候选确认前不得创建正式课程。

### AUTH-02 对话追加

用户消息必须立即进入当前会话，AI 回复完成后保存为独立消息。网络失败时用户输入不得静默消失。

### AUTH-03 对话与候选生成分离

AI 对话回复不得自动生成完整候选。只有用户点击“生成新候选”才提交候选任务。

验收标准：

- 已有候选后继续对话，右侧候选保持不变；
- “生成新候选”使用完整历史和当前候选；
- 同一会话同一时间最多一个候选任务；
- 生成期间可取消；
- 取消不删除对话和上一有效候选。

### AUTH-04 候选实时状态

候选生成期间必须显示明确悬浮状态。刷新后页面必须读取活动任务并恢复生成进度，不要求手工刷新第二次。

### AUTH-05 候选合同

候选必须包含：

- 课程标题；
- 50–100 字课程摘要；
- 学科/领域大类标签；
- 一至三个主题标签；
- 可编译课节；
- 每课目标、核心知识点、前置关系和预计时长。

### AUTH-06 候选确认

确认必须由用户显式触发，并以原子事务创建正式课程、确认版大纲和稳定课节。确认失败不得产生半成品课程。

### AUTH-07 草稿管理

用户必须能够恢复和永久删除未确认草稿。被删除或从未确认的草稿不得进入正式学习统计。

## 8.4 正式课程与大纲版本

### COURSE-01 正式课程页

课程页必须展示课程标题、归一化学科大类、课程摘要、模式、课节目录和当前大纲版本。

### COURSE-02 摘要来源分离

课程摘要只读取课程级显式摘要；课节摘要只读取课节自身目标和知识点。两套规则不得复用导致相互污染。

### COURSE-03 不可变版本

确认版大纲不可原地修改。每次发布必须形成新版本并保留旧版本读取能力。

### COURSE-04 大纲修改对话

正式大纲修改必须提供历史对话和输入框。AI 回复只解释或确认修改要求，不自动替换右侧大纲。

### COURSE-05 手动生成修改候选

用户点击“生成新候选”后才生成右侧新版本，并展示版本差异和模块改动说明。生成可取消。

### COURSE-06 候选新鲜度

候选生成后若出现新对话，页面必须提示候选未包含最新对话。系统不得自动发布或静默重生。

### COURSE-07 显式发布

“确认并发布 vN”必须由用户触发。发布后课程指向新确认版，并维护课节沿用、替换、新增和移除关系。

### COURSE-08 课程关闭与删除

课程关闭后大纲只读。永久删除必须有风险确认，并级联撤销该课程对学习事实和画像证据的贡献。

## 8.5 课程规划

### PLAN-01 初始日期状态

规划页进入时不得默认选中今日。未排期课节必须显示在待安排区。

### PLAN-02 行内日期选择

点击日期字段应直接使用行内日历。选择有效日期后立即保存，不再增加独立确认弹窗。

### PLAN-03 权威响应回填

日期、移动、时长、锁定和删除操作成功后必须使用服务端响应更新页面；失败时恢复原值并在当前操作位置提示。

### PLAN-04 确定性计划流

计划流必须根据结构化约束生成预览，不调用 AI。相同约束和基础排期版本必须产生相同结果。

### PLAN-05 预览与确认分离

预览不得写正式排期。用户确认前若基础排期变化，系统必须拒绝旧预览并要求重新计算。

### PLAN-06 排期不变量

计划流必须严格保持正式大纲中的课程内课节顺序、前置依赖和锁定项；即使课节没有显式先修关系，也不得跳过尚未完成的前置课节。课节不可拆分；超出每日目标的单课节仍作为原子项安排并明确标记。生成器与确认写入层必须分别校验该不变量。

### PLAN-07 清空当前筛选排期

课程规划页必须提供“清空当前筛选结果中的排期”操作。前端只提交当前筛选结果中已排期课节的 ID，后端按现有带集合版本的批量取消机制执行；未提交的排期不受影响。

### PLAN-08 撤回最近一次计划流排期

计划流必须能够恢复首次确认之前的完整排期状态。撤回只影响该计划流自动写入的确认批次，不修改无冲突的手工排期。若批次内排期已被手工修改，或恢复内容与当前手工/其他有效排期冲突，系统必须拒绝整批撤回并明确提示，不得覆盖用户修改。

## 8.6 正式学习会话

### LEARN-01 自动教学开场

开始正式课节后，AI 必须主动生成教学开场，不要求用户先提问。

### LEARN-02 渐进式教学

AI 每轮只承担当前教学阶段，不一次性倾倒整课。教学必须结合课程目标、当前知识点、真实历史、可用个性化背景和用户最新表达。

### LEARN-03 深度与思维激活

教学智能体不得默认用户已经理解。讲解必须提供充分理解过程，并通过问题、案例、比较、推理或应用提高思维激活与思考密度。

### LEARN-04 双区块输出

教学智能体必须同时返回：

- 用户可见 Markdown；
- 前端不可见的完整教学状态指令。

状态指令必须经过程序校验后才能推进教学账本。

### LEARN-05 教学进度来源

前端课程进度只能读取教学账本，不得根据消息数量、文字关键词或教学观察猜测。

知识点前端文案必须统一为：

| 状态 | 文案 |
| --- | --- |
| `pending` | 待讲解 |
| `learning` | 正在学习中 |
| `completed` | 该知识点已完成 |
| `skipped` | 跳过知识点 |
| 互动 `skipped` | 跳过知识点互动 |
| 综合检测 `skipped` | 跳过检测 |

### LEARN-06 教学推进规则

教学智能体拥有判断学习者是否足以进入下一阶段的自主权，但：

- 已完成或跳过节点不得倒退；
- 未完成知识点不得进入综合检测；
- 不得用“已经通过检测”等流程话术；
- 知识点完成后应通过小结自然过渡；
- 只跳过互动与跳过整个知识点必须区分。

### LEARN-07 对话不掉地

最终课程总结之前，每轮教学回复必须以一个自然、与本课相关、容易回应的问题或表达邀请收束。

### LEARN-08 讨论答疑

综合检测完成或被跳过后必须进入讨论答疑。

验收标准：

- AI 主动询问是否还有疑惑或其他讲解需求；
- 用户提问后完整回答并继续停留在讨论状态；
- 用户可以连续追问任意轮次；
- 未明确没有其他问题前不得输出最终课程总结；
- “明白了”与新问题同时出现时继续处理新问题。

### LEARN-09 最终总结与闭环

只有用户明确没有其他疑问时，AI 才能输出最终课程总结，并在同一轮将账本推进到 `ready_to_close`。最终总结不再提出新问题。

### LEARN-10 跳过综合检测

用户明确跳过综合检测后仍可进入讨论答疑、最终总结和正常闭环。跳过行为必须保留为观察事实。

### LEARN-11 用户显式结束

`ready_to_close` 不自动结束课节。用户点击“结束本课”后才进入最终 Review 关闭事务。

## 8.7 消息、暂停、计时与多窗口

### SESSION-01 用户消息可靠性

用户消息提交前可以乐观显示。请求被拒绝时必须保留输入并显示失败，不得悄然移除。

### SESSION-02 流式回复与停止

AI 回复必须支持流式展示和用户停止生成。已生成部分作为中断回复保存，不伪装成完整回复。

### SESSION-03 刷新恢复

页面刷新或 SSE 断开后必须根据活动任务 ID 和帧序号恢复，不得重复提交同一生成任务。

### SESSION-04 页面后台

页面进入后台时暂停计时和新用户输入，但不取消已经启动的 AI 任务。

### SESSION-05 暂停后回复提交

已启动任务在会话暂停后完成时，只要会话、任务和写入权身份匹配，必须允许提交完整回复；不匹配的迟到回复必须拒绝。

### SESSION-06 实际学习时长

实际学习时长只累计页面前台可见、当前窗口持有写入权、会话未暂停且不处于 AI 等待的区间。预计时长不得覆盖实际时长。

### SESSION-07 多窗口写入权

同一原始会话同一时间只能有一个写入窗口。第二窗口默认只读，可以显式接管；接管后旧窗口不得继续写入。

## 8.8 教学观察与学习行为

### OBS-01 完整历史重建

教学观察必须在完成的教学回合后读取完整会话历史，重建当前有效行为记录，而不是只处理最后一条消息。

### OBS-02 职责隔离

教学观察只记录教学行为、学习者回答、推理、提问、纠偏、跳过和开放问题，不判断用户是否通过检测，不推进知识点状态，也不决定课程闭环。

### OBS-03 来源引用

每条有效观察必须带真实消息来源。助手提出但用户没有提出的问题不得被误记为用户开放问题。

### OBS-04 观察失败恢复

观察失败不得撤销已经提交的教学回复和账本指令。系统必须把观察标记为待恢复，并可从完整历史重建。

## 8.9 放弃、恢复与 Review

### REVIEW-01 无证据放弃

没有有效教学或互动证据的短会话被放弃时，不生成 Review；恢复后回到未开始状态。

### REVIEW-02 有证据放弃

已有有效证据的会话被放弃时，冻结原会话并生成或更新阶段 Review；恢复后继续原会话。

### REVIEW-03 暂停不构成证据

暂停学习事实在任何层都不得计入行为证据，也不得触发 Review。

### REVIEW-04 冻结输入

Review 必须消费冻结的教学账本、观察引用、消息范围和来源哈希。页面是否打开不得决定后台 Review 能否完成。

### REVIEW-05 稳定 Review

每个课节最多一个稳定 `reviewId`。阶段 Review 可被后续阶段或最终 Review 原子覆盖；最终 Review 成功后不可修改。

### REVIEW-06 课节关闭事务

正常结束必须依次完成：结束意图、停止计时、冻结会话、冻结检查点、生成 Review、校验并提交。只有最终 Review 成功后才提交课节完成事实。

### REVIEW-07 未闭环结束

账本未进入 `ready_to_close` 时，结束弹层必须展示仍未完成的教学责任。用户确认后按放弃课节处理，不得记为正常完成。

### REVIEW-08 课程总 Review

课程关闭后生成课程总 Review。课程总 Review 可以消费会话聚合，但不得把自身重新写成独立画像证据。

### REVIEW-09 补充学习

已完成课节可以创建独立补充会话。补充学习不得修改原始会话、最终课时 Review 和课节完成事实。

## 8.10 历史、统计和周报

### FACT-01 结构化事实

历史统计必须消费结构化学习事实，不从 AI 可见文本反推课程、时长、完成或互动状态。

### FACT-02 投影一致性

历史、课程摘要、总体统计、日历和周视图必须能够从相同事实进行增量或全量重建，并得到等价结果。

### FACT-03 学习参与指标

当前学习参与面板只展示“关键互动回应率”和“跳过互动”，不展示互动回应绝对数量。

### FACT-04 周报时间范围

周报必须使用 `Asia/Shanghai` 的周一 00:00 至下周一 00:00 完整自然周冻结快照，并在每周一 00:00 生成上一完整周报告。报告仅展示不超过 300 字的学习成果概括：完成课节数、领域分布，以及根据课节标题和一句话摘要归纳的主要内容；不得生成下周建议或混入其他统计。生成中的目标周不得回退展示上一周报告；失败必须明确显示并按持久化退避时间自动重试，不得以机械拼接内容转成成功。空周直接生成空周说明。边界错误的历史快照和能够精确识别的旧机械摘要必须自动重建，正常已成功周报不得被重写。

### FACT-05 删除撤销

永久删除课程后，历史投影、统计和画像证据不得继续展示该课程贡献。

### FACT-06 历史首屏加载

历史页面必须按当前页签请求数据。总体统计应先展示统计接口可确定的权威指标，再异步补齐课程、课节和日历明细；画像、周报或日历不应被当前页签不需要的历史聚合请求阻塞。

## 8.11 全局用户档案与学习画像

### PROFILE-01 数据分层

行为数据必须按以下层次处理：

1. 原始行为层：回答、推理和精确来源；
2. 会话聚合层：学习会话 + 抽象维度；
3. 全局用户档案层：跨会话语义归并后的稳定维度；
4. 学习画像：面向用户的版本化分析产物。

### PROFILE-02 独立来源门槛

同一抽象模式至少由两个真正独立学习会话支持，才可进入稳定画像结论和教学个性化隐式上下文。

### PROFILE-03 证据治理

画像必须同时保留支持证据、限制和反证。运行遥测、页面状态、暂停事实和 Provider 故障不得进入画像证据。

### PROFILE-04 画像刷新

画像刷新必须创建独立任务和不可变版本。系统按 `Asia/Shanghai` 每周六 00:00 定时刷新，并保留用户显式手动刷新。进入画像页面、切换页签和普通读取只能展示当前成功静态快照，不得同步证据或提交刷新任务。只有生成成功并通过来源校验的版本才能替换当前画像；失败时保留上一成功版本。

### PROFILE-05 用户可见表达

画像必须使用普通语言描述学习情境和行为，不直接展示分析器、投影、快照、候选证据等后台术语。

## 8.12 运行中心

### RUNTIME-01 Provider 状态

运行中心必须展示当前 Provider、模型、推理强度、配置状态和健康状态。

### RUNTIME-02 Provider 选择

产品支持 Mock、条件接入的 OpenAI-compatible API 和条件接入的 Codex CLI。

### RUNTIME-03 动态模型目录

Codex CLI 模型必须来自真实 CLI 动态目录，并只展示可列出模型及其支持的推理强度，不在产品中硬编码固定两个型号。

### RUNTIME-04 切换与回滚

Provider 切换必须经过配置验证和健康检查。失败时保留或恢复上一有效 Provider，不得只改变前端标签。

### RUNTIME-05 AI 一键重连

“重连当前接口”必须重新应用持久化配置并执行真实连接检查。

### RUNTIME-06 本地服务一键重连

本地一键重连必须从当前工作区构建候选 release、验证并激活。失败时保留旧活动版本和用户数据。

### RUNTIME-07 三方版本一致

只有 Host active build、Runtime readiness 和 served Web `build-meta.json` 一致时，页面才显示本地恢复完成。

### RUNTIME-08 安全阻断

遇到未知端口占用、实例身份不匹配或 Host 身份不可信时，系统必须停止自动处理，不强行终止未知进程。

## 9. 数据与指标

### 9.1 当前可用学习事实

当前产品能够形成或展示：

- 实际学习时长；
- 已完成、已放弃和已恢复课节；
- 活跃学习日期；
- 课程和学科覆盖；
- 关键互动提示、回应率和跳过；
- 阶段/最终 Review；
- 周事实快照和周报；
- 跨会话行为维度与画像版本。

### 9.2 当前事实不包含

- 页面浏览次数；
- Provider 调用失败次数作为学习行为；
- 暂停次数作为行为证据；
- 仅由 AI 文案宣称的“掌握”；
- 未确认草稿中的长期学习事实；
- 课程总 Review 作为新的独立画像来源。

### 9.3 产品健康判断

当前系统具备事实基础，但没有在产品层固化统一北极星指标。现阶段可从以下事实观察闭环健康：

- 开始课节中最终完成的比例；
- 正常闭环与中途放弃的分布；
- 关键互动回应率与跳过率；
- 课程创建会话到候选确认的转化；
- Review、周报和画像任务成功状态；
- 恢复后继续原会话的成功情况。

这些是基于现有事实可计算的产品观察口径，不代表当前页面已经提供完整增长分析看板。

## 10. 非功能需求

### NFR-01 本地安全

Server 和 Launcher 默认只监听 `127.0.0.1`。写请求需要 Origin、CSRF 或 Launcher capability。Provider 密钥不得明文写入公开配置和诊断。

### NFR-02 可恢复性

事务、生成任务、关闭事务、投影 checkpoint、画像版本和 Provider 配置必须能够在进程重启后恢复或明确失败，不得静默丢失。

### NFR-03 幂等与并发

重复用户命令不得产生重复课程、消息、候选、Review 或关闭提交。资源版本冲突必须拒绝过期写入。

### NFR-04 数据一致性

页面展示以服务端权威资源为准。投影必须可从事件/事实重建；不可变产物成功后不得原地修改。

### NFR-05 AI 可替换性

业务模块不得绑定单一模型或 Provider。Provider 切换只影响新任务，已运行任务保持提交时的配置快照。

### NFR-06 可访问性与输入

对话组件必须支持键盘操作、中文输入法组合态、Enter 发送、Shift+Enter 换行、用户消息右对齐、多行换行和短文本正常排版。

### NFR-07 版本兼容

前端与 Runtime 构建或协议不一致时必须禁止写入，并引导用户完成受控恢复。

### NFR-08 品牌一致性

favicon 与页面品牌区必须使用同一 SVG 图形事实来源。品牌组件不得持有路由、运行状态或业务状态；16–32 px 下仍须保持中心点、开放圆环和扩展路径可辨。

## 11. 当前版本整体验收标准

当前产品满足以下条件时，可视为核心闭环成立：

1. 用户可从主页创建并恢复大纲创建会话。
2. AI 对话不会自动生成候选，用户可手动生成、取消、再次生成和确认。
3. 候选确认后生成正式课程、稳定课节和不可变大纲版本。
4. 用户可确定性安排课节或确认计划流预览。
5. 正式课节可自动开场，并根据真实回答逐知识点推进。
6. 教学账本与前端进度同步，观察不越权修改进度。
7. 综合检测后进入持续答疑，用户明确无问题后才总结并闭环。
8. 暂停、后台和刷新不取消身份匹配的已启动 AI 回复。
9. 实际学习时长不会在 AI 等待、后台或多窗口失权时重复累计。
10. 正常结束只在最终 Review 成功后产生课节完成事实。
11. 放弃、恢复、补充学习和课程关闭保持各自不变量。
12. 历史统计、周报和学习画像只消费允许的事实与证据。
13. Provider 可切换和重连，本地版本激活失败时旧版本与用户数据仍可用。
14. 页面刷新后能够读取权威状态，不要求通过手工刷新才能看到已提交结果。

## 12. 当前能力边界

- API Provider 当前没有开放完整高级模型参数面板；
- Runtime 并发配置字段尚未接入实际生成调度；
- 周报失败已有后台自动重试，但没有公开手动重试入口；
- 学习画像依赖多阶段后台链路，单一学习会话不足以形成稳定结论；
- 产品仅支持本地单用户运行；
- 当前不提供外部学习效果认证、多人协作和云端同步。

以上是当前产品边界，不属于本 PRD 的待实现需求。
