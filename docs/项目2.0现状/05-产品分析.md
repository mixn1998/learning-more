# Learning MORE 2.0：产品分析

> 本文基于当前实现判断产品价值、风险与下一步优先级。“现状”是已实现事实；“建议”不是当前承诺。

## 1. 核心产品判断

Learning MORE 当前最有价值的部分，不是单次 AI 对话，而是把学习过程变成长期可修订、又不会被后续生成覆盖的个人学习系统。

它已经具备三个互相增强的差异点：

1. **课程可以继续变化，已完成学习不能被改写。** 完成课时锚点解决了生成式课程最危险的版本漂移问题。
2. **学习结束不是聊天停止，而是可恢复事务。** 状态机、Review 和事实投影让“完成”具有稳定语义。
3. **画像来自跨会话证据，而非问卷或模板。** 它有机会成为长期教学个性化的基础，而不是一页装饰性总结。

这三点共同决定产品定位：Learning MORE 更接近“可演进的个人学习操作系统”，而不是课程生成器或聊天机器人。

## 2. 当前用户价值闭环

### 2.1 从目标到课程

课程创建对话降低了用户先写完整教学设计的门槛。候选大纲允许继续修订，确认动作又避免 AI 草稿直接污染正式课程。

当前最重要的进展是已完成课时锚点：用户可以在模块一学完后重做模块二，而不会失去模块一，也不会在新版本里再看到同义的“新课”。这让长期课程迭代真正可信。

### 2.2 从课程到学习

教学阶段状态机给自由对话加上必要边界。尤其是讨论结束改为语义识别，并由状态组合验证，兼顾了自然交互与流程可靠性。

动态推理强度把计算投入放在需要的轮次：简单过渡不必使用高强度推理，连续实质追问和综合判断才增加预算。这同时改善响应时间和成本。

### 2.3 从学习到复盘

Review 的后端完整、前端精简是正确分层。用户需要的是一条关系主链、一个核心方法和几个可行动的判断；系统治理需要的是完整证据、原文和结构化记录。二者不应使用同一展示颗粒度。

补充学习进一步修复了“完成后还想问，但又不该改写历史”的冲突。原课时保持冻结，新的探索仍能自然延续。

### 2.4 从复盘到长期认识

画像管线已经从模板填充转向证据治理：单次行为、会话维度、候选证据、跨会话分析和静态快照各自有边界。它能回答“你近期反复怎么处理问题”，但会拒绝把两次行为说成稳定人格。

周六定时刷新和手动刷新把画像从页面即时生成改成持久产物，减少等待和结果漂移，也便于比较版本。

## 3. 当前优势

### 3.1 领域不变量清晰

完成、放弃、Review、修订、删除都不只是 UI 标签，而有后端事务和恢复语义。这会显著降低数据越积越多后的不可解释状态。

### 3.2 本地优先不是简单“写 JSON”

系统已经具备原子写入、事务日志、写租约、checksum、投影重建、迁移与激活回滚。对当前单用户规模而言，这种实现保留了可审计性，也避免过早引入数据库运维。

### 3.3 AI seam 进入真实使用

16 个场景共享任务运行时，但拥有各自合同和预算。Provider 可切换，业务模块不依赖具体厂商协议。这使 AI 可靠性问题可以集中处理，而不散落在每个路由里。

### 3.4 性能优化已经对准“无变化”场景

首页源修订快照和 ETag 解决了常见的重复加载问题。对本地应用而言，用户反复打开首页时无数据变化远比大规模并发更常见，因此优先优化条件命中是合理方向。

### 3.5 独立守护链降低开发工具耦合

Host 由任务调度器启动，不再依赖某个终端或 Codex 进程。Launcher 管理 Server 与版本激活，交互包装器才负责打开浏览器，职责边界已经清楚。

## 4. 当前主要风险

### 4.1 用户价值仍受生成质量上限约束

架构能保证一份 Review 不被重复提交，却不能保证 Review 一定精炼、有洞察。知识图谱、核心思想、画像标题和摘要仍需要真实课程样本持续校准。

风险信号包括：

- 图谱再次变成长段解释。
- 核心思想重复课程摘要。
- 学习表现一条行为一张卡。
- 画像用后台术语或模板标题。
- 证据不足时仍生成强结论。

### 4.2 画像“可信”不等于“有用”

证据门槛能减少过度推断，但若洞察只是“你会分层拆解问题”，用户仍可能不知道下一次学习要如何行动。画像需要把观察转化为可验证建议，同时避免变成普遍适用的鸡汤。

### 4.3 历史读模型仍可能随数据增长变慢

首页已有统一快照；历史、统计、日历和周报是多个查询组合。当前分拆有利于按需加载，但数据量变大后仍可能出现大量小文件读取、冷启动索引和多区块刷新成本。

### 4.4 本地守护可靠性需要长期实机证据

进程监督、退避、激活和回滚都有自动测试，但 Windows 更新、用户注销、休眠、杀毒软件、磁盘占满和权限变化属于真实环境变量。一次恢复成功不能证明永久不会复发。

### 4.5 删除链是高风险能力

课程永久删除会跨越课程、会话、Review、计划、事实、证据和画像。任何遗漏都会产生“页面看不见但画像仍引用”的幽灵数据。它应持续保留独立的一致性审计和恢复测试。

### 4.6 测试体系可能再次膨胀

系统横跨 AI、文件、进程和 UI，容易把每个边界都塞进日常测试。若快速层和发布层失去边界，开发反馈会重新变慢；若为了速度删除恢复验证，运行可靠性又会倒退。

## 5. 产品成熟度判断

| 维度 | 判断 | 理由 |
| --- | --- | --- |
| 核心闭环 | 已成立 | 创建、学习、Review、规划、历史、画像可串联 |
| 长期数据可信度 | 较高 | 完成锚点、不可变 Review、事实与投影分层明确 |
| 教学体验 | 中高 | 自由追问和状态机并存，但质量依赖模型与内容校准 |
| 画像价值 | 中 | 管线可信度提升明显，用户语言和行动价值仍需样本验证 |
| 本地运行 | 中高 | 独立守护与激活具备，仍需更长周期实机观察 |
| 性能 | 中高 | 首页路径优化到位，历史规模化尚未充分量化 |
| 可发布性 | 中高 | 构建、恢复与发布工具具备，仍需稳定执行门禁 |

## 6. 建议的后续优先级

以下均为建议，不代表已经实现。

### P0：巩固真实用户主链

1. 用多门真实课程持续验收“完成课时锚点 + 后续大纲修订”，重点覆盖同义改写、部分重叠和跨模块移动。
2. 对课时 Review 建立内容质量样本集，人工评估关系图式、核心思想和两块学习表现是否真正精炼。
3. 对画像建立“用户能否读懂、能否指出下一步行动、是否感觉被过度推断”三类验收。
4. 持续观察 readiness degraded、任务积压和 Host 重启原因，形成可重复的运行基线。

### P1：量化性能和数据恢复

1. 建立不同数据规模下的首页命中、历史冷加载、日历刷新、画像输入冻结和完整重建基准。
2. 给备份、恢复、投影重建和课程级删除设定容量档位与时间预算。
3. 为历史读模型引入一致的 revision/ETag 策略，但只在测量证明收益的接口上实施。

### P1：提升画像的教学反馈价值

1. 将每条画像洞察连接到“下一次教学如何调整”的受控建议。
2. 显示证据覆盖范围和最近更新时间，而不是抽象置信分。
3. 允许用户纠正明确偏好或指出观察不适用；纠正应成为新事实，而不是直接改写历史证据。

### P2：资料域与扩展能力

只有在核心闭环稳定后，再评估附件、网页和外部资料。资料域需要来源、授权、版本、引用和删除语义，不能只在 Prompt 中拼接文本。

多用户、登录和云同步会改变 Repository、密钥、权限和冲突模型，属于新的产品阶段，不应以“小功能”方式加入当前架构。

## 7. 不建议现在做的事

- 不为了“未来分布式”提前拆微服务或引入远程事件总线。
- 不把模型名称、Provider 或推理参数写死为产品规范。
- 不用更长 Prompt 代替领域状态机和证据门槛。
- 不让画像追求数量；没有足够证据时，一条清楚洞察优于多条模板结论。
- 不让每个页面都自行扫描 DataRoot；读模型和修订边界必须集中。
- 不让日常测试重新承担全部发布演练。

## 8. 后续决策应关注的指标

建议建立但当前尚未形成完整仪表盘的指标：

- 从创建课程到确认大纲的完成率和修订轮数。
- 课时开始、暂停、恢复、放弃和成功关闭比例。
- Review 生成/关闭恢复失败率及平均恢复时间。
- 补充学习的创建率、持续轮数和归档率。
- 首页快照命中率及冷/热加载时间。
- 历史各区块的文件读取量和响应分位数。
- 画像有效独立来源数、候选淘汰原因、手动刷新率和用户展开证据率。
- Host/Launcher/Server 非预期退出、自动恢复和激活回滚次数。

这些指标用于发现产品和运行问题，不应反向诱导系统生成更多无意义会话或画像条目。

## 9. 总结

Learning MORE 2.0 的架构已经能保护长期学习记录，当前挑战已从“有没有系统”转向“生成内容是否真正帮助学习、画像是否真正可懂可用、长期本机运行是否持续稳定”。

下一阶段最值得投入的不是扩展更多入口，而是用真实课程和真实数据把三个核心承诺做扎实：已学内容不会丢，学习结束可靠，跨会话反馈有证据且说人话。
