# Learning MORE 2.0：后端架构层

## 1. 架构形态

Learning MORE 当前是本地优先、单用户、模块化单体。工作区使用 pnpm monorepo：

```text
apps/web       React 产品界面
apps/server    Fastify HTTP 服务、领域模块和文件持久化
apps/launcher  本地控制面、静态页面、反向代理和服务恢复
apps/host      Windows 登录任务与 Launcher 监督
packages/contracts  跨端合同和 Schema
packages/ui         共享 React UI
packages/test-kit   测试辅助
tools/*             架构、CLI、发布、基准和验证工具
```

目标不是微服务拆分，而是在一个进程内保持清晰模块边界、可恢复文件事务和可替换 AI Provider。

## 2. 运行进程拓扑

工作区模式下的默认拓扑是：

```text
Windows 计划任务 “Learning MORE”
  → Host supervisor
    → Launcher 127.0.0.1:43119
      ├─ 静态托管 apps/web/dist
      ├─ /control/v1/* 本地控制面
      └─ /api/* 反向代理
          → Fastify Server 127.0.0.1:43120
              → .learning-more-data
              → .learning-more-runtime
```

Host 负责登录启动、单实例租约、Launcher 监督、工作区/便携版本激活和重启风暴阻断。Launcher 即使内部 Server 启动失败也尽量保留静态产品页和控制面，使用户仍可诊断和重连。

Launcher 重连遵循身份核验：只终止已验证属于当前 Learning MORE 的 Server；端口由未知进程占用或实例身份不匹配时进入阻断状态，不强杀外部进程。

### 2.1 工作区安全激活

工作区源码身份变化时，Launcher 写入带 `requestId` 的激活请求。Host 是候选构建、release 暂存、Supervisor 切换和工作区 manifest 提交的唯一写入者：

1. 候选位于 `releases/.activation-work/<requestId>/attempt-<n>`，不会覆盖活动 release；
2. 构建最多两次，首次失败只清理该 request/attempt；
3. Supervisor 验证候选 Runtime 后提交活动 release，验证失败则回滚旧 release；
4. 工作区 manifest 只在 Supervisor 成功后提交；
5. schema v2 激活状态原子持久化，Launcher 被替换后仍能恢复同一请求的终态；
6. 失败状态只包含稳定错误码、阶段、build 身份和时间，不包含绝对路径、命令、密钥或原始异常。

控制 POST 只等待 Host 确认同一请求已经被接受，不等待承载该 POST 的旧 Launcher 自身被替换。新 Launcher 从持久化状态向 Web 投影 `activated` 或 `failed`。Host 未确认请求时，Launcher 最多执行一次使用受信 Host entry/project root 的 `host repair`；浏览器请求不能提供可执行路径。

## 3. 配置、身份与本地安全

### 3.1 运行配置

配置合并顺序是默认值 < `runtime.json` < 环境变量 < CLI 参数。当前字段包括：

- 数据目录、时区；
- Launcher/Server 端口；
- 初始 Provider；
- 交互/后台并发字段；
- 日志级别。

默认数据目录为 `.learning-more-data`，默认 Provider 为 `mock`，时区为 `Asia/Shanghai`。

需要注意：`interactiveConcurrency` 和 `backgroundConcurrency` 虽然存在于配置 Schema，但当前生产接线没有将它们传给 `createGenerationRuntime`。当前调度并发实际由任务组/owner 规则和各 Provider 的 `maxConcurrency` 决定。

### 3.2 运行身份

Server 启动创建 manifest，包含：

- `instanceId`
- `generation`
- PID、可执行文件和项目根目录
- 数据目录和配置指纹
- `buildId`、`protocolVersion`
- 启动时间和健康地址

`/api/v1/runtime/ready` 返回公开身份、Store/投影/Provider 状态。前端同时验证构建与协议，避免旧页面向新实例或错误实例写入。

每个生产 Web 构建在静态根生成严格的 `build-meta.json`。激活成功的最终事实要求 Host active build、`/api/v1/runtime/ready` 的 `buildId` 和实际 served `build-meta.json` 的 `buildId` 一致，且 Runtime/Web 协议相同。旧 Runtime 健康只能表示旧版本仍可用，不能覆盖 Host 已发布的激活失败。

### 3.3 安全

- Server 和 Launcher 默认仅监听 `127.0.0.1`；
- 写请求要求允许的 Origin 和 CSRF Token；
- Launcher 控制写请求要求短期 capability；
- Windows Provider 密钥存入当前用户 DPAPI Secret Store；
- Provider 配置文件只保存公开配置和密钥句柄，不保存明文密钥；
- 诊断产物进行脱敏，不公开本地绝对密钥路径或密钥内容。

## 4. 模块边界

服务端业务模块位于 `apps/server/src/modules`。架构检查规定：一个业务模块导入另一个业务模块时，只能依赖对方的 `interface.ts`，不能越过公共接口访问其 `implementation`、`model` 或 `ports`。

## 6. AI 生成运行时

### 6.1 任务模型

所有 AI Agent 通过 `GenerationRuntime` 或 `GenerationExecution` 提交统一任务。请求包含：

- 稳定任务键和输入快照哈希；
- 场景 `taskKind`；
- `interactive` 或 `background` 任务组；
- owner 引用；
- Provider、模型、fallback 列表和最大尝试次数；
- 优先级和完整 prompt。

相同任务键和输入快照会 join 同一非失败任务，避免重复调用。提交时将 `current` Provider 和当前模型快照到任务；运行中心后续切换只影响新任务。

任务状态为 queued、running、completed、failed、cancelled、timeout。运行租约过期时：尚未输出的任务可重新入队；已有部分交互输出的任务保留为可恢复中断，不静默重跑并覆盖内容。

### 6.2 调度与 fallback

调度器同时考虑：

- Provider 最大并发；
- Mock 与真实 Provider 隔离；
- 交互/后台任务组上限；
- 同一 owner 的并发限制；
- 优先级和提交顺序。

默认 fallback Provider 列表来自 `LEARNING_MORE_FALLBACK_PROVIDER_IDS`，最大尝试次数来自 `LEARNING_MORE_FALLBACK_MAX_ATTEMPTS`，默认 3、上限 10。fallback 仅在错误可重试且尚未产生首个 delta 时发生；一旦输出开始，运行时不会切换 Provider 拼接结果。

### 6.3 帧日志与恢复

`GenerationFrameLog` 为每个任务保存递增序号的状态和内容帧。SSE 客户端按序号续读；元数据陈旧时可从帧推导终态。Server 重启后，`GenerationExecution.recover` 读取任务与帧，业务模块再验证 owner、会话和任务身份后提交结果。

这使“页面进入后台只暂停计时和用户输入，既有 AI 回复继续生成”成为服务端保证，而不是前端绕过暂停状态。

## 7. Provider 接入

### 7.1 Mock

Mock 始终作为第一个 Provider 创建，支持确定性脚本、故障注入和开发测试。默认运行配置选择 `mock`。

### 7.2 OpenAI-compatible API

只有同时提供 `LEARNING_MORE_API_BASE_URL` 和 `LEARNING_MORE_API_MODEL` 时，生产启动才创建 API Provider。它调用兼容的 `/chat/completions` 流式 SSE 接口，并用 `/models` 做健康检查。请求当前传递：

- `model`
- 单条 user message 中的完整 prompt
- `stream: true`
- 可选 Bearer API Key

当前 API Provider 没有在请求体中传递 temperature、top_p、max_tokens 等额外模型参数；公开配置主要是 Base URL、模型和密钥句柄。

### 7.3 Codex CLI

启动时按以下顺序发现可执行文件：显式环境覆盖、PATH、当前用户 `%LOCALAPPDATA%\OpenAI\Codex\bin` 下最新安装。探测流程为：

1. `codex --version`
2. `codex login status`
3. `codex debug models`

只接受目录中 `visibility=list` 的模型，并读取每个模型的默认/支持推理强度。生成命令为非 shell 子进程：

```text
codex exec --ephemeral --skip-git-repo-check --sandbox read-only
  --model <model>
  -c model_reasoning_effort=<effort>
  <prompt>
```

工作目录可配置，进程默认隐藏 Windows 窗口。用户可从运行中心启动 `codex login`，页面轮询目录直到认证和模型探测成功。

当前生产实现没有硬编码 `gpt-5.6-sol/high` 与 `gpt-5.5-luna/high` 两个固定选项；前者仅为测试夹具，后者没有生产接线。

### 7.4 切换、持久化与回滚

Provider 切换按串行屏障执行：

1. 验证公开配置和密钥句柄；
2. 预检 Provider 健康；
3. 切换运行时 Provider；
4. 再次健康检查；
5. 原子替换 `provider-config.json`。

任一步失败都尝试恢复上一 Provider 和上一配置；回滚失败有独立错误码。重连会重新应用持久化配置，而不是只刷新前端标签。

## 9. 领域状态与重要不变量

### 9.1 课程

- 正式课程只在候选确认事务成功后存在；
- 大纲版本不可变，当前指针可前进；
- 课程关闭后禁止修订；
- 永久删除启动后拒绝迟到的学习、Review 和排期写入。

### 9.2 学习会话

- 每个课节最多一个原始会话；
- 每个原始会话最多一个活动生成任务；
- 用户消息只允许在 active 会话写入；
- 身份匹配的 AI 回复允许在 active 或 paused 会话提交；
- paused 回复必须匹配 sessionId、taskId 和写入租约 owner；
- completed 课节不可恢复为可写；
- 最终 Review 不可变。

### 9.3 计划流

- 预览不写排期；
- 确认检查基础排期版本；
- 课节不可拆分；
- 课程内顺序和依赖先后必须满足；
- 锁定排期在重排中保留；
- 放弃课节取消活动排期，恢复不会自动复原旧排期。

### 9.4 画像

- 候选证据不直接写永久人格；
- AI 输出引用必须属于冻结 manifest；
- 独立来源不足时禁止稳定结论；
- 失败版本不推进当前指针；
- 删除/撤销事实会传播到证据与后续画像。

## 10. 文件持久化

Store 初始化以下主要区域：

```text
store.json
locks/
transactions/{prepared,committed}/
idempotency/
entities/<entity-type>/<hash-shard>/<id>.json
outbox/{pending,receipts}/
events/segments/
tasks/{queued,active,terminal,journals}/
indexes/
read-models/
global-profile/{fact-metrics,time-series,artifact-index,cursors}/
portrait-evidence/
portraits/
work/
quarantine/
```

聚合 ID 经过安全路径段校验并按 SHA-256 前两位分片。Store manifest 记录格式版本、最后事务序号、时区和校验算法。

写入使用文件级 Unit of Work、prepared/committed 事务日志和原子 rename。启动时先恢复未完成事务，再创建模块。命令幂等结果和资源版本一并持久化，防止重复提交和丢失更新。

## 11. 事件、事实与投影

领域写入通过 outbox 发布 `LearningEventEnvelope`。事件日志是可重放输入，`learning-facts` 将允许的提交事件转换为稳定事实；生成 delta、UI 遥测、未知事件和阶段性 AI 状态不会成为学习事实。

投影包括：

- history
- course summary
- statistics
- calendar
- weekly

投影保存 checkpoint，可增量执行、随机批处理或全量重建；测试要求三种方式字节等价。课程永久删除事件会在重放中撤销该课程贡献的全部事实。

Profile Evidence 从事实与少量受控来源摘录构建，保存 extractor/analyzer 版本、来源游标和输出校验和。Learning Portrait 只消费打包后的证据 manifest，不直接扫描任意原始文件。

## 12. Review 与产物

Review、周报和画像使用 Markdown Artifact Store。关键产物策略：

- 候选草稿和中断回复可保留为可重试材料；
- 阶段 Review 可被同一 reviewId 原子替换，不维护展示版本时间线；
- 最终课节 Review、课程 Review、成功周报和画像版本不可变；
- 课节关闭先冻结来源快照，再生成，再校验校验和，最后提交领域状态；
- 页面是否打开不决定后台 Review 是否可完成。
