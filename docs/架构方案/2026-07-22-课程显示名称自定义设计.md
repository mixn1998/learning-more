# 课程显示名称自定义设计

## 目标与边界

课程创建完成后，用户可以且只能在正式课程页面修改课程主标题。修改后的名称作为课程的全局显示名称，同步用于课程目录、主页汇总、课程规划、历史记录、学习页面和 Review 等当前投影。

本功能不修改候选大纲、已发布大纲或历史大纲中的 Markdown 一级标题，也不创建新的大纲版本。模块标题和课时标题不在本次范围内。

## 领域语义

`CourseAggregate.title` 是课程级、用户可维护的全局显示名称。课程首次确认时，仍从候选大纲 Markdown 的一级标题初始化；初始化后，它与 Markdown 标题解耦。

发布新大纲时必须保留当前 `CourseAggregate.title`，不得再用新 Markdown 的一级标题覆盖。Markdown 标题只属于对应的大纲版本，用于大纲内容与版本对比。

该设计不增加 `customTitleOverride` 或独立标题映射表，避免双字段优先级和额外迁移。现有课程记录无需数据迁移，其已有 `title` 直接成为规范显示名称。

## 命令与 HTTP 合同

新增 `RenameCourse` 命令，输入为 `courseId` 和去除首尾空格后的非空 `title`。命令对活动课程和已关闭课程均可执行。

HTTP 使用课程资源上的条件更新：

- `PATCH /api/v1/courses/{courseId}/title`
- 请求体：`{ "title": "新的课程名称" }`
- 必须携带 `If-Match`、幂等键和页面实例标识。
- 成功返回 `courseId`、规范化后的 `title` 和递增后的 `resourceVersion`。

空标题返回输入校验错误；版本不一致返回既有版本冲突问题；课程不存在返回资源不存在。重复提交相同标题仍按幂等命令处理，不修改 Markdown 或大纲版本。

## 查询与全局映射

课程查询和课程目录不再通过当前大纲 Markdown 重新解析并覆盖课程名称，而是直接投影 `CourseAggregate.title`。所有需要当前课程名称的页面和读模型使用同一课程名称入口。

历史大纲查看器继续显示该版本 Markdown 自带的一级标题；这不会影响页面外层显示的当前课程名称。已经固化在不可变学习事实或 Review 正文中的历史文本不回写，只更新当前界面所关联的课程名称投影。

## 课程页面交互

课程主标题旁提供编辑入口。进入编辑态后显示单行输入框以及保存、取消操作：

- 保存成功后立即更新课程页面及客户端课程目录状态。
- 取消恢复保存前名称。
- 保存期间禁用重复提交。
- 保存失败保留输入并显示可重试提示。
- 标题只允许在课程页面编辑；其他页面只展示同步后的名称。

活动课程和已关闭课程使用相同交互。编辑标题不会触发大纲生成、课程规划重算或 Review 重新生成。

## 一致性与测试

课程记录通过 Repository 和 Unit of Work 原子更新，使用资源版本防止并发覆盖。大纲发布事务必须有回归断言，证明其保留已自定义名称。

测试覆盖：

- 课程重命名命令的成功、版本冲突、空标题和已关闭课程场景。
- HTTP 条件更新与合同校验。
- 大纲重新发布后课程名称不变、Markdown 一级标题不变。
- 课程页编辑、取消、失败重试和保存后显示更新。
- 课程目录及相关当前投影统一展示新名称。
