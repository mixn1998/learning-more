# 架构绿线修复设计

日期：2026-07-17

## 背景

当前提交存在三个确定的质量门禁失败：六个源文件不符合 Prettier；课程大纲修订清理直接依赖 Planning 的私有 Repository port；`learning-runtime.ts` 超过本地组合文件 650 行预算。本设计仅修复这三个问题，不改变课程修订、排期清理、教学上下文或持久化语义。

## 决策

采用“Planning 公开事务参与者 + Learning 内部深 Module”的方案。

不采用以下替代方案：

- 不从 `planning/interface.ts` 重新导出 Repository 类型。那只会让私有实现泄漏变成合法依赖，无法提升 Module 深度。
- 不把大纲修订清理改成异步领域事件。当前清理与大纲发布共享事务，改成最终一致会扩大故障恢复和用户可见语义。
- 不单纯提高 650 行预算。预算失败反映 `learning-runtime.ts` 同时承担教学上下文查询和运行装配，应该拆分职责。

## Planning Interface

在 `modules/planning/interface.ts` 增加一个应用内事务 Interface：

```ts
interface PlanningOutlineRevisionParticipant {
  retireOutlineReferences(
    input: PlanningOutlineRevisionInput,
    tx: TransactionContext,
  ): Promise<void>;
}
```

`PlanningOutlineRevisionInput` 只暴露 Planning 完成工作所需的业务事实：课程、保留课节、已知原课节、命令和发生时间。`TransactionContext` 明确表示该 Interface 必须加入调用方已开启的原子事务；它不是 HTTP Interface，也不自行开启第二个事务。

实现移动到 Planning Module 内部。实现独占 Schedule/PlanFlow Repository port、未确认计划流状态集合、排期取消规则和事件回调。CourseAuthoring 只持有上述 Interface，并在大纲版本写入事务中调用它，不再认识 Planning 的数据模型或 Repository。

现有行为保持不变：

- 被新大纲移除的已排期课节标记为 `removed / outline_revised`。
- 对应排期取消事件仍写入同一 outbox 事务。
- 引用课程的未确认计划流标记失败，并移除失效课节引用和建议。
- 已确认或终态计划流不被修改。
- `commandId` 继续作为幂等收据写入。

## Learning 内部 Module

从 `learning-runtime.ts` 提取 `learning-teaching-context.ts`。该内部 Module 的唯一 Interface 是创建 `TeachingContextSources`；它隐藏以下实现：

- 课程与课节教学事实装配。
- 核心知识点稳定引用生成。
- 会话消息 Markdown 读取。
- 相关最终 Review 选择。
- 课节材料摘录读取。
- 教学个性化视图转发。

`learning-runtime.ts` 继续负责 Repository 和运行时装配、路由、检查点、恢复及公开 `LocalLearningRuntime` Interface。提取后目标不超过 610 行，为后续小幅增长保留余量，而不是贴着 650 行门禁通过。

新内部 Module 接收现有依赖，不自行创建 Repository，不增加外部 seam，也不改变 `LocalLearningRuntime` 或 HTTP 合同。

## 格式修复

只对门禁报告的六个文件运行仓库固定版本的 Prettier。格式化结果不得包含手工语义修改；差异需单独审查。

## 验收

权威验收顺序：

1. Planning 大纲修订清理行为测试通过。
2. `local-application-boundaries.test.ts` 通过，且 `learning-runtime.ts` 不超过 610 行目标。
3. `pnpm format:check` 通过。
4. `pnpm architecture:check` 无 `MODULE_PUBLIC_INTERFACE_ONLY` 问题。
5. Server typecheck、Lint、完整 Vitest 和完整 `pnpm verify` 通过。
6. 工作树只包含本设计范围内的文件；无合同、Schema 或生成产物漂移。

## 非目标

本次不调整 Vitest worker、CI 分层、便携发布构建、Host 激活、启动后台任务或健康检查。这些属于独立的性能架构改造。
