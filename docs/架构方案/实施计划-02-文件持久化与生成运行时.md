# 文件持久化与生成运行时 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan.

**Goal:** 交付可原子写入、可崩溃恢复、可重建读模型的本地文件 Store，以及具备幂等、并发控制、续传和多 Provider adapter 的生成运行时。

**Architecture:** 聚合 JSON 是当前状态权威源，append-only event log 是历史与投影源，outbox 保证状态提交与事件发布一致。UnitOfWork 通过 staging、journal、原子 rename 和启动恢复提供跨文件事务；GenerationRuntime 使用持久任务记录和严格 SSE 序列，不把 Provider 协议泄露给领域模块。

**Tech Stack:** TypeScript 5.9.3、Node.js fs/promises、Zod 4.4.3、Fastify 5.10.0、Vitest 4.1.9、fast-check 4.8.0。

## Global Constraints

- 先完成《实施计划-01》Phase Gate。
- 数据根只能由 `DataRoot` 值对象提供，任何用户输入不得直接拼接文件路径。
- 写入同一数据根时只允许一个 `StoreWriteLease`；读路径在安全时可并发。
- JSON 使用 UTF-8、LF、稳定 key 顺序与末尾换行；Markdown 正文和元数据分离。
- 最终 Review 和课程总 Review 一经提交不得原位覆盖。
- 崩溃测试必须在每个 journal 状态点注入，不能只测 happy path。
