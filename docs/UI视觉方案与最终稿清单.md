# Learning MORE UI 视觉方案与当前样稿清单

> 更新时间：2026-07-12  
> 权威样稿根目录：`docs/UI视觉预览`  
> 组织方式：设计系统 + 七个功能域，按课程生命周期分类

## 1. 统一视觉语言

- 暖白纸面、浅米灰背景、陶土色主操作、低饱和绿色成功状态；
- 深墨色正文、克制阴影、轻边框和中等圆角；
- 链接按钮统一使用共享 `.lm-btn`，不得出现浏览器默认蓝色或访问后紫色；
- 桌面端保持信息密度，移动端恢复自然单列；
- 模式色仅表达课程来源身份，不覆盖成功、警告、失败、只读等全局状态色；
- 对话界面中用户回答使用右侧气泡，AI 内容直接排版在页面上，不显示“AI”或“用户”发送者标签。

## 3. 主页最终规则

- 左侧以九张同规格卡展示“标准模式 + 八大玩法”，标准模式默认选中；
- 商业洞察位于案例研习下方；
- 点击模式只改变共享输入区的模式语境、文案和强调色，不提前创建会话；
- 阅读研讨选中后显示 PDF、TXT、Markdown 等材料上传入口；
- 输入“想学什么”并提交后，直接进入对应模式的学习起点评估；
- “继续学习”样稿默认进入最近一门学习中课程的正式课程大纲，生产实现由最近活动查询决定；
- 周历工具栏顺序为“返回当周 / 上一周 / 日期范围 / 下一周 / 进行课程规划 / 上周学习回顾”；
- 周切换和返回当周已提供样稿级交互；
- 今日学习课节整卡点击后先打开核心知识点导航弹窗；
- 周历卡片和今日列表均展示具体课节名称。

## 4. 课程创建与大纲

- 九种模式共用同一建档流程与全宽大纲工作台；
- 主页提交后，建档页不重复显示模式选择栏和主题输入框；
- 模式仅提供整体体验语境，不提供固定模块、方法列表或问题数量；
- AI 通过自然对话完成学习起点评估、生成 Markdown 候选大纲并允许继续调整；
- 大纲必须包含一个 `disciplineTag`、一至三个 `topicTags`，以及每节课的核心知识点；
- 用户确认最终 Markdown 后才原子创建正式课程和课节列表；
- 修改大纲通过新的调整会话发布不可变新版本；课程关闭后不再修改大纲。
- 正式课程大纲右侧不堆叠多个同权重大卡：使用一个粘性侧栏整合紧凑进度、重点推荐课节和轻量辅助入口；主题总结在课程关闭前仅显示不可用状态。

## 5. 课程规划与排期

- 桌面端左侧七天栏粘性跟随，无内部滚动条；七张日期卡在可视高度内等分铺满；
- 左右栏顶边、底边对齐，只有右侧内容超出时内部滚动；
- 点击左侧日期联动右侧列表；日期筛选与其他筛选采用互斥模式；
- 待规划课节显示“点击安排学习日期”，只有已排期课节提供改期或取消排期；
- 课节预览沿用未开始课节导航视觉模板，但不显示“开始学习”；
- 计划流支持课程多于四门、排期超过六天的滚动和分页结构。

## 6. 课节学习与 Review

- 正式学习采用渐进式生成；AI 内容无气泡，用户回复使用右侧气泡；
- 支持暂停学习、结束本课和 AI 输出时停止生成；
- 暂停学习保留同一可写会话；有有效证据的提前结束转为已放弃并冻结同一会话；
- 恢复已放弃课节时解除原会话冻结，不创建新的续学主会话；
- 最终课时 Review 生成后不可修改、不可重新生成；补充学习不修改最终 Review；
- 课时 Review 弹窗展示完整权威 Markdown，只提供“返回课程大纲”和“查看课节记录”；
- 课节记录顶部为“学习对话 / 课时 Review”双 Tab；学习对话内部切换原始会话和已有补充会话；
- 课节记录页顶部仅“返回主页”，底部仅“返回课程大纲”，不提供发起补充学习按钮；
- 全部课节处置完成后关闭课程；主题总 Review 失败不阻止关闭并可重试。

## 7. 历史统计、学习日历与学习画像

- 顶部固定为“历史统计 / 学习日历 / 学习画像”三个同级 Tab、三个视图；
- 不提供课程聚合式“历史回顾”页面；
- 历史统计采用分层归档：核心事实、趋势与投入、历史课程清单；
- 历史课程清单并列状态、学科/领域、来源模式和排序筛选，不提供搜索框；
- 学习日历只记录已完成归档课节，不显示今日待学习课节；日期格直接展示具体课节名；
- 点击日期筛选右侧已完成课节，点击课节打开双 Tab 只读记录；
- 学习画像沿用共享设计系统与历史功能域的顶栏、三 Tab、卡片、边框、圆角和暖色规范；顶部直接呈现 AI 自由生成的标题与摘要，下方使用统一的“编号栏—自由正文—证据链折叠栏”洞察组件；
- 每条洞察提供可展开的复合行为证据链，以数量不定的跨课节、跨课程或跨时间行为片段及限制性/反向证据共同支撑结论；不得把单点事件包装成画像洞察；
- 页面不设置固定分类、状态、目录、近期变化、行动或用户反馈组件；视觉样稿中的所有洞察正文使用相同的通用占位内容，不出现任何具体学习结论或画像内容模板；列表末尾保留“可继续生成”的虚线占位，仅表达洞察可扩展，不预设下一条内容；画像与统计字段、全局学习档案和数据流向以《历史统计与学习画像数据源定义清单》为准，候选证据抓取和自由分析规则以《学习画像数据抓取与分析策略规则》为准。

## 8. 运行服务

- 统一设计系统页面已接入共享运行状态层，顶部持续显示两个独立可点击状态：AI Provider 与本地服务；
- 点击任一状态进入同一个运行中心，并自动定位到 AI 接口或本地服务页签；
- 运行中心的故障场景、版本状态和自愈结果会同步到其他样稿页面；
- 支持检查中、就绪、降级、断开和版本不一致状态；
- 操作包括切换 Provider、重连本地服务和同步前端版本；
- 自愈弹窗不遮挡关键诊断信息，重试过程提供明确进度与结果。

- 正式应用使用 React + TypeScript 重写，不直接把 HTML 样稿当作生产代码。
