# 课程学习与 Review 功能逻辑规则

> 状态：规格确认稿（待用户最终审阅）  
> 适用项目：Learning MORE  
> 范围：用户进入正式课节，至课节结束、Review 归档及课程关闭  
> 关联文档：《课程创建通用流程与功能逻辑规则》《课程永久删除功能规则》《基础模块功能等价清单与回归基线》《历史统计与学习画像数据源定义清单》《学习画像数据抓取与分析策略规则》《UI视觉方案与最终稿清单》

## 1. 文档目标

本文件定义正式课程学习流的前后端功能边界、领域状态、AI 教学责任、会话与计时规则、课时 Review、课程总 Review、错误恢复及验收条件。

本系统不预生成和固化整篇课程正文。AI 依据确认版大纲中的课节目标和核心知识点，以实时对话方式渐进式完成教学；实际发生并被保存的学习对话即本课正文。

## 2. 本阶段范围

### 2.1 包含

- 未开始课节的学习导航；
- 正式学习会话创建与上下文装配；
- AI 课前热身、知识讲解、关键节点互动和动态补救；
- 流式 Markdown、停止生成与技术重试；
- 暂停、恢复、放弃及恢复已放弃课节；
- 多窗口写入权和实际学习时长；
- 课节闭环、最终 Review 生成和只读归档；
- 补充学习会话边界；
- 推荐下一课；
- 课程关闭和课程总 Review。

### 2.2 不包含

- 历史统计的数据字段、指标和流向细节（由《历史统计与学习画像数据源定义清单》定义）；
- 用户档案候选证据抓取、全局用户档案和学习画像生成策略（由《学习画像数据抓取与分析策略规则》定义）；
- 各玩法壳的隐藏教学上下文；
- 附件、网页、外部知识库的上传与引用规则；
- 推荐扩展课程的后续创建交互；
- Prompt 正文和模型供应商技术接入细节。

上述内容另立专项规则，不得在实现时自行扩展本文件边界。

## 3. 核心原则

### 3.1 模型自由度优先

系统约束教学责任和状态边界，不用固定模板约束讲解顺序、问题数量、篇幅、案例或互动轮次。AI 可以根据学习者最新回答动态改变深度、顺序、解释方式和验证方法。

### 3.2 真实证据优先

AI 不预设学习者已经理解。知识点是否完成必须建立在学习者真实回答、应用、比较、预测、纠错、举例或任务表现之上。完成讲解本身不等于学习者掌握。

### 3.3 对话不可改写

已经成功发送的用户消息和已经完整生成的 AI 消息只允许追加，不允许编辑、删除或重新生成。技术中断的同一次 AI 回复可以续接或重试，但不能用新内容替换一条已经完成的历史消息。

### 3.4 Review 单一且权威

一个课节任何时刻最多只有一个 `reviewId`。阶段 Review 可以在课节最终完成前被后续阶段覆盖；最终课时 Review 首次成功写入后永久不可变。

### 3.5 用户掌握最终控制权

AI 可以建议继续、加深或结束，但不能自行结束课节。用户始终可见“暂停学习”和“结束本课”。教学未闭环时结束按放弃课节处理。

## 4. 领域对象

### 4.1 LessonDefinition

来自不可变确认版大纲的课节定义，至少包含：

- `lessonDefinitionId`；
- `courseId`；
- `outlineVersionId`；
- 模块与课节名称；
- 教学目标；
- `coreKnowledgePoints`；
- 大纲顺序。

### 4.2 LessonSession

课节的原始学习会话。一个 `LessonDefinition` 在完成前最多只有一条原始会话。

- 首次开始学习时创建；
- 永久绑定创建时的 `lessonDefinitionId` 和 `outlineVersionId`；
- 暂停时保持可写；
- 有有效证据后放弃时冻结；
- 恢复已放弃课节时解除同一会话冻结；
- 无有效证据而放弃时删除空会话；
- 课节完成后永久只读。

### 4.3 LessonReview

课节唯一 Review Markdown，使用稳定 `reviewId`：

- `stage`：存在有效学习证据但课节未闭环；
- `final`：课节完整闭环后的权威 Review。

Review 正文的唯一权威内容是完整 Markdown。程序只保存 ID、所属课程、所属课节、大纲版本、类型和时间等元数据，不复制另一套结构化正文。

### 4.4 SupplementarySession

课节完成后由用户发起的补充学习对话：

- 与原始学习会话分离；
- 原始会话继续只读；
- 补充会话完整保留；
- 不生成新的课时 Review；
- 不修改最终课时 Review、完成事实或课程总 Review。

课节记录页不为补充学习增加新的顶层 Tab。顶层仍为“学习对话 / 课时 Review”；“学习对话”内部使用会话列表按时间切换原始学习对话和每次补充学习，右侧展示所选会话。每段补充学习独立保存 ID、时间和对话内容。

### 4.5 CourseReview

课程关闭后生成的课程总 Review。输入在课程关闭时固定，首次成功后永久不可变。

## 5. 状态模型

### 5.1 课节生命周期

用户可见状态只有四种：

| 状态          | 含义                         | 主要入口               |
| ------------- | ---------------------------- | ---------------------- |
| `not_started` | 尚未开始或无证据放弃后已恢复 | 打开学习导航           |
| `in_progress` | 已开始且尚未完成、未放弃     | 继续原始学习会话       |
| `abandoned`   | 用户放弃，未形成完成事实     | 恢复导航或查看阶段记录 |
| `completed`   | 最终 Review 已成功写入       | 只读课节记录           |

`closing` 只用于最终 Review 生成中的内部操作状态，不是第五种用户可见生命周期。

### 5.2 状态转换

```text
not_started
  ├─ 开始学习 → in_progress
  └─ 直接放弃 → abandoned（无会话、无 Review）

in_progress
  ├─ 暂停学习 → in_progress（停止计时，会话仍可写）
  ├─ 无有效证据时结束 → abandoned（删除空会话，无 Review）
  ├─ 有有效证据但未闭环时结束 → abandoned（冻结会话，生成阶段 Review）
  └─ 闭环后确认结束 → closing

abandoned
  ├─ 无保留会话时恢复 → not_started
  └─ 有冻结会话时恢复 → in_progress（解除原会话冻结）

closing
  ├─ 最终 Review 成功 → completed
  ├─ 最终 Review 失败并重试 → closing
  └─ 用户恢复学习 → in_progress
```

### 5.3 课程生命周期

持久化状态：

- `active`；
- `closed`。

“可关闭”是根据课节状态计算出的派生条件，不新增持久化状态。

关闭条件以关闭前最后一个确认版大纲为准：

- 有效课节均为 `completed` 或 `abandoned`；
- `abandoned` 不阻止关闭；
- `not_started` 或 `in_progress` 阻止关闭；
- 被新版明确移除或替换的旧课节不参与条件；
- 新版明确沿用且已完成的旧课节可满足对应完成条件。

关闭触发：

- 全部有效课节均为 `completed`：最后一课最终 Review 成功后自动关闭；
- 存在 `abandoned`：课程保持 `active` 并显示“结束课程”；用户查看放弃清单和不可恢复提示后显式确认关闭；
- 确认前可恢复放弃课节；确认关闭后不可恢复、不可修改大纲、不可追加课节、不可重开。

## 6. 进入课节

### 6.1 未开始课节

点击课节卡先打开学习导航，不立即创建会话。导航至少显示：

- 所属课程和模块；
- 课节名称；
- 来自确认版大纲的核心知识点；
- “开始学习”和“返回课程大纲”。

关闭导航不产生会话、计时、历史或完成事实。只有点击“开始学习”才创建 `LessonSession`。

### 6.2 学习中课节

点击后恢复同一原始学习会话。暂停不会创建新会话，也不会生成 Review。

### 6.3 已放弃课节

无有效证据、无保留会话：

- 点击恢复后回到 `not_started`；
- 再次开始时创建新原始会话；
- 计时从零开始。

有有效证据和冻结会话：

- 先打开恢复导航；
- 只显示“已学习的核心知识点”和“待完成的核心知识点”；
- 只提供“查看记录”和“恢复学习”；
- “查看记录”打开只读的学习对话与阶段 Review；
- “恢复学习”解除同一原会话冻结并切换为 `in_progress`。

恢复导航不重复展示阶段 Review 正文、累计时长或会话详情。

### 6.4 已完成课节

直接打开只读课节记录，不创建主学习会话。顶部固定提供：

- `学习对话`；
- `课时 Review`。

完成态入口统一使用“点击查看课节记录”。

## 7. 学习上下文装配

新课节开始时自动继承：

1. 学习起点评估摘要；
2. 该会话绑定版本的确认版大纲；
3. 开课当时所有已完成课节的最终 Review；
4. 必要的课程级记忆压缩结果。
5. 阅读研讨课节所绑定的相关原文章节、定位信息和必要上下文片段；长材料按当前课节范围检索，不把全文无差别放入每次请求。

不继承：

- 其他课节原始学习对话全文；
- 已放弃课节阶段 Review；
- 补充学习对话；
- 已废弃思维模式标签。

较早最终 Review 可以无损要点化压缩，但不得删除会影响当前教学判断的知识掌握、误区和学习表现信息。

恢复已放弃课节时，除上述课程上下文外，还加载本课原始学习会话、当前阶段 Review 和未完成知识点。

每次生成由 `interactive-teaching` 内部的 `TeachingContextAssembler` 统一装配已经物化的 `TeachingContextPackage`，不把 `templateRef`、`artifactRef` 或文件路径直接交给教学智能体。上下文包含：

1. 当前用户消息、最近完整对话和教学账本游标后的未观察消息；
2. 课程与本课契约层，其中 2A 是当前绑定版本的课程目标、课程课节地图、本课目标、全部核心知识点和相关材料片段，2B 是课程身份事实 `courseMode` 与八种玩法可选的非强制 `playIntent`；标准模式不携带 `playIntent`；
3. 最新教学状态账本，包括已讲解内容、支持/限制性掌握证据、开放项、教学支线和观察游标；
4. 学习起点评估、相关最终 Review 和必要课程记忆；
5. 全局用户档案针对当前教学用途返回的安全只读个性化视图，不包含学习画像正文。

上下文冲突时，当前明确表达优先于历史弱信号，原始来源优先于派生摘要，当前会话绑定版本优先于后续大纲版本。Token 不足时先裁剪长期弱信号、较远 Review、较远对话和材料扩展片段；当前消息、当前课节核心知识责任、开放项及其来源不得裁剪。

不构造允许主题清单、前置知识白名单或固定教学范围模板。AI 可以自行发现对理解有价值的跨域案例、前置知识和课程邻接方向。

标准模式与八种玩法共用同一互动教学深模块。`courseMode` 只保存课程来源身份；`playIntent` 是第二层中的条件性择优信号，只在多个教学动作均能满足当前问题、本课责任和账本开放项时影响选择。系统不设置数值权重、回合配额、固定激活阶段或方法命中率；没有自然机会时允许不体现玩法。它不编译成固定步骤、阶段、题量、方法库、观察字段或完成条件；玩法不得创建专属课节状态机、Review Schema 或用户档案证据管线。

## 8. 大纲版本绑定

原始学习会话永久绑定开始时的大纲版本。课程发布新版大纲后：

- 暂停或已放弃课节仍恢复原课节、原版本和原会话；
- 不得静默迁移或覆盖为新版课节；
- 若原课节被调整、拆分、替换或移除，恢复导航显示版本差异；
- 用户可以继续原会话，也可返回当前大纲选择替代课节；
- 选择替代课节是开始新的 `LessonDefinition`，不是恢复旧会话；
- 原会话和 Review 永远归属于原课节及原大纲版本。

## 9. AI 教学流程

### 9.1 内部教学路径

AI 在开课时形成覆盖本课教学目标和核心知识点的内部教学路径，但不一次性生成整篇正文。内部路径可随用户回答动态调整，不直接作为固定 UI 步骤强制用户完成。

### 9.2 课前热身

AI 先读取已有上下文，再决定是否热身：

- 证据不足时，根据本课目标提出合适问题；
- 证据充分时可缩短或跳过；
- 不使用固定问卷或固定轮数；
- 只用于调整本课起点、深度、案例和验证方式；
- 不固化为永久水平标签。

### 9.3 渐进式讲解

- 按知识之间的真实依赖关系逐步生成；
- 可以完整讲清紧密关联的一组概念后再互动；
- 不强制“一段讲解一个问题”；
- 可以使用 Markdown 标题、列表、表格、代码块、引用和知识图谱；
- AI 内容不使用整条消息气泡，用户消息使用右侧气泡；
- 不显示“AI”“用户”等发送者标签。

### 9.4 关键节点互动

AI 在需要确认理解、暴露偏差或决定下一步路径时邀请用户回应：

- 问题必须服务于当前教学判断；
- 不按固定题量或轮次触发；
- 用户可以打断提问；
- AI 回答后自然回到主线；
- 用户可要求继续、换题或稍后验证；
- 跳过不等于掌握，也不自动判定未掌握。

### 9.5 偏差补救

发现理解偏差后，AI 应：

1. 明确偏差发生在哪里；
2. 换一种解释、案例或任务；
3. 用不同问题再次验证；
4. 根据新证据决定继续主线或进一步加深。

### 9.6 课程闭环判断

AI 结合全部核心知识点和真实掌握证据判断：

- 已达到教学目标：建议结束；
- 尚有未验证内容：指出缺口并建议继续；
- 存在明显偏差：继续补救和验证。

AI 只能建议，不能执行“结束本课”。

### 9.7 教学智能体、观察与状态账本

教学智能体只读取已经装配的教学上下文并输出面向学习者的自由 Markdown。它可以决定讲法、案例、顺序、深度、互动和教学支线，但不能直接修改课节状态、建立 `evidenceCheckpoint`、写掌握结论、Review、全局用户档案或学习画像。

每个完整教学回合提交后，独立教学观察器异步生成局部、可追溯观察；严格校验消息范围、完成状态、知识点引用和来源哈希后，由确定性 Reducer 更新唯一教学状态账本。Review 和全局用户档案候选证据提炼不得绕过账本重新扫描整段原始对话建立私有状态。有效 `learner_reasoning_behavior` 条目可以经专用只写端口投影为全局用户档案中的局部 Episode，但不直接形成画像结论或固定思维类型。

观察尚未完成时不阻塞当前回复展示。下一回合同时读取最后稳定账本和账本游标后的原始消息，避免遗漏最新互动。观察失败时会话保留并进入恢复队列，不使用过期状态伪造完成判断。

### 9.8 教学支线与课程邻接探索

学习者提出与整门课程相关但不属于当前课节责任的脑洞时，观察关系记为 `adjacent`，不记为 `off_scope`：

- 可以自然展开，不要求立刻打断或机械拉回本课；
- 账本单独记录教学支线、课程主题关系、发起问题和返回主线引用；
- 支线内容不冒充当前核心知识点已讲解，也不自动完成未来课节；
- 支线成为新的主要学习目标时，由学习者选择继续、暂存后返回本课，或以后建立补充学习/新课；
- Review 可以记录有价值的探索，但课程闭环仍按当前课节责任判断。

`direct`、`supporting`、`adjacent`、`unclear` 和 `off_scope` 是回复完成后的语义关系，不是生成前许可。只有无法与课程、学习目标或用户当前学习意图建立合理关系时才保守使用 `off_scope`；新颖、跨域或尚未映射到大纲的内容优先保留为 `adjacent` 或 `unclear`。

## 10. 有效证据

### 10.1 掌握证据

用于判断教学目标是否达成。包括学习者真实的解释、应用、比较、预测、纠错、举例或任务表现。仅完成讲解或询问“懂了吗”不构成掌握证据。

### 10.2 evidenceCheckpoint

用于判断放弃时应保留还是删除会话，不等同于掌握证据。

以下任一发生时建立检查点：

- AI 完整输出实质知识讲解；
- 用户对热身、理解检查或教学问题作出实质回答；
- 用户提出与课节知识相关的具体问题、判断或反思。

以下不建立检查点：

- 欢迎语、导航或流程说明；
- “开始吧”“好的”等无知识信息回复；
- AI 只提出问题但用户尚未回答；
- 被停止生成或技术中断的残缺 AI 输出；
- 页面停留、按钮点击和时长。

后端不得使用字数、消息数量或时长代替语义判断。`evidenceCheckpoint` 只能由通过来源校验的教学观察建立。观察待处理、失败或无法确定时优先保留会话，但不得伪造检查点已经成立。

## 11. 流式对话

### 11.1 渐进输出

- 用户点击发送后，同步追加本地用户消息、清空输入框并展示“正在思考中…”，不得等待发送请求或 AI 完整回复后再一次性显示整轮对话；
- 服务端确认后以规范消息快照替换本地消息；首个 AI 流式片段到达后由真实 Markdown 替换思考占位；
- AI 回复以流式 Markdown 增量显示；
- 已到达前端的内容立即渲染；
- 结构未闭合时采用容错渲染；
- 完成后固化为不可编辑消息。

### 11.2 停止生成

用户可停止当前 AI 回复：

- 已显示部分保留为未完成回复；
- 未完成回复不构成完整教学或掌握证据；
- 用户可继续原回复或发送新问题；
- 停止生成不等于暂停学习或结束本课。

### 11.3 技术失败

只有因断线、超时或进程异常而未完成的同一次 AI 回复可以续接或重试。重试不得覆盖已经完成的历史消息。

发送请求在服务端受理前失败时，必须移除思考占位、标记本地消息失败并把原内容恢复到输入框；受理后流式失败则保留已经确认的用户消息和已到达片段。任何本地乐观消息、思考占位或按钮忙碌态都不是会话事实，不得进入 Repository、统计、全局用户档案或画像证据。

## 12. 单窗口写入权

同一原始会话任一时刻只有一个页面实例拥有写入和计时资格：

- 持有者可发送消息、接收 AI 回复和累计时长；
- 其他标签页、窗口或设备只读同步最新内容；
- 只读窗口显示“本课正在其他窗口学习”和“切换到此窗口”；
- 接管写入权必须原子完成；
- 新窗口接管成功后，旧窗口立即停止计时、取消输入并转为只读；
- 接管不创建新会话、不复制消息、不重置教学位置；
- 并发接管请求串行化，最终只能有一个持有者。

## 13. 暂停学习

统一业务术语为“暂停学习”。触发来源：

- 用户手动暂停；
- 关闭课程页；
- 离开课程页；
- 网络断开；
- 页面进入后台。

规则：

- 停止计时并保存当前位置；
- 保持 `in_progress`；
- 不冻结原会话；
- 不生成 Review；
- 不产生完成事实；
- 手动暂停、离页、关闭或断线后，再次进入才恢复；
- 页面仅进入后台时，回到前台可自动恢复计时。

## 14. 实际学习时长

仅在同时满足以下条件时计时：

- 课程学习页前台可见；
- 当前窗口持有会话写入权；
- 会话未暂停、未冻结、未结束。

暂停、后台、断线、离页、放弃或写入权转移时，必须原子关闭当前计时区间。

- 有有效证据的同一会话跨暂停、放弃和恢复累计；
- 最终课时实际时长等于全部不重叠有效区间之和；
- 已放弃未完成期间只在所属课节记录显示，不进入完成统计、学习日历或周报；
- 最终完成后按最终完成日期一次性进入完成统计；
- 无证据空会话被删除时，其短暂停留时长同时清除；恢复后从零开始；
- 课前预估时长仅用于排期提示，不覆盖实际时长。

## 15. 放弃课节

### 15.1 从未开始时放弃

- 状态切换为 `abandoned`；
- 不创建会话；
- 不创建 Review；
- 不计完成、不推荐、不排期；
- 恢复后回到 `not_started`。

### 15.2 已开始但无有效证据时放弃

- 停止计时；
- 删除已创建的空会话；
- 清除空会话时长；
- 不创建 Review；
- 状态切换为 `abandoned`；
- 恢复后回到 `not_started`。

### 15.3 已有有效证据时放弃

- 停止计时；
- 冻结原始学习会话；
- 生成或更新同一 `reviewId` 的阶段 Review；
- 状态切换为 `abandoned`；
- 不产生完成事实；
- 不进入推荐、排期、计划流、学习日历或周报；
- 恢复时解除同一会话冻结，不创建续学会话。

### 15.4 提前结束确认

用户在教学未闭环时点击“结束本课”，系统先展示尚未完成或未经验证的核心知识点。用户确认后执行相应放弃规则。

## 16. 阶段 Review

仅在已有 `evidenceCheckpoint` 的课节被放弃时生成。Review 必须忠实覆盖下列业务语义，但不要求对应为固定标题、段落或顺序：

- 已经讲解或验证的核心知识点；
- 已出现的掌握证据与偏差；
- 尚未完成或尚未验证的核心知识点；
- 阶段性学习表现。

规则：

- 多次放弃始终使用同一 `reviewId`；
- 新阶段 Review 在临时区域完整生成后原子覆盖旧阶段 Review；
- 失败时保留旧阶段 Review；
- 不保留 Review 版本时间线；
- 不作为其他课节默认继承上下文；
- 课程关闭时可作为课程总 Review 的输入；
- 最终闭环后被最终课时 Review 原子覆盖。

## 17. 最终课时 Review

### 17.1 生成内容

完整 Markdown 必须同时履行“本课知识责任回看”和“基于真实互动的学习表现回看”，但不要求这两项成为固定章节。AI 可根据学科、证据和用户路径自由采用知识图谱、结构树、代码、公式、叙事或其他合适表达。

学习表现评价必须基于真实对话证据，不能根据时长、点击或无信息回复推断掌握。

最终 Review 的权威输入由服务端冻结：完整教学检查点、全部 active 观察及其消息来源、课节知识责任和可选 `reviewLens`。客户端可继续携带旧版来源字段用于兼容，但它们不是权威输入。`reviewLens` 只影响叙事显著性，不能筛除证据、改变完成度或要求玩法专属栏目。

### 17.2 关闭事务

用户在课程闭环后确认结束：

1. 持久化不可变结束快照和结束意图；
2. 立即停止计时；
3. 冻结原学习会话；
4. 进入内部 `closing`；
5. 使用同一结束快照和 `reviewId` 生成最终 Review；
6. 原子写入成功后才切换为 `completed` 并产生完成事实；
7. 弹出完整最终 Review。

### 17.3 生成失败

- 原会话保持冻结；
- 已有阶段 Review 保持不变；
- 不产生完成事实；
- 不进入日历、周报或继承上下文；
- 提供“重新生成 Review”和“恢复学习”；
- 重试复用同一结束快照和 `reviewId`，不得重复计时或复制对话；
- 恢复学习取消结束意图、解除冻结并回到 `in_progress`；
- 服务重启后可继续未完成事务。

### 17.4 成功后的不可变性

最终课时 Review 首次成功写入后：

- 永久只读；
- 用户无修改或纠错权；
- AI 和后台任务不得覆盖；
- 不允许再次生成；
- 补充学习不得修改；
- “重新生成 Review”入口永久消失。

### 17.5 弹窗和离页

- 用户仍在页面时，成功后立即弹出完整 Review；
- 弹窗展示已成功写入的完整权威 Markdown，不做摘要截断；
- 弹窗头部显示课节、所属课程、课程模式、生成时间和永久只读状态；正文区域可滚动，头部和底部操作区固定；
- 玩法身份只以低强度模式徽标、细强调线和章节锚点呈现；完成与只读继续使用全局状态色；
- 用户已离页、关闭或断线时，后台继续归档；
- 下次进入应用时显示一次“课时 Review 已生成”；
- 点击提示打开双 Tab 课节记录并默认定位“课时 Review”；
- 关闭弹窗不撤销完成事实、不删除 Review；
- 弹窗只提供“查看课节记录”和“返回课程大纲”，不显示推荐下一课、修改 Review、重新生成、补充学习或主题总结；
- Escape 与“返回课程大纲”等效，不增加第三个关闭按钮。

## 18. 推荐下一课

- 大纲确认时，AI 只在先修条件已满足的课节集合内给出初始推荐，不使用数组第一项作为业务默认；
- 每个最终课时 Review 成功后，AI 结合确认版大纲、已完成课节和本次表现，在先修条件已满足且尚未完成、未放弃的课节中推荐一项；
- 只保存 `recommendedLessonId`；
- 对应课节卡显示“推荐下一课”；
- 用户可自由进入其他课节，不确认、不警告、不锁课；
- 已放弃和已完成课节不进入候选；
- 不存在候选时清空 `recommendedLessonId`；
- 单课 Review 弹窗不展示推荐下一课入口。

推荐只改变课程导航提示，不创建、不启动 LessonSession，也不改变任何课节完成状态。AI 返回不在可选集合中的课节时，后端拒绝该结果并进入可诊断失败/重试路径，不静默回退为第一课。

## 19. 课程关闭

### 19.1 全部完成

最后一个有效课节最终 Review 成功后，系统自动：

1. 清空 `recommendedLessonId`；
2. 锁定最终大纲；
3. 将课程切换为 `closed`；
4. 固定课程总 Review 输入快照；
5. 异步生成课程总 Review。

### 19.2 存在已放弃课节

当所有有效课节均为 `completed` 或 `abandoned`：

- 课程仍保持 `active`；
- 页面显示派生的“可关闭”状态和“结束课程”；
- 展示全部已放弃课节及关闭后不可恢复提示；
- 用户确认前仍可恢复放弃课节；
- 用户确认后执行与自动关闭相同的关闭事务。

### 19.3 关闭后的限制

- 不可修改大纲；
- 不可发布新版本；
- 不可追加或恢复课节；
- 不可撤回关闭；
- 推荐扩展课程必须创建新的 Course，并保存 `sourceCourseId`；
- 原课程档案、课节记录和 Review 继续可读。

### 19.4 课程永久删除

课程永久删除不同于关闭：它允许针对任意正式课程执行不可逆级联删除。用户从正式课程大纲页的独立危险操作入口发起；风险弹窗只提供“取消”和“永久删除”，不要求输入课程名称。

- 删除开始时立即撤销所有会话写入权、停止计时并拒绝后到的消息、Review、排期和计划流写入；
- 删除成功后永久移除 Course、大纲版本、课节、学习及补充会话、Review、课程总 Review、关闭快照、排期、计划流、材料引用和所有页面索引；
- 同时撤销该课程贡献的完成事实、时长、活跃日、日历记录、候选证据、ReasoningBehaviorEpisode 和来源组，使跨课程思维行为分析快照失效，并从剩余事实/Episode 重建历史统计、学习日历、个性化与学习画像；
- 画像重算失败不回滚删除；画像页面显示更新失败或更新中，且不得继续展示该课程的证据或结论；
- 删除命令必须幂等；任何关联资源不能安全删除时，整项删除失败并保持删除前状态，不得对用户宣告部分成功。

## 20. 课程总 Review

### 20.1 固定输入

课程关闭时形成不可变输入快照：

- 最终确认版大纲；
- 已完成课节的最终课时 Review；
- 已放弃课节现存的阶段 Review；
- 无 Review 的已放弃课节及其未学习事实。

不读取原始学习对话全文或补充学习对话。

### 20.2 输出责任与自由度

课程总 Review 使用“冻结课程结构 + 已完成课节最终 Review + 已放弃课节阶段 Review + 无 Review 缺口”的物化证据包自由生成 Markdown，不使用固定标题、固定段落或固定推荐模板。它应帮助用户理解课程知识线索、实际学习表现和仍存在的缺口；只有在证据和学习方向自然支持时才提出扩展方向。

对于已放弃课节，AI 必须区分“未学习”“部分学习但未闭环”和“已完成”，不得把阶段 Review 当作最终掌握结论。课程玩法意图只可作为叙事关注点，不能过滤任何课节证据或改变完成事实。

### 20.3 失败与重试

- 课程先关闭，后生成课程总 Review；
- 生成失败不撤销或阻止关闭；
- 课程档案显示失败状态和“重新生成主题总结”；
- 重试使用同一关闭输入快照，幂等执行；
- 服务重启后仍可重试。

### 20.4 成功后的不可变性

- 首次成功写入后永久不可修改；
- 不允许主动重新生成；
- 补充学习不触发同步更新；
- 成功后入口固定为“查看主题总结”；
- 失败重试入口永久消失。

## 21. 前后端共享动作

建议共享合同至少包含：

- `StartLesson`；
- `PauseLessonSession`；
- `ResumeLessonSession`；
- `TakeOverLessonSession`；
- `StopGeneration`；
- `AbandonLesson`；
- `RestoreAbandonedLesson`；
- `FinalizeLesson`；
- `RetryFinalReview`；
- `ResumeClosingLesson`；
- `StartSupplementarySession`；
- `CloseCourse`；
- `RetryCourseReview`。

所有命令必须具备幂等键。会话写入权转移、计时区间关闭、Review 原子覆盖、课节完成和课程关闭不得依赖前端单方面保证。

## 22. UI 行为规则

### 22.1 对话视觉

- AI 内容直接铺陈，不使用整条消息外框；
- 用户内容使用右侧气泡；
- 不显示发送者名称；
- 发送后立即显示用户气泡和 AI 思考占位，思考占位与后续流式正文占用同一回复位置；
- 代码块、表格、引用、知识图谱可使用内容容器；
- 流式生成期间保持稳定布局，避免整体跳动。

### 22.2 常驻操作

正式学习页始终可见：

- 暂停学习；
- 结束本课；
- 停止生成（仅 AI 正在输出时）；
- 当前实际学习时长。

### 22.3 只读记录

- 已放弃阶段记录：学习对话 / 阶段 Review；不允许补充学习；
- 已完成课节记录：学习对话 / 课时 Review；只展示已有原始与补充会话，不在记录页提供新建补充学习入口；
- “学习对话”Tab 左侧为会话列表，第一项固定为原始学习对话，其后按创建时间排列“补充学习 01、02……”；右侧展示当前选中会话；
- 原始学习对话标记为“课时依据”，补充学习标记为“独立归档 · 不修改 Review”；
- 新补充学习结束后追加到会话列表，不拼接进原始对话；
- 最终 Review 页面不出现“补充说明并修正评价”或任何编辑入口；
- 补充学习对话单独归档，不混入原始会话。

### 22.4 课程总 Review

- 关闭成功、总 Review 生成中：显示生成状态；
- 生成失败：显示“重新生成主题总结”；
- 生成成功：显示“查看主题总结”；
- 成功后不显示重新生成或编辑入口。

## 23. 错误与恢复

| 场景               | 必须行为                             |
| ------------------ | ------------------------------------ |
| 消息受理前失败     | 恢复原输入；标记本地消息失败；允许重试 |
| AI 回复中断        | 保留已到达片段；允许续接同一次回复   |
| 页面后台           | 停止计时；回到前台自动恢复           |
| 离页或断线         | 停止计时并暂停；再次进入恢复         |
| 多窗口竞争         | 只有一个写入者；接管后旧窗口只读     |
| 阶段 Review 失败   | 保留旧阶段 Review；课节保持已放弃    |
| 最终 Review 失败   | 不完成课节；允许幂等重试或恢复学习   |
| 最终 Review 成功后 | 永久不可修改、不可重生成             |
| 课程总 Review 失败 | 课程保持关闭；允许同快照重试         |
| 服务重启           | 恢复未完成的课节关闭和总 Review 任务 |

## 24. Repository 边界

初期采用本地文件存储，但领域服务只能依赖 Repository 接口。建议至少拆分：

- `LessonDefinitionRepository`；
- `LessonSessionRepository`；
- `LessonReviewRepository`；
- `CourseRepository`；
- `CourseReviewRepository`；
- `LearningTimeRepository`；
- `WriteLeaseRepository`；
- `ClosingIntentRepository`；
- `CourseDeletionJobRepository`。

关键写入必须支持：

- 条件更新或乐观并发控制；
- 原子替换；
- 幂等命令；
- 崩溃恢复；
- 单写入权租约；
- 级联删除任务的原子提交、幂等和崩溃恢复。

## 25. 验收与回归基线

### 25.1 课节状态

- 四种用户可见状态转换正确；
- `closing` 不泄漏为第五种课节状态；
- 暂停不生成 Review；
- 无证据放弃删除空会话并清零时长；
- 有证据放弃冻结同一会话并生成阶段 Review；
- 恢复不创建新会话。

### 25.2 教学与证据

- 热身可以跳过且不依赖固定问卷；
- 用户发送后立即看到本地消息和思考占位，服务端规范消息到达后无重复消息；
- 消息受理失败时恢复输入，临时 UI 状态不建立教学证据或画像证据；
- 跳过互动不构成掌握；
- AI 不能仅凭讲解完成判定掌握；
- evidenceCheckpoint 与掌握证据分离；
- 停止生成的残缺回复不构成完整教学证据。

### 25.3 时长与并发

- 后台、断线、离页、暂停和接管均停止旧计时区间；
- 多窗口不能重复生成 AI 回复或重复计时；
- 恢复后累计同一会话时长；
- 无证据空会话时长不进入统计。

### 25.4 Review

- 每课最多一个 `reviewId`；
- 阶段 Review 可原子覆盖但不保留版本；
- 最终 Review 成功后不可变；
- 最终 Review 失败不产生完成事实；
- 补充学习不修改任何 Review；
- 单课弹窗只有两个规定入口。

### 25.5 课程关闭

- 全课完成自动关闭；
- 存在放弃课节时不自动关闭；
- 显式关闭前仍能恢复放弃课节；
- 显式关闭后不能恢复或改大纲；
- 总 Review 失败不影响关闭；
- 总 Review 只能在首次成功前重试；
- 总 Review 成功后不随补充学习更新。

## 26. 明确废弃的旧口径

实现和 UI 不得重新引入：

- “学习起点审计”术语，统一为“学习起点评估”；
- 固定课程正文模板；
- 固定问题数量和互动轮次；
- 思维模式标签；
- 强制锁课；
- “待继续”状态，统一使用“学习中”；
- 放弃后创建续学会话；
- 多份阶段 Review 时间线；
- 最终 Review 的修改、纠错或重新生成入口；
- 补充学习回写课时或课程总 Review；
- 课程关闭后重新修改大纲。

## 27. 规格完成条件

本文档覆盖从点击正式课节到课节完成、Review 归档和课程关闭的完整功能边界。历史统计和学习画像已经由《历史统计与学习画像数据源定义清单》《学习画像数据抓取与分析策略规则》另行确定；本学习流实现必须按其中的数据键、检查点和分流规则产出事实与候选证据。玩法隐藏上下文、附件资料和扩展课程创建仍按各自专项规则处理。
