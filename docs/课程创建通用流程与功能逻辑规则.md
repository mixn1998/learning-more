# Learning MORE 课程创建通用流程与功能逻辑规则

## 1. 范围

本文定义从用户发起“想学什么”到正式课程单元列表生成完成的通用流程。

包含：

- 标准课程入口；
- 玩法入口复用；
- AI 学习起点评估；
- 至少三轮基础评估与开放继续；
- 候选大纲生成和对话调整；
- AI 标签识别；
- 最终确认；
- 正式课程、版本和课程单元列表创建。

不包含：

- 课节内部的具体教学玩法；
- 课节实时学习对话；
- 课节结束 Review；
- 主题级总结；
- 商业洞察等新玩法的隐藏上下文细则。

## 2. 核心原则

1. 用户创建标准课程时只输入“想学什么”。
2. 正式课程在最终大纲确认前不存在。
3. 学习起点评估和大纲创建是一段可恢复的 AI 对话切片。
4. 基础评估至少完成三轮；用户可自行继续更多轮，再决定何时生成候选大纲。
5. AI 在对话中自然追问，不展示传统字段表单。
6. 大纲以完整 Markdown 为课程内容权威来源。
7. 每个候选大纲必须同时带有一个学科标签和一至三个主题标签。
8. 标签由 AI 识别，用户不填写字段，但可通过对话要求修正。
9. 用户可以反复调整候选大纲，只有最新候选可确认。
10. 确认必须是显式按钮动作，不能仅凭自然语言自动创建正式课程。
11. 确认采用原子事务：要么完整创建课程及单元列表，要么不创建任何正式对象。
12. 标准入口与八个玩法壳均接入同一完整通用流程；玩法差异遵守《八大玩法功能规则》。

## 3. 领域术语

### 3.1 大纲创建会话（OutlineSession）

正式课程创建前的自然 AI 对话。承担学习起点评估、候选大纲生成和调整。它不是草稿课程。

### 3.2 候选大纲（OutlineCandidate）

AI 在某次回复中生成的完整可确认大纲快照，包含 Markdown 和标签元数据。新候选产生后，旧候选保留但标记为已替代。

### 3.3 确认版大纲（OutlineVersion）

用户显式确认后，与正式课程一起创建的不可变版本。后续修改产生新版本，不改写旧版本。

### 3.4 正式课程（Course）

确认版大纲生成后才存在的一级学习实体。新项目不使用旧 `Project/Topic` 两级运行时模型。

### 3.5 课程单元（LessonDefinition）

从确认版 Markdown 中解析出的可点击课节定义。它描述课程结构、课节说明和核心知识点，不包含预生成正文和学习对话。

### 3.6 课程模式（courseMode）

标识课程从标准入口或某个玩法入口发起，例如：

```text
standard
brainstorm
argument_clash
case_study
process_decomposition
decision_analysis
cross_explore
reading_seminar
business_insight
```

它不直接决定大纲形状。

### 3.7 玩法隐藏上下文（PlayHiddenContext）

玩法专项设计提供给 AI 的整体、非强制玩法意图。四类玩法导向只作为设计者区分玩法的观察面，不得成为运行时字段，也不得映射为课程模块、阶段、课节类型、固定 Prompt 模板、步骤清单或输出格式。玩法层不提供“可选方法”、推荐技法或方法库。正式大纲仍由主题知识依赖和学习起点评估证据决定，AI 可以自由调整教学结构与方法。具体规则见《八大玩法功能规则》。

阅读研讨是输入层例外：除自然语言主题外，允许在同一创建入口上传 PDF、TXT、Markdown 等阅读材料。材料解析完成后仍进入相同学习起点评估、候选大纲和显式确认流程，不直接创建 Course。

## 4. 总体流程

```text
用户输入“想学什么”
  ↓
创建 OutlineSession（不是 Course）
  ↓
AI 起点评估对话
  ├─ 至少完成三轮
  └─ 用户可继续更多轮或触发候选生成
  ↓
AI 生成 OutlineCandidate
  ├─ outlineMarkdown
  ├─ disciplineTag（恰好 1 个）
  ├─ topicTags（1–3 个）
  └─ creationContextSummary
  ↓
用户阅读并继续对话调整
  ├─ 保留旧候选可读
  ├─ 生成新候选
  └─ 用户确认最新候选
  ↓
原子确认事务
  ├─ 创建 Course
  ├─ 创建 OutlineVersion v1
  ├─ 解析 LessonDefinition 列表
  ├─ AI 从满足先修条件的集合生成 recommendedLessonId 建议
  └─ 记录 CourseCreated/OutlineVersionConfirmed
  ↓
展示正式课程单元列表
```

## 5. 阶段一：发起课程创建

### 5.1 标准入口

页面只展示：

- 输入框：“今天想学什么？”；
- 一个开始按钮；
- 待完成大纲会话入口。

不展示：

- 学科；
- 学习阶段；
- 时长；
- 思维模式；
- 知识范围；
- 教学风格；
- 课程类型；
- 其他旧建档字段。

输入规则：

- 去除首尾空白；
- 空输入不创建会话；
- 保留用户原始表达，不在前端先分类或改写；
- 有效提交后立即进入对话页，不等待 OutlineSession 创建请求或首轮 AI 回复完成；
- 对话页首屏立即展示产品固定的起始说明、用户刚提交的原始表达和“正在思考中…”；固定说明不是模型消息，不计评估轮次或画像证据；
- 重复点击必须通过客户端禁用和后端幂等键避免创建重复会话。

### 5.2 玩法壳入口

八个玩法作为同级课程创建入口存在：

- `brainstorm`；
- `argument_clash`；
- `case_study`；
- `business_insight`；
- `process_decomposition`；
- `decision_analysis`；
- `cross_explore`；
- `reading_seminar`。

共同规则：

- 每个玩法壳拥有唯一 `courseMode`；
- 主页左栏使用九张同规格入口卡，第一张为“标准模式”，下面依次为八个玩法；主页默认选中 `standard`，顶部“想学什么”输入框是共享创建入口；
- 点击任一入口卡只选择 `courseMode`，并同步改变同一输入框的提示文案、识别色和说明，不创建 OutlineSession、正式 Course 或学习事实；
- 用户提交主题后才创建带所选 `courseMode` 的 OutlineSession，并进入统一建档工作台；
- 阅读研讨被选中时，同一主页输入区额外展开材料上传入口；材料与主题在提交时一起进入 OutlineSession；
- 用户可在提交前点击“标准模式”卡恢复 `standard`，不另设“重置”按钮，并保留尚未提交的主题文本；
- 所有玩法壳接入统一 OutlineSession、候选大纲和确认流程；
- 除阅读研讨的材料上传外，玩法不增加显式字段或专属表单；
- 阅读研讨允许只上传材料，再在学习起点评估中澄清阅读目标；
- 不继承旧项目玩法表单、旧 Prompt、旧临时课、旧转档案或旧玩法历史逻辑；
- 玩法意图不能映射为课程模块、阶段、固定课节类型或执行清单。

八个玩法均可发起完整课程创建，具体玩法身份、自由度保护和视觉差异见《八大玩法功能规则》。

建档工作台不再显示玩法栏或重复主题输入框，页面根据 OutlineSession 中保存的 `courseMode` 横向铺满。用户需要更换玩法时返回主页并创建新的 OutlineSession，旧会话按既有规则保留。主页的课程表、今日学习和历史入口不因玩法选择而改变。

阅读材料规则：

- 支持 PDF、TXT、Markdown 等可解析文本；
- 原文件引用和解析快照保存于 OutlineSession；
- 解析快照记录文本、章节标题层级、PDF 页码或其他定位范围及解析警告；
- 候选大纲展示课节与原文章节或页码范围的材料章节映射；
- AI 可按教学需要合并或拆分章节，但不得静默遗漏重要范围；
- 无法提取文本、加密或扫描版 PDF 必须显示解析失败，不得生成虚构章节；
- 解析后仍进入相同学习起点评估，不自动确认或创建正式课程。

### 5.3 创建结果

只创建 `OutlineSession`：

```ts
type OutlineSession = {
  id: string;
  kind: 'creation' | 'adjustment';
  status: 'active' | 'paused' | 'confirming' | 'confirmed' | 'abandoned';
  topicText: string;
  courseMode: CourseMode;
  sourceCourseId?: string;
  hiddenContextRef?: string;
  messageIds: string[];
  candidateIds: string[];
  currentCandidateId?: string;
  candidateUpdateStatus: 'idle' | 'updating';
  createdAt: string;
  updatedAt: string;
};
```

此时不得创建 Course、OutlineVersion 或 LessonDefinition。

## 6. 阶段二：AI 学习起点评估

### 6.1 对话形式

评估以实时 AI 对话进行，不使用固定问卷弹窗。AI 根据用户输入动态决定追问内容和数量。

评估目标是了解足够影响课程主线的信息，例如：

- 用户已有经验和真实作品；
- 用户对主题的当前理解；
- 最近遇到的问题、停滞或失败；
- 想完成的真实任务；
- 对成功的判断标准；
- 需要避免的方向；
- 可用材料、上下文或限制。

这些是 AI 的推断目标，不是前端字段。

首页提交的初始课程方向必须作为本会话第一条 `user` 消息持久化并立即进入第一轮 AI 回应；课程创建页加载时先以本地乐观消息直接展示该原始表达，并用“正在思考中…”占位，不要求用户重复提交。服务端返回后用权威会话消息替换本地副本，首个 AI 流式片段到达后替换思考占位。只有一条完整的“用户消息 + AI 完整回复”才计为一轮，失败或中断的 AI 回复不增加轮数。

后续每次评估或调整消息也遵守同一交互规则：点击发送后同步追加本地用户消息、清空输入框并显示思考占位；请求受理失败时停止占位、标记本地消息失败并恢复原输入。乐观消息、固定说明和思考占位不进入 Repository、历史统计、全局用户档案或画像证据，只有服务端确认后的规范消息可以进入领域数据链。

### 6.2 追问规则

- 每轮优先提出少量高信息量问题；
- 不重复询问用户已经明确表达的信息；
- 不为填满模板而无限追问；
- 用户回答模糊时可以用具体场景澄清；
- 用户不知道答案时，允许用示例帮助表达；
- 不把推断包装成用户明确说过的话；
- 不要求用户显式选择标签或课程结构；
- 玩法隐藏上下文只能提供整体意图，不能覆盖用户当前意图，也不能被实现为问卷、步骤、阶段、课程模块、固定课节类型、必交产物或固定输出结构。

### 6.3 最低评估轮次与开放继续

- 基础评估至少完成三轮；三轮前不得显示“跳过评估”或候选大纲生成入口；
- 达到三轮只代表用户获得生成候选的选择权，不代表 AI 可以自动结束对话；
- 用户可自行继续任意轮数，AI 继续按真实信息缺口追问或帮助澄清；
- 候选入口只由 `completedAssessmentRounds >= 3` 和当前无运行中任务共同决定；
- 技术失败不计轮次，恢复后从原状态继续，不用伪造 AI 回复补齐轮数。

### 6.4 退出与恢复

- 用户中途退出时会话状态变为 `paused` 或保持可恢复；
- 首页显示待完成会话；
- 恢复时加载完整消息和当前候选；
- 未确认会话不进入正式课程、历史统计或课程表；其中有实质内容的评估对话可以按《学习画像数据抓取与分析策略规则》在稳定检查点提炼画像候选证据，但必须保留“未确认建档会话”来源状态，不得冒充正式课程或已完成学习事实；
- 用户可显式放弃会话；放弃不删除历史消息，但不再作为默认继续入口。

## 7. 阶段三：候选大纲生成

### 7.1 生成时机

AI 在以下任一条件下生成候选：

- 已完成至少三轮基础评估后，用户明确触发生成候选；
- 用户基于现有候选提出结构调整，且对齐判断为整版重生或局部调整。

普通解释或追问回复不得强制生成空壳候选。

用户触发候选生成后，右侧候选区域和主操作按钮必须立即显示“正在生成”状态，不得等待生成请求被服务端受理后才反馈。受理失败时恢复可重试状态并保留旧候选；该按钮忙碌态只是前端临时状态，不是候选或学习事实。

### 7.2 候选合同

```ts
type OutlineCandidate = {
  id: string;
  sessionId: string;
  sequence: number;
  status: 'current' | 'superseded' | 'confirmed';
  outlineMarkdown: string;
  disciplineTag: string;
  topicTags: string[];
  creationContextSummary: string;
  sourceMessageId: string;
  createdAt: string;
  supersededAt?: string;
};
```

不变量：

- `disciplineTag` 必须恰好一个非空值；
- `topicTags` 必须为一至三个去重后的非空值；
- 标签由 AI 识别，不由用户表单提交；
- 用户在对话中纠正标签时，必须生成新候选；
- 标签作为结构化元数据保存，并在大纲顶部可见；
- Markdown 正文只保存课程内容，不依赖 YAML frontmatter；
- 候选与标签共同版本化，不允许只改标签而不产生新候选。

### 7.3 Markdown 结构

确认候选至少使用：

```markdown
# 课程名称

课程定位或学习主线说明。

## 模块名称

### 课节名称

本课节的目标、核心问题或简短说明。

#### 核心知识点

- 知识点一；
- 知识点二；
- 知识点三；
- ……
```

规则：

- 一个 `#` 课程标题；
- 一个或多个 `##` 模块；
- 每个模块至少一个 `###` 课节；
- 课节标题必须可点击、可独立学习；
- 每个课节必须包含非空的“核心知识点”列表，通常为二至五条，但不以固定条数限制 AI 对主题的合理拆分；
- 核心知识点用于大纲展示、进入课节前的导航预览和后续学习上下文，是确认版大纲的一部分；
- 核心知识点只描述本课将覆盖的关键概念、判断或能力，不扩写为课节正文；
- 不生成课节正文；
- 不生成锁课规则；
- 不强制固定课节数量、时长、阶段或内容组织形式；
- 大纲必须存在可理解的主线，也允许跨模块和非线性学习；
- 可设计但不强制“综合复习课”，主题总结后续作为独立能力设计。

### 7.4 标签识别

`disciplineTag` 表示最主要的学科或领域，例如“计算机科学”“艺术与设计”“商业与管理”。

`topicTags` 表示课程实际聚焦的一至三个主题，但不能过于细分。

规则：

- 标签从用户对话和候选大纲共同推断；
- 多学科课程仍只选一个主 `disciplineTag`；其他重要方向进入 `topicTags` 或大纲说明；
- 标签使用用户可读中文，不暴露内部枚举；
- 标签不能包含课程模式、思维模式或玩法名称，除非玩法本身就是学习主题；
- 用户纠正优先于 AI 推断；
- 正式确认后标签写入 OutlineVersion 和 Course 当前快照。

## 8. 阶段四：候选调整交互

### 8.1 页面布局

采用已确认的 B 方案：

- 尚无候选时：单栏聚焦对话；
- 首个候选产生后：桌面端左侧对话、右侧当前大纲；
- 移动端：对话与大纲使用 Tab；
- 大纲顶部显示 `disciplineTag` 和 `topicTags`；
- 确认按钮固定在候选区域的稳定位置。

### 8.2 更新期间

当用户要求调整：

1. `candidateUpdateStatus = updating`；
2. 旧候选继续显示并可阅读；
3. 确认按钮禁用；
4. 点击触发后立即显示生成中反馈；AI 回复随后实时流式显示；
5. 新候选完整生成并通过校验后原子替换；
6. 旧候选标记 `superseded`；
7. 更新失败时恢复 `idle`，旧候选保持 current。

不得先清空右侧大纲，也不得在半段 Markdown 上允许确认。

### 8.3 可调整内容

用户可通过自然语言调整：

- 课程主线；
- 模块顺序；
- 增删模块或课节；
- 课节粒度；
- 关注重点和排除范围；
- 学科标签和主题标签；
- 面向任务、作品或理解的侧重。

系统不重新展示旧字段表单。

### 8.4 候选后对齐动作

候选产生后对话保持开放。每个用户调整回合先由 AI 判断更新动作，该动作只控制系统如何写入候选，不限制用户能讨论什么：

- `clarify`：用户意图或边界尚不清楚，只继续自然对话，右侧候选保持不变；
- `regenerate`：目标、受众、范围或全局主线变化，从完整对话与当前候选重新组织整版；
- `patch`：变更可局部落实，在保证整体连贯的前提下保留未涉及模块，并生成一个新的完整候选版本。

动作判断与自然语言回复分离；不得要求教学设计对话输出隐藏 JSON。任何 `regenerate` 或 `patch` 都必须经过完整候选校验和版本写入，不能直接修改已保存候选正文。

## 9. 阶段五：确认正式大纲

### 9.1 确认前校验

确认必须同时满足：

- 会话状态允许确认；
- 当前无候选更新任务；
- candidateId 等于会话最新 currentCandidateId；
- Markdown 可解析出课程标题、模块和至少一个课节；
- 课节标题非空且解析后 ID 唯一；
- `disciplineTag` 恰好一个；
- `topicTags` 为一至三个；
- 当前候选未被确认；
- 幂等键未对应另一笔不同确认。

### 9.2 原子确认事务

确认操作必须一次完成：

1. 锁定会话及 current candidate；
2. 解析 Markdown；
3. 创建 `Course`；
4. 创建 `OutlineVersion v1`；
5. 创建全部 `LessonDefinition`；
6. AI 在满足先修条件的候选课节集合内生成初始 `recommendedLessonId` 建议；
7. 标记候选和会话为 confirmed；
8. 写入领域事件；
9. 提交 Repository transaction。

任一步失败：

- 不暴露半个 Course；
- 会话恢复 active；
- current candidate 保持可确认；
- 返回稳定错误码和可重试提示。

### 9.3 幂等性

- 同一 sessionId + candidateId 重复确认返回同一 courseId；
- 不重复创建 OutlineVersion 或 LessonDefinition；
- 已被新候选替代的 candidateId 返回 `candidate_stale`；
- 已确认会话不能再发送普通创建消息。

## 10. 正式课程与课程单元列表

### 10.1 Course

```ts
type Course = {
  id: string;
  title: string;
  courseMode: CourseMode;
  disciplineTag: string;
  topicTags: string[];
  currentOutlineVersionId: string;
  lessonDefinitionIds: string[];
  completedLessonIds: string[];
  recommendedLessonId?: string;
  status: 'active' | 'closed';
  createdAt: string;
  updatedAt: string;
};
```

### 10.2 OutlineVersion

```ts
type OutlineVersion = {
  id: string;
  courseId: string;
  version: number;
  sourceSessionId: string;
  sourceCandidateId: string;
  outlineMarkdown: string;
  disciplineTag: string;
  topicTags: string[];
  creationContextSummary: string;
  createdAt: string;
};
```

OutlineVersion 不可变。后续调整课程大纲时创建新的 adjustment OutlineSession 和新版本。

### 10.3 LessonDefinition

```ts
type LessonDefinition = {
  id: string;
  courseId: string;
  outlineVersionId: string;
  moduleId: string;
  moduleTitle: string;
  title: string;
  description: string;
  coreKnowledgePoints: string[];
  order: number;
  status: 'not_started' | 'in_progress' | 'abandoned' | 'completed';
};
```

规则：

- ID 从确认版本和结构位置稳定派生或持久化生成；
- 所有已确认课节立即可点击；
- 系统只标记“推荐下一课”，不锁定其他课节；
- 没有 Review 时默认推荐大纲顺序中的第一个非放弃课节；
- 推荐候选只包含 `not_started` 和 `in_progress`，明确排除 `abandoned` 与 `completed`；
- 课程单元列表不包含课节正文；
- `coreKnowledgePoints` 必须从所属确认版大纲解析，不得由页面临时生成或另存一套可漂移文案；
- 点击未学习课节时先打开课节导航弹窗，此时不创建 LessonSession；
- 用户在导航弹窗点击“开始学习”后才创建对应 LessonSession；
- 点击已完成课节时直接打开只读课节记录，不重新创建主学习会话；
- 同一 LessonDefinition 在完成前最多只有一条原始学习会话：暂停学习时保持可写；有有效证据后放弃时冻结，恢复时解除同一会话冻结；无有效证据时放弃则删除空会话；课节完成后原始会话永久只读，之后才可创建补充学习会话。
- 原始学习会话首次创建时绑定当时的 `lessonDefinitionId` 与 `outlineVersionId`，此绑定在会话整个生命周期内不可改写。

### 10.4 课节点击分流

所有课节按钮整体可点击，系统按课节状态分流：

- `not_started`：打开课节导航弹窗；
- `in_progress`：统一显示为“学习中”；暂停学习后再次进入时恢复当前原始学习会话；
- `abandoned`：显示“已放弃”及“恢复学习”操作；若存在已冻结会话和阶段 Review，则先打开恢复学习导航，用户确认后解除原始会话冻结；
- `completed`：打开课节记录页。

课节生命周期规则：

- 所有前端文案、后端命令和设计文档统一使用“暂停学习”，其他退出表述不得作为业务术语；
- 暂停学习保持 `in_progress`，停止计时但不冻结原始会话；下次返回同一条可写会话，不生成 Review；
- 手动点击“暂停学习”、关闭页面、离开课程页和网络断开均触发 `PauseLessonSession`；
- 页面进入后台时立即暂停计时并保存当前位置，回到前台后自动恢复计时；关闭、离页或断线后不会自动恢复，须再次进入课程；
- 暂停原因只用于恢复与诊断，可区分 `manual`、`page_leave`、`background`、`disconnect`，但用户可见状态统一为“学习中”；
- 同一原始学习会话任一时刻只能由一个页面实例持有写入权；只有该窗口可以发送消息、接收 AI 回复并累计实际学习时长；
- 其他标签页、窗口或设备再次打开同一课节时默认只读，并提示“本课正在其他窗口学习”；只读窗口持续同步最新会话内容，但不启动第二条 AI 流或第二个计时器；
- 用户点击“切换到此窗口”后，系统原子转移写入权；新窗口接管成功后方可输入和计时，旧窗口立即停止计时、取消输入资格并转为只读；
- 写入权转移不得创建新 LessonSession，不得复制消息，也不得重置当前教学位置；并发接管请求必须串行化，最终只能有一个成功持有者；
- 课程发布新版大纲后，暂停或已放弃课节仍恢复其原 `LessonDefinition`、原 `OutlineVersion` 和原始学习会话，不得静默迁移到新版课节；
- 若当前大纲已调整、拆分、替换或移除原课节，恢复导航必须显示原会话版本与当前大纲版本的差异，并提供“恢复学习”及返回当前大纲选择替代课节的路径；
- 用户选择当前大纲中的替代课节时，按该新版 `LessonDefinition` 开始新的课节；该操作不恢复、不迁移也不覆盖旧会话，旧课节的 Review 永远归属于原课节定义和原大纲版本；
- 会话首次出现以下任一内容时写入不可逆的 `evidenceCheckpoint`：AI 已完整输出实质知识讲解；用户对热身、理解检查或教学问题作出实质回答；用户提出与本课知识相关的具体问题、判断或反思；
- 欢迎语、课程导航、流程说明、无知识信息的简短确认、仅提出问题但尚无用户回答、停止生成或技术中断的残缺 AI 输出，以及页面停留、按钮点击和时长，不得写入 `evidenceCheckpoint`；
- `evidenceCheckpoint` 是保留会话的最低语义证据，不代表知识点已经掌握，也不能代替课程闭环所需的掌握证据；
- 后端不得用消息字数、消息数量或停留时长推断该检查点；语义判定无法确定时按已有证据处理并保留会话，避免误删；
- 实际学习时长由多个不可重叠的计时区间累加；只有前台可见、持有会话写入权且未暂停的窗口能够开启区间，暂停、后台、断线、离页、放弃和写入权转移均须原子关闭当前区间；
- 有有效证据的会话在暂停、放弃和恢复之间保留累计时长；最终完成时，以该原始会话全部有效区间之和写入完成事实，不按恢复次数重复统计；
- 已放弃未完成期间，累计时长仅在所属课节记录中可见，不进入已完成学习时长、学习日历或周报；最终闭环后按最终完成日期一次性进入这些完成口径；
- 无有效证据而删除空会话时同步丢弃其短暂停留时长；恢复到 `not_started` 后从零开始；
- 教学未闭环时点击“结束本课”等同于放弃课节并停止计时；已有有效教学或互动证据时冻结当前会话并生成或更新阶段 Review，尚无有效证据时删除已创建的空会话且不生成 Review；两者均切换为 `abandoned`；
- 从未开始即放弃，以及开始后尚无有效证据即放弃，恢复时都直接回到 `not_started`；只有存在有效证据、冻结会话和阶段 Review 的放弃课节，才进入恢复导航，并在用户点击“恢复学习”后解除原始会话冻结、切换为 `in_progress`；
- 放弃和恢复均不得删除或改写确认版大纲及既有学习对话；每个课节始终最多只有一份 Review；
- Review 使用稳定 `reviewId`：多次放弃时，新阶段内容综合当前 Review 与新增对话后，在临时区域完整生成，再原子覆盖同一 ID；失败时保留旧内容；
- 完整闭环时，最终课时 Review 综合当前 Review 与完整原始会话后原子覆盖同一 `reviewId`；覆盖成功后只保留最终 Review，课节才进入 `completed`；
- 用户确认闭环结束时，后端先持久化不可变的结束快照与结束意图，立即停止计时、冻结原会话，并进入内部 `closing` 处理态；`closing` 不是新的用户可见课节状态；
- 最终 Review 必须使用该结束快照和同一 `reviewId` 幂等生成；只有原子写入成功后才清除结束意图、把课节切换为 `completed`、产生完成事实并弹出 Review；
- 最终 Review 生成失败时，原会话保持冻结，已有阶段 Review 保持原样，不产生完成事实，也不进入学习日历、周报或后续课节继承上下文；
- 失败页面提供“重新生成 Review”和“恢复学习”：前者复用同一结束快照幂等重试，不重复计时或复制对话；后者取消结束意图、解除原会话冻结并回到 `in_progress`；
- 结束意图和关闭进度必须持久化；进程或服务重启后能够自动继续或由用户重试，不得将课节永久留在不可恢复状态；
- 最终 Review 生成不依赖课程页保持打开；用户仍在课程页时成功后立即弹出完整 Review，用户已离页、关闭或断线时仍继续归档，并在下次进入应用时提供一次“课时 Review 已生成”提示；
- 点击异步完成提示直接打开该课节双 Tab 记录并默认定位“课时 Review”；关闭 Review 弹窗只关闭展示，不撤销完成事实、不删除 Review，也不影响课程推荐状态；
- 单课 Review 弹窗只提供“查看课节记录”和“返回课程大纲”，不展示 AI 推荐下一课、“查看主题总结”或任何 Review 编辑操作；
- 最终课时 Review 原子写入成功后即永久不可变：用户、AI、补充学习和后台任务均不得修改、覆盖或重新生成；“重新生成 Review”只用于首次成功写入前的失败重试；
- 补充学习创建新的独立对话并完整保留，但不生成新的课时 Review，也不修改原始学习对话、最终课时 Review、课节完成事实或课程总 Review。

课程达到关闭条件后，课程学习档案页面显示“查看主题总结”，并由 AI 生成课程总 Review。课程总 Review 与任何单课 Review 分离，至少包含：

1. 主题核心知识线索总结；
2. 学习者总体学习表现；
3. 基于本课程课节 Review 材料生成的推荐扩展课程。

课程总 Review 使用课程关闭时锁定的输入快照：最终确认版大纲、已完成课节的最终 Review，以及已放弃课节当时现存的阶段 Review；无 Review 的放弃课节只作为未学习事实体现。它不读取或拼接原始及补充学习对话全文。其入口仅属于课程学习档案页面，不进入单课 Review 弹窗。

课程先关闭，再异步生成课程总 Review；总 Review 成功与否不影响课程关闭。失败时课程档案显示生成失败状态和“重新生成主题总结”，并使用同一关闭输入快照幂等重试。首次成功原子写入后，课程总 Review 永久不可修改或再次生成；由于课时最终 Review 同样不可变且补充学习不属于输入，因此不存在同步更新机制。

课程关闭条件按关闭前最后一个确认版大纲计算：所有有效课节均须为 `completed` 或 `abandoned`，其中 `abandoned` 不阻止关闭；任何 `not_started` 或 `in_progress` 均阻止关闭。全部有效课节均为 `completed` 时，在最后一课最终 Review 成功后自动关闭。若存在 `abandoned`，课程只进入派生的“可关闭”条件，仍保持 `active`；课程档案显示“结束课程”和已放弃课节清单，学习者确认“关闭后无法恢复”后才切换为 `closed`，确认前仍可恢复。被新版明确移除或替换的旧课节不参与条件；新版明确沿用且已完成的旧课节可直接满足对应条件。课程关闭后锁定最终确认版大纲；`closed` 是不可逆状态，不得再次创建 adjustment OutlineSession、发布新大纲版本、追加课节、恢复已放弃课节或撤回关闭。推荐扩展课程只能创建新的 Course，并保存其 `sourceCourseId`，不能修改原课程。

前后端共享动作口径：

- `PauseLessonSession`：暂停学习，停止计时，保持会话可写，并携带暂停原因；
- `ResumeLessonSession`：恢复暂停的原始学习会话；
- `TakeOverLessonSession`：将同一原始学习会话的排他写入权原子转移到当前页面实例，并使原持有窗口停止计时、转为只读；
- `AbandonLesson`：将课节标记为已放弃；有有效证据时冻结原会话并生成或更新阶段 Review，无有效证据时删除空会话且不生成 Review；
- `RestoreAbandonedLesson`：解除原始学习会话冻结并恢复为学习中；
- `FinalizeLesson`：持久化结束快照与结束意图，冻结会话并启动最终 Review 关闭事务；
- `RetryFinalReview`：使用既有结束快照和同一 `reviewId` 幂等重试最终 Review；
- `ResumeClosingLesson`：取消失败的结束意图、解除原会话冻结并恢复为学习中；
- `CloseCourse`：在存在已放弃课节的可关闭课程中，校验确认信息后执行不可逆关闭并锁定输入快照；全课完成时由系统自动触发同一关闭事务；
- `RetryCourseReview`：课程总 Review 首次成功前，使用课程关闭时的固定输入快照幂等重试；成功后该动作永久失效。
- `DeleteCourse`：撤销会话写入权和计时，原子级联删除课程及关联数据，撤销历史/画像事实并触发投影与画像重算；不支持软删除、回收站或恢复。

课节导航弹窗至少展示：

- 所属课程与模块；
- 课节名称；
- 来自确认版大纲的核心知识点；
- “开始学习”和“返回课程大纲”操作。

有有效证据的已放弃课节使用恢复导航。该导航只展示“已学习的核心知识点”和“待完成的核心知识点”，主要操作统一为“查看记录”和“恢复学习”；阶段 Review 正文、累计时长和会话详情不在导航重复展示。“查看记录”打开冻结原会话与当前阶段 Review 的只读双 Tab；“恢复学习”解除同一原会话冻结。阶段记录不允许发起补充学习，也不进入全局历史、学习日历、周报或其他课节的继承上下文。

仅打开或关闭弹窗不产生学习历史、会话或完成事实。用户点击“开始学习”后，系统才创建独立学习会话并进入实时学习页。

课节记录页不是“只查看 Review”。页面顶部固定提供两个同级 Tab：

1. `学习对话`：展示该课节已归档的原始主学习对话，默认只读；
2. `课时 Review`：展示该课节的权威 Review Markdown。

完成态入口统一使用“点击查看课节记录”，不使用“查看 Review”或其他变体暗示只有单一内容。若用户希望继续讨论，应从课节记录页创建新的补充学习会话，不改写原始对话。恢复已放弃课节只解除原始学习会话冻结，不创建补充学习会话或其他新会话。

### 10.5 确认后页面

页面展示：

- 课程标题；
- `disciplineTag`；
- 一至三个 `topicTags`；
- 当前大纲版本；
- 按模块分组的全部课节按钮；
- 每节课的核心知识点摘要，可在课节卡内直接阅读；
- 当前 `recommendedLessonId` 对应课节的“推荐下一课”标记；
- 活跃课程的修改大纲入口；
- 返回首页和课程表入口。
- 独立危险操作区中的“删除课程”入口。

不展示：

- 旧建档字段；
- 思维模式标签；
- 自动生成的课节正文；
- 强制顺序或锁定提示。

“删除课程”不等于关闭或归档。它必须通过风险确认弹窗执行，确认动作仅为“永久删除”，不要求输入课程名称；成功后该课程与所有关联档案、会话、Review、排期、历史事实和画像证据均被永久删除，并触发历史统计与学习画像从剩余事实重新计算。

### 10.6 修改正式大纲

状态为 `active` 的正式课程页提供“修改大纲”入口。`closed` 课程不显示也不接受修改大纲命令。进入修改后创建 `kind = "adjustment"` 的新 `OutlineSession`，并绑定：

- `sourceCourseId`；
- 当前 `OutlineVersion`；
- 学习起点评估摘要；
- 已完成课节的 Review Markdown；
- 当前未完成课节及其排期引用。

修改过程继续采用左侧 AI 对话、右侧完整候选大纲的同类工作台，不回到字段表单。AI 每次调整都生成完整的新候选大纲，不直接修改当前确认版，也不只返回无法独立确认的局部补丁。

右侧候选必须清楚标记课节相对当前版本的影响：保留、调整、拆分、新增或移除。已完成课节允许在新版本中被引用和重新编排，但其既有 `LessonDefinition`、学习对话与 Review 永久保留，不得删除或改写。

用户点击“确认并发布大纲 vN”后：

1. 创建新的不可变 `OutlineVersion`；
2. 为新版本生成对应的 `LessonDefinition` 列表；
3. 将 `Course.currentOutlineVersionId` 切换到新版本；
4. 保留全部旧版本、旧课节定义和历史学习记录；
5. 对受影响的未完成排期给出明确清单，交由计划流重新规划，不静默替换；
6. 重新计算当前可推荐的未完成且未放弃课节；已放弃课节保留历史状态，但不进入推荐候选。

已经开始的课节采用版本绑定规则：其原始学习会话继续绑定开始时的旧 `LessonDefinition` 与旧 `OutlineVersion`。新版大纲不得迁移或覆盖该会话；恢复旧课节时必须提示版本差异。用户也可以放弃恢复并从当前大纲开始替代课节，两者作为不同的课节事实分别保存。

取消、退出或 AI 生成失败时，当前正式课程仍停留在原确认版本；调整会话可稍后恢复。

## 15. 错误处理

至少定义：

| 错误码                     | 说明                 | 用户行为               |
| -------------------------- | -------------------- | ---------------------- |
| `topic_required`           | 主题为空             | 保留输入并提示         |
| `session_not_found`        | 会话不存在           | 返回首页并刷新列表     |
| `session_closed`           | 会话已确认/放弃      | 打开正式课程或只读记录 |
| `message_required`         | 消息为空             | 不发送                 |
| `generation_in_progress`   | 当前已有生成任务     | 保持当前界面           |
| `ai_unavailable`           | AI Provider 不可用   | 保留输入并提供重连     |
| `candidate_invalid`        | 候选结构或标签不合法 | 保留旧候选并重试生成   |
| `candidate_stale`          | 确认的不是最新候选   | 刷新当前候选           |
| `confirmation_in_progress` | 正在确认             | 禁止重复提交           |
| `confirmation_failed`      | 事务失败             | 恢复可确认状态         |

AI 流式中断时，未完成 assistant 消息可标记 failed；不得把半段大纲保存为 current candidate。

创建会话或发送消息在服务端受理前失败时，前端必须移除思考占位、恢复原输入并提供可重试提示；不得把未受理的本地消息伪装为已持久化消息。

## 16. 功能验收

### 16.1 主路径

- 输入主题后只创建 OutlineSession；
- 点击有效主题后无需等待接口完成即可进入建档页，并立即看到起始说明、原始主题和思考占位；
- 首页输入自动成为第一条对话消息，并完成第一轮 AI 回应；
- 三轮前无候选生成或跳过入口；三轮后用户可继续评估；
- AI 生成 Markdown 候选和正确数量标签；
- 用户可多轮调整并保留旧候选历史；
- 更新期间旧大纲可读、确认禁用；
- 每次消息发送和候选生成点击都在服务端受理前提供即时反馈；失败时输入与旧候选不丢失；
- 确认后一次性创建正式课程和全部课节定义；
- 页面按模块渲染所有可点击课节；
- 每个课节展示从确认版大纲解析出的非空核心知识点；
- 点击未学习课节先显示知识点预览，确认开始前不创建会话；
- 点击已完成课节进入包含“学习对话 / 课时 Review”双 Tab 的只读课节记录；
- 初始推荐只能来自满足先修条件的课节集合，且不自动启动课节。

### 16.2 恢复路径

- 评估中退出后可从首页恢复；
- 有候选时退出后仍显示最新候选；
- AI 失败后输入和旧候选不丢失；
- 服务重启后会话可恢复；
- 重复确认返回同一课程。

### 16.3 玩法壳边界

- 八个玩法壳拥有唯一且稳定的 `courseMode`；
- 八个玩法壳均可发起完整 OutlineSession 和正式课程创建；
- 不继承旧项目玩法内部逻辑；
- 除阅读研讨材料上传外，不增加显式字段或专属表单；
- 玩法意图不得成为课程模块、阶段、课节类型、固定 Prompt 或执行清单；
- 全部玩法共享同一 OutlineSession、学习、Review、计划流和课程关闭规则；
- 详细玩法身份与视觉规则见《八大玩法功能规则》。

### 16.4 负向断言

- 确认前不存在 Course；
- 不出现旧建档字段；
- 不出现思维模式；
- 标签不是用户表单字段；
- 旧候选不能被确认；
- 半段流式 Markdown 不能成为候选；
- 不批量生成课节正文；
- 不锁定任意课节；
- 新项目不读取旧数据目录。

## 17. 后续接口

本流程结束后，正式课程继续进入：

```text
课程单元列表
→ 用户自由选择任意课节
→ 未学习课节先展示确认版大纲中的核心知识点预览
→ 用户点击开始学习
→ 创建独立 LessonSession
→ 继承评估摘要、确认版大纲和已完成 Review
→ 实时 AI 学习对话
→ 暂停学习：保留原始会话并停止计时，恢复时继续同一会话
→ 未闭环结束：标记已放弃；有有效证据时冻结原会话并原子更新阶段 Review，无有效证据时删除空会话且不生成 Review
→ 恢复已放弃：解除原始会话冻结并回到学习中
→ 完整闭环：持久化结束意图并冻结会话 → 最终 Review 原子覆盖同一 reviewId → 成功后才产生完成事实、更新课程记忆和推荐课节
→ 再次打开已完成课节时进入双 Tab 课节记录
```

该部分由后续《课程学习与 Review 功能逻辑规则》单独定义。
