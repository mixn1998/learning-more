# 主页与九模式建档工作台整合设计

## 1. 文档目的

本文固化标准模式与八大玩法在主页、OutlineSession 创建和建档工作台中的最终界面关系。本文只定义界面结构、交互边界和共享实现方向，不增加课程生成方法清单，也不改变学习起点评估、大纲确认和正式课程创建规则。

## 2. 已确认决策

1. 采用“整合方式 1”：主页完整复用大间距图标玩法列表，不保留旧紧凑卡片样式。
2. 主页玩法栏共有九张同规格入口卡：标准模式在最上方，下面依次为八大玩法。
3. 不设置独立的“重置”按钮；“标准模式”卡本身就是恢复 `standard` 的入口。
4. 用户在主页选定模式并提交主题后，进入该 OutlineSession 的专属建档页面。
5. 建档页面删除左侧模式选择栏和重复的主题输入框，主体横向铺满。
6. 八大玩法不再通过同一页面内的 Tab 或侧栏切换来演示，而是提供八张独立路径样稿。
7. 标准模式与八大玩法在生产实现中共用同一个建档工作台，仅视觉变量和整体玩法意图不同。

## 3. 主页信息架构

### 3.1 桌面端结构

```text
共享顶部与 AI 状态
↓
“想学什么”输入区
↓
┌────────────────┬──────────────────────────────┐
│ 九模式入口栏   │ 本周课程表、今日学习等原主页内容 │
└────────────────┴──────────────────────────────┘
```

主页课程表、今日学习、历史入口和状态监控的既有组件关系保持不变。九模式入口栏只负责创建入口选择，不参与课程表筛选。

### 3.2 九张入口卡顺序

1. 标准模式；
2. 头脑风暴；
3. 论证交锋；
4. 案例研习；
5. 商业洞察；
6. 流程拆解；
7. 决策分析；
8. 交叉探索；
9. 阅读研讨。

标准模式属于通用课程入口，不计入“八大玩法”。

### 3.3 入口卡统一规格

九张卡使用完全一致的：

- 图标容器尺寸；
- 卡片高度和内边距；
- 标题、副标题字号；
- 圆角、描边与选中阴影；
- 键盘焦点和点击热区；
- 选中、悬停和禁用状态结构。

标准模式使用全项目陶土橙作为识别色，入口文案确定为：

```text
标准模式
系统全面学习掌握
```

八大玩法使用各自识别色。选中卡的描边、图标底色和顶部输入区强调色随当前模式变化，而不是全部使用统一黄色。

### 3.4 左栏高度规则

- 桌面端九张入口卡在左栏可视高度内均匀铺满；
- 左栏不出现内部滚动条；
- 右侧课程内容超出时可独立滚动；
- 左栏可保持粘性跟随，但不得遮挡共享顶部；
- 主页整体仍维持左侧入口栏、右侧课程表的原布局关系。

### 3.5 模式选择行为

主页初始选中“标准模式”。点击任一入口卡时：

1. 只更新前端待提交的 `courseMode`；
2. 同步输入框标题、示例、按钮文案和识别色；
3. 不创建 OutlineSession；
4. 不创建正式 Course；
5. 不写入历史、日历或画像事实；
6. 保留用户已经输入但尚未提交的主题文本。

点击“标准模式”即恢复 `courseMode = standard`，不使用“重置”字样，也不清空主题。

### 3.6 阅读研讨特例

选择阅读研讨后，“想学什么”输入区额外展开材料上传入口，支持 PDF、TXT、Markdown 等可解析文本。切换到其他模式时：

- 上传区隐藏；
- 已暂存文件在当前前端页面生命周期内保留，切回阅读研讨可恢复；
- 非阅读模式提交时不携带该文件；
- 页面刷新或显式移除材料后，按普通临时文件规则清理。

## 4. 从主页到建档工作台

### 4.1 提交事务

用户提交主题时，前端发送：

```ts
type StartOutlineSessionCommand = {
  courseMode: CourseMode;
  initialTopic: string;
  readingMaterialDraftId?: string;
  idempotencyKey: string;
};
```

后端成功创建 OutlineSession 后，进入：

```text
/outline-sessions/:outlineSessionId
```

页面根据 OutlineSession 中保存的 `courseMode` 渲染视觉状态，不依赖可修改的 URL 查询参数作为权威来源。

### 4.2 模式切换边界

OutlineSession 创建后，建档工作台不提供模式切换栏。用户希望换模式时：

1. 返回主页；
2. 选择新的模式；
3. 创建新的 OutlineSession。

旧 OutlineSession 按既有规则保留为可恢复会话或由用户显式放弃。不得原地改写旧会话的 `courseMode`、对话或候选大纲。

## 5. 全宽建档工作台

### 5.1 删除的组件

进入 OutlineSession 后删除：

- 左侧“选择玩法”栏；
- 顶部重复的主题输入框；
- 页面内八玩法 Tab；
- 独立“重置模式”按钮。

### 5.2 页面头部

页面头部只显示：

- 当前模式名称和视觉识别；
- 初始主题摘要；
- OutlineSession 保存状态；
- AI 接口状态；
- 返回主页入口。

初始主题不是固定字段表单。用户需要修正主题、目标或范围时，直接在 AI 对话中说明，AI 据此更新候选大纲。

### 5.3 主工作区

桌面端横向铺满可用内容宽度：

```text
┌──────────────────────────┬────────────────────────────┐
│ AI 学习起点评估与调整对话 │ 当前完整候选大纲 Markdown  │
└──────────────────────────┴────────────────────────────┘
```

- 两栏共用页面宽度，不再为玩法选择栏预留空间；
- AI 内容无消息气泡和发送者标签；
- 用户回答使用右侧气泡；
- 候选大纲可以独立阅读，但不通过字段表单直接编辑；
- 大纲确认按钮位于大纲栏稳定操作区；
- 阅读研讨在头部或大纲栏显示材料解析状态与章节映射，不恢复左侧玩法栏。

移动端恢复自然单列：对话在前、大纲在后，不做左右内部滚动。

## 6. 标准模式与八大玩法的合并方式

### 6.1 生产实现

只实现一个共享的 `OutlineSessionWorkspace`。它读取：

- OutlineSession；
- `courseMode`；
- 视觉 Token；
- 可选的阅读材料解析状态；
- 当前候选 OutlineVersion。

标准模式使用中性内容意图和陶土橙视觉；八大玩法使用各自整体玩法意图与视觉变量。所有模式共享：

- 会话保存；
- 学习起点评估；
- 渐进式 AI 对话；
- 候选大纲版本；
- 用户确认；
- 错误恢复；
- 正式 Course 原子创建。

不得为九种模式复制九套前端逻辑或后端流程。

### 6.2 视觉样稿

视觉审查保留九个状态：

- 现有标准建档页调整为共享工作台的标准模式样稿；
- 八大玩法各自生成一张全宽建档样稿。

建议目录：

```text
UI视觉预览/02-课程创建与大纲/
├─ 标准模式建档.html
├─ 正式课程大纲.html
├─ 修改大纲.html
└─ 八大玩法建档/
   ├─ 头脑风暴.html
   ├─ 论证交锋.html
   ├─ 案例研习.html
   ├─ 商业洞察.html
   ├─ 流程拆解.html
   ├─ 决策分析.html
   ├─ 交叉探索.html
   └─ 阅读研讨.html
```

新样稿验证完成后，删除旧的“单页左栏切换八玩法”样稿，不保留冗余版本。

## 7. 可访问性与响应式规则

- 九张入口卡必须是可聚焦按钮，不使用只有视觉效果的 `div`；
- 选中状态同时使用描边、背景和语义属性，不只依赖颜色；
- `aria-pressed` 或等价语义反映当前模式；
- 键盘 Enter 和 Space 可选择模式；
- 移动端九张卡改为两列自然流布局，不在狭窄视口强制等分满高；
- 阅读材料上传入口需提供文件类型、解析状态和错误说明文本。

## 8. 验收条件

1. 主页出现九张同规格入口卡，标准模式位于第一张且默认选中。
2. 选择任一模式后，顶部输入区文案和识别色同步变化，但没有任何会话或历史写入。
3. 点击标准模式能恢复 `standard` 且不清空主题。
4. 阅读研讨选择态显示材料上传入口，其他模式不显示。
5. 提交后进入全宽建档工作台，页面不存在玩法选择栏和重复主题输入框。
6. 八张玩法样稿均可独立打开，且只展示对应玩法状态。
7. 标准模式和八大玩法共享同一工作台结构，不产生九套流程逻辑。
8. 桌面端无横向溢出，左侧九模式栏无内部滚动条。
9. 旧切换式玩法样稿在新样稿验证完成后彻底移除。

## 9. 非目标

- 本设计不修改 AI 课程生成方法；
- 不为玩法增加 Prompt 方法清单、固定模块或固定步骤；
- 不改变 OutlineSession、Review、课程关闭或正式学习状态机；
- 不在本轮实现生产前后端路由，只调整设计口径和静态视觉样稿。
