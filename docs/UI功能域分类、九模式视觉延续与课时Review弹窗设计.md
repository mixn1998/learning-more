# UI 功能域分类、九模式视觉延续与课时 Review 弹窗设计

## 1. 文档目的

本文固化三项已确认设计：

1. UI 样例资源按功能域与课程生命周期重新分类；
2. 标准模式与八大玩法采用渐进式身份延续；
3. 最终课时 Review 生成成功后弹出完整 Review。

本文定义目标目录、视觉强度、弹窗行为和迁移验收条件。它不修改课程生成方法、Review 内容合同或课程状态机。

## 2. 分类原则

UI 样例按“功能域 + 课程生命周期”组织，不再按制作批次、页面类型或临时组合关系命名。

### 2.1 拆分与合并规则

- 不同产品路由或不同功能责任拆成独立文件；
- 同一路由中的加载、空状态、错误状态和操作弹窗可以保留在同一交互样例中；
- 同一组件的九模式视觉变体共用结构，不复制九套业务逻辑；
- 文件名不使用“新版”“最终版 2”“修改版”等版本词；
- 每个目标页面只保留一个当前有效样例；
- 新样例验证完成、索引和相互链接更新后，删除被替代的旧混合文件。

## 5. 渐进式九模式身份延续

### 5.1 核心原则

`courseMode` 的视觉身份贯穿课程生命周期，但随任务从“选择与创建”进入“学习与归档”逐步收敛：

| 生命周期 | 身份强度 | 主要载体 |
| --- | ---: | --- |
| 主页入口 | 强 | 整卡选中、图标、输入区强调色 |
| 建档与候选大纲 | 强 | 页面头部、用户气泡、大纲强调线 |
| 修改大纲 | 中强 | 模式标识、用户气泡、新版本强调 |
| 课节导航 | 中 | 模式图标、顶部细线、主操作按钮 |
| 正式学习对话 | 中弱 | 顶部模式标识、用户气泡、局部进度强调 |
| 课时 Review 弹窗 | 弱 | 模式徽标、细强调线、章节锚点 |
| 课节记录与课程总 Review | 弱 | 稳定模式标识和少量锚点 |
| 历史与日历 | 最弱 | 小型图标或模式名称，不改变正文底色 |

### 5.2 模式身份与状态语义分离

- 模式色回答“这门课程以什么体验创建”；
- 状态色回答“当前是否完成、警告、失败或只读”；
- 成功、警告、错误、已放弃和只读状态必须使用全局状态色；
- 不得用模式色代替状态色；
- AI Markdown 正文、代码、表格、知识图谱等按内容语义渲染，不因玩法大面积换色。

### 5.3 共享主题注册表

所有页面从同一注册表读取视觉身份：

```ts
type CourseModeTheme = {
  mode: CourseMode;
  label: string;
  subtitle: string;
  icon: string;
  accent: string;
  accentDark: string;
  tint: string;
  motif: string;
};
```

- 标准模式使用陶土橙；
- 八大玩法使用已确认的各自识别色；
- 页面不得复制颜色常量或自行解释模式；
- Review Markdown 不写入颜色、图标或 CSS 标识；渲染层根据所属 Course 的 `courseMode` 应用低强度主题。

### 5.4 生命周期继承

- 修改大纲会话继承原 Course 的 `courseMode`，不可更换；
- 正式课节、暂停与恢复会话继承 Course 模式；
- 补充学习会话继承 Course 模式，但不修改 Review；
- 课时 Review、课节记录和课程主题总 Review 根据所属 Course 渲染同一模式身份；
- 历史、日历和周报只显示轻量来源标识，不根据单次玩法选择推断用户人格。

## 6. 完整课时 Review 弹窗

### 6.1 触发条件

仅当最终课时 Review 首次原子写入成功、课节已切换为 `completed` 后弹出。Review 仍在生成、写入失败或课节未完成时不得显示成功弹窗。

### 6.2 页面结构

```text
遮罩层
└─ 大尺寸完整 Review 弹窗
   ├─ 固定头部
   │  ├─ 已完成 · 课时 Review
   │  ├─ 课节名称
   │  ├─ 所属课程、课程模式
   │  └─ 生成时间、永久只读
   ├─ 可滚动 Markdown 正文
   │  ├─ 本课总结
   │  ├─ 知识图谱或学科适配结构
   │  ├─ 核心思想
   │  └─ 学习表现评价
   └─ 固定底部操作区
      ├─ 返回课程大纲
      └─ 查看课节记录
```

弹窗展示已生成的完整权威 Markdown，不做摘要截断。Review 的内部表达仍由学科和真实教学证据决定，不强制固定知识图谱等栏目。

### 6.3 尺寸与滚动

- 桌面端宽度 `min(1080px, calc(100vw - 48px))`；
- 最大高度 `82vh`；
- 头部和底部操作区固定；
- 仅 Markdown 正文区域内部滚动；
- 弹窗不得造成页面横向溢出；
- 移动端占据接近全屏宽度，头部、正文和底部自然纵向排列。

### 6.4 视觉身份

- 使用低强度模式身份；
- 模式徽标、顶部细线和章节锚点可使用模式色；
- “已完成”使用全局成功色；
- “永久只读”使用全局只读色；
- 正文保持中性纸面和深墨色文字；
- 不使用整页模式色背景，不把 Review 做成玩法海报。

### 6.5 操作行为

弹窗只提供两个可见操作：

1. `返回课程大纲`：关闭弹窗并进入所属正式课程大纲；
2. `查看课节记录`：进入课节记录并默认选中“课时 Review”Tab。

不显示：

- 推荐下一课；
- 修改、纠错或重新生成 Review；
- 发起补充学习；
- 查看主题总结；
- 第三个“关闭”按钮。

键盘 Escape 与“返回课程大纲”等效；关闭弹窗不会撤销完成事实、删除 Review 或恢复学习会话。

### 6.6 离页完成

如果 Review 在用户离页后生成成功：

- 下次进入应用时只提示一次“课时 Review 已生成”；
- 提示不重复展示完整弹窗；
- 用户点击提示后直接进入课节记录的“课时 Review”Tab；
- 忽略提示不改变完成事实和 Review 归档。

## 7. 样例组织规则

- `正式课程学习会话.html` 负责生成中、失败重试和恢复学习状态；
- `课时Review弹窗.html` 专门展示最终 Review 已成功后的完整弹窗；
- `课节记录.html` 展示持久只读归档及学习对话/课时 Review 双 Tab；
- 三者通过链接模拟生命周期路径，但不在单个 HTML 中堆叠三个独立路由；
- 每个样例文件顶部注明对应领域规则、产品路由和覆盖状态。

## 8. 迁移顺序

1. 创建新目录和 `README.md` 索引；
2. 先拆分现有混合文件，不改变已确认视觉内容；
3. 应用主页九模式入口和全宽建档工作台新设计；
4. 生成八张独立玩法建档样稿；
5. 应用渐进式身份延续到修改大纲、正式学习和 Review；
6. 新增完整课时 Review 弹窗；
7. 逐页进行浏览器交互、响应式、链接和控制台验证；
8. 更新所有文档链接和索引；
9. 删除已被替代的旧混合文件；
10. 全目录扫描，确认没有重复样稿和失效路径。

## 9. 验收条件

1. UI 样例目录按七个功能域和一个设计系统目录组织；历史功能域包含历史统计、学习日历和学习画像三个独立资源，三者使用同级三 Tab。
2. `README.md` 能从规则来源定位到唯一当前样例。
3. 不再存在将主页与历史、规划与周回顾、导航与课节记录混在同一文件的情况。
4. 九模式视觉身份在创建、修改、学习、Review 和历史中按强度逐步收敛。
5. 模式色与状态色不存在语义冲突。
6. 完整课时 Review 弹窗展示权威 Markdown，头尾固定、正文滚动。
7. Review 弹窗只有“返回课程大纲”和“查看课节记录”两个可见操作。
8. 八张玩法建档样稿、标准建档样稿和后续课程页面共享同一模式主题注册规则。
9. 新目录验证完成后，旧混合文件和切换式玩法演示被彻底移除。
10. 所有 HTML 无横向溢出、无控制台错误、无失效相对链接。

## 10. 非目标

- 不在本设计中实现生产 React 组件；
- 不改变 AI 生成 Review 的内容自由度；
- 不增加玩法专属 Review 模板；
- 不在本 UI 文档中另行修改历史统计与学习画像的数据定义；相关视觉必须遵守《历史统计与学习画像数据源定义清单》和《学习画像数据抓取与分析策略规则》；
- 不以视觉模式替代课程状态或学习证据。
