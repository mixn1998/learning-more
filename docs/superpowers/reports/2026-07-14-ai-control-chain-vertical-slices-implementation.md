# AI 控制链纵向切片实施验收报告

> 日期：2026-07-14
> 范围：课程创建、统一生成执行、计划流、周报、学习画像、下一课推荐、思维倾向证据链、正式课程教学控制链

## 1. 结论

本轮目标已按纵向切片落地。AI 的自由度放在教学、解释、追问、课程结构与画像叙事中；程序控制只负责输入真实性、任务终态、状态转换、来源引用、先修约束、候选版本和不可变产物。系统不使用 `TeachingScopeEnvelope`，不把玩法编译成输出模板，也不以固定占位内容伪造 AI 业务完成。

## 2. 已落地切片

### 2.1 课程创建与候选后对齐

- 首页输入作为第一条用户消息持久化，进入页面后自动显示，并由 AI 完成第一轮回应。
- 至少三轮完整对话后才开放候选生成；用户可继续更多轮。
- 候选生成读取真实主题、完整对话、材料摘录、课程模式关注点和当前候选。
- 候选 metadata 使用独立机器协议；内部会话 ID、轮次和消息 ID 不进入模型可见学习背景，Markdown 正文继续自由生成。
- 候选结构增加稳定 `modules -> lessonIds` 映射；旧候选读取时确定性迁移，不改写原始版本文件。
- 前端区分结构校验失败、生成超时和连接中断，不再把所有失败统称为“生成中断”。
- 候选后对话由独立计划器判断 `clarify/regenerate/patch`；该判断只控制更新动作，不限制讨论内容。
- `regenerate/patch` 自动生成新候选版本；失败时保留旧候选。

### 2.2 统一生成执行

- `GenerationExecution` 提供 submit、awaitTerminal、stream、cancel、recover。
- 业务模块只在真实任务终态后落业务结果；取消、超时、排队或部分输出不再被包装成成功。
- AI 场景注册表覆盖当前生产场景，架构 seam 通过公共接口暴露。

### 2.3 计划流、周报与学习画像

- 计划流预览读取真实课程、课节、先修、时间窗口、约束与已有排期，AI 输出严格解析为建议，用户确认后才写正式排期。
- 周报读取冻结事实快照和自然周语境，任务成功后才最终化。
- 学习画像读取冻结 manifest、候选证据与思维行为分析，成功后写版本，失败保留上一成功版本。

### 2.4 下一课推荐

- 课程确认、大纲调整和课节闭环后均可刷新推荐。
- 后端先按先修与完成状态建立 eligible 集合，AI 只能返回集合内 semantic key。
- 推荐只更新 `recommendedLessonId`，不自动创建或启动学习会话。

### 2.5 思维倾向证据链

- 教学观察产生开放语义 `ReasoningBehaviorEpisode`，保留是否由教学任务引出的 elicitation 语境。
- AI 在证据窗口内动态归纳维度并做多标签归类；逻辑、关联、发散、结构、隐喻都不是固定列。
- 后端确定性统计次数、占比、独立来源组、自发/引出、课程与课节覆盖。
- 分析结果幂等投影为 `thinking_tendency.<dynamic_dimension_id>` 候选证据，进入全局用户档案长线证据链，但不升级为永久事实。
- 学习画像按冻结输入消费这些候选证据；雷达图未纳入本轮 UI，数据链不依赖雷达图存在。

### 2.6 正式课程专项验收

- 教学智能体继续消费课程责任、当前课节、近期对话、状态账本、受控个性化和玩法关注点。
- 教学观察只记录可回溯局部事实；课程邻接探索记录为支线，不冒充本课完成。
- 教学状态账本维护覆盖、证据、误解、支线和返回锚点。
- 暂停、放弃、恢复、阶段 Review、最终 Review、课程 Review 均保持原子与不可变边界。
- 生产装配统一使用真实生成终态，不改变上述领域责任。

## 3. 数据治理与模块消费关系

```text
教学消息
  -> 教学观察
  -> 教学状态账本 / ReasoningBehaviorEpisode
  -> AI 动态维度与多标签归类
  -> 确定性统计快照
  -> 动态候选证据（全局用户档案）
  -> 冻结 PortraitInputManifest
  -> 学习画像版本
```

- InteractiveTeaching 拥有单会话教学行为与账本更新。
- GlobalUserProfile 拥有 Episode、动态维度、分类和长期分析快照。
- ProfileEvidence 通过公开 Episode 读取接口投影候选证据，不越界修改档案内部存储。
- LearningPortrait 只生成画像版本，不写回 `user_profile.*`。
- 前端可暂不展示思维图形，但后端完整保存来源、版本、统计与失效关系。

## 4. 验证结果

候选输出协议修复增量验证：20 个相关测试文件、89 项测试通过；服务端与前端类型检查、Contracts Schema/OpenAPI、一致性构建通过；真实 codex-cli 错误输出已固化为回放 fixture。运行实例已受控重载至 generation 5，Provider 状态为 ready。

- 全量 Vitest：181 个测试文件、616 项测试通过。
- 全仓类型检查：通过。
- ESLint：通过。
- Prettier：通过。
- OpenAPI 与共享 Zod schema：一致。
- 架构门禁：237 个 dataKey 通过，0 个越界导入。
- 全仓生产构建：通过；Vite 仅报告现有主 chunk 超过 500 kB 的非阻断警告。

## 5. 明确未做

- 不做思维倾向雷达图或固定轴 UI。
- 不把动态思维维度提升为固定数据库列、人格标签或能力评分。
- 不让玩法决定固定教学步骤、固定 Review 章节或大纲模板。
- 不让下一课推荐替用户启动课节。
