# Learning MORE 当前前端工作基础报告

> 评估日期：2026-07-13
> 评估口径：以当前工作区可运行代码、公开 HTTP 接口、自动化测试和 29 个现行 HTML 样稿为准
> 覆盖范围：`apps/web`、`packages/ui`、前端依赖的共享合同与服务端公开接口、`docs/UI视觉预览`

## 1. 结论

Learning MORE 已经具备正式建设产品前端的工程基础，不需要另起一套工程，也不需要重写现有交互程序。当前 React 前端已完成路由骨架、真实 API/SSE 接入、主要领域状态编排、幂等与版本保护基础，并且核心学习闭环和运行时自愈闭环已经通过真实浏览器端到端测试。

当前主要欠缺不是“有没有前端”，而是以下三类增量：

1. **视觉产品化**：把现有工程界面迁移为 29 个现行样稿定义的正式布局、组件、九模式视觉身份和统一 AI 内容排版；
2. **现有能力补接**：把后端已经公开、但前端尚未消费的接口和恢复状态接完整；
3. **跨层补齐**：为样稿已经定义、但当前 HTTP 层尚未公开的排期管理等操作补合同、接口和前端闭环。

因此，正确施工方式是“保留业务逻辑，替换视图层，补齐缺口”：先建立共享 React 设计系统和视觉回归门禁，再按业务纵向切片迁移。已通过测试的状态机、客户端和闭环不得因视觉迁移重写。

## 4. 当前前后端闭环覆盖

### 4.1 已形成真实闭环

以下能力已经有 React → HTTP/SSE → 服务端 → 持久化/读模型 → React 的真实浏览器证据，施工时只迁移视图，不重做业务程序：

- 建档评估、候选生成失败恢复、确认建课和刷新恢复；
- 课节预览、正式学习、消息生成、会话恢复、Review 和课程关闭；
- 手工排期、计划流预览与确认、历史投影重建；
- 历史、日历、学习画像与证据链主路径；
- Provider 切换和 DPAPI 凭据持久化；
- 服务崩溃自愈、外部端口保护、实例身份校验和过期前端写入阻断。

### 4.2 后端公开能力已存在，前端尚未完整消费

| 服务端能力 | 当前前端缺口 | 应补位置 |
| --- | --- | --- |

### 4.3 领域能力存在，但公开 HTTP/合同尚未形成完整闭环

规划领域已实现并测试 `MoveScheduleItem`、`ResizeScheduleItem`、`RemoveScheduleItem`，也有计划流 pause、resume、reflow、delete 和锁定规则；当前 HTTP 只公开创建排期、读取排期、请求预览和确认计划流。因此下列样稿操作必须先补共享合同和 HTTP 路由，再接 React：

- 改期、调整时长、取消排期；
- 手动锁定后保持不被计划流重排；
- 计划流暂停、恢复、重排和结束管理；
- 对应版本冲突、幂等重试与失败恢复。

这部分是跨层施工，不应仅通过前端本地状态模拟。

## 7. 视觉与字体基准

视觉迁移必须保持现行样稿的色彩、布局、组件几何、响应式和九模式身份，不允许在 React 中重新发明第二套视觉语言。当前 React `styles.css` 只是简化工程样式，且九模式颜色与样稿的 `mode-themes.js` 不一致，应以现行样稿 token 为准统一。

AI 生成内容采用唯一排版规则：

- AI 标题：SimHei/黑体；
- AI 正文：英文和西文数字优先 Times New Roman，中文回退 SimSun/宋体；
- Markdown 代码：项目统一等宽字体；
- 导航、按钮、表单、用户消息、统计数字和系统诊断：继续使用产品无衬线字体；
- AI 正文默认 `16px/1.8`，标题、段落、列表、引用、表格和代码块的上下间距由共享 token 控制，Feature 不得局部覆盖。

当前正式 React UI 尚未实现这套 AI 排版，因此它属于待施工项，不计为完成。
