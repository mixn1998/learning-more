# Review 核心思想动态语义保真设计

## 目标

课时 Review 的“核心思想”应从最终课堂总结中提炼，但不能为了简短而破坏原总结成立所依赖的结构。不同课程可以呈现不同结构，不预设固定模板。

## 生成边界

- 先识别理解本课核心内容所必需的语义结构，再进行精炼。
- 必要结构可以是概念关系、因果链、判断框架、操作步骤、条件对比、推理过程、适用边界或其他课程自身需要的组织方式。
- 保留必要的层次、段落和列表；不得强制压缩为一句话，也不得套用固定的“问题—框架—结论”格式。
- 删除完成宣布、用户评价、掌握判断、互动复盘、鼓励、未来建议、课程流程说明和不承载知识含义的过渡语。
- 合并真正同义的重复表述，但不能把互相支撑的不同层次误判为重复。
- 精炼标准由“最小充分表达”改为“在不损失必要总结结构、关键关系、推理链和边界条件的前提下，使用尽可能清晰紧凑的表达”。

## 字段分工

- `coreInsight`：保留课堂总结中形成完整理解所需的动态结构，可以是多段或列表。
- `methodologyInsight`：仍是一句高度凝练、可迁移的方法或技巧，不承担完整总结职责。

## 数据与兼容性

- 不修改 Review 数据结构和页面接口。
- 未来 Review 使用新语义规则生成。
- 历史 Review 使用相同规则重新处理，避免新旧口径分裂。
- 原始课堂总结和证据保持不变，重处理只更新 Review 投影。

## 验证

- 生成提示词不得再出现“只保留最小充分表达”的压缩要求。
- 测试应确认提示词明确允许动态保留段落、列表与必要层次。
- 历史重处理应覆盖所有符合条件的 Review，并验证无遗漏或投影不一致。
