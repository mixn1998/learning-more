# 轻量全量测试设计

## 目标

让开发者默认执行的全量验证快速、稳定且没有大磁盘、外部服务或浏览器副作用，同时保留发布前需要的容量、恢复和端到端门禁。

## 测试分层

### 默认测试

`pnpm test` 运行全部单元测试与轻量集成测试，但排除：

- `tests/performance/**`
- 恢复与服务重启演练
- Playwright 浏览器测试
- 视觉回归测试

默认测试不得创建超大文件、依赖外部 AI 服务或启动长期驻留进程。

### 默认验证

`pnpm verify` 依次执行格式、Lint、类型、Schema、架构、等价性、默认测试和构建。该命令用于日常提交前验证。

### 专项门禁

- `pnpm test:capacity`：容量配置、关键索引复杂度、内存和延迟预算。
- `pnpm test:recovery`：故障恢复、服务重启和运行时激活演练。
- `pnpm frontend:acceptance`：浏览器、可访问性、视觉和完整前端验收。
- `pnpm verify:release`：串联默认验证与全部专项门禁。

## 容量检查

移除默认测试中通过 `truncate(20 GiB)` 创建容量文件的做法。容量门禁改为验证：

- 课程、课节、消息、事件和证据的目标基数配置；
- 对目标基数的线性遍历能够在预算内完成；
- 热查询、非 AI 写入与 Provider 到 SSE 的延迟预算；
- 运行过程的内存增长预算；
- 结构化数据逻辑容量上限为 20 GiB。

逻辑容量通过配置与边界计算验证，不通过实际创建 20 GiB 文件证明。

## 成功标准

- `pnpm test` 不运行容量测试。
- `pnpm verify` 不触发大磁盘、浏览器或恢复演练。
- `pnpm test:capacity` 无 20 GiB 文件副作用并能独立通过。
- 发布级命令仍能覆盖容量、恢复和前端验收。
- 原有功能测试不因分层而丢失。
