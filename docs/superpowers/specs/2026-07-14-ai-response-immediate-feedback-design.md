# AI 响应即时反馈设计

**状态：** 待用户复核  
**日期：** 2026-07-14  
**适用项目：** Learning MORE

## 1. 目标

消除所有用户主动触发 AI 后的空白等待。用户动作发生后，界面必须在同一渲染周期内反馈；服务端返回只负责确认、补全或纠错，不能成为首次视觉反馈的前置条件。

统一交互顺序为：

```text
用户触发
  → 立即呈现用户动作与处理中状态
  → 请求被服务端受理
  → 流式或完整结果回填
  → 完成、失败或可重试状态
```

本次覆盖：

1. 主页提交学习主题后立即进入学习档案创建页；
2. 学习档案创建对话中的每次发送；
3. 候选大纲生成按钮及右侧候选区域；
4. 正式课程学习对话中的每次发送与流式回复；
5. 为后续用户主动触发的 AI 操作建立同一交互规则。

## 2. 方案比较

### 方案 A：只增加按钮 Loading

保持现有请求顺序，只在原页面显示按钮忙碌状态。改动最小，但主页仍不能立即进入建档页，用户消息仍要等服务端返回后才出现，不能满足目标。

### 方案 B：前端即时状态，服务端权威结果回填（采用）

点击后立即建立仅存在于当前页面的临时消息和处理中状态，再执行当前服务端命令。服务端结果返回后，用权威消息快照替换临时状态。它不改变领域数据、回合计数、写入顺序或证据规则，能以最小风险覆盖全部可感知延迟。

### 方案 C：把所有建档对话改造成异步 GenerationTask

服务端先返回任务标识，再统一通过流式任务完成对话。长期一致性最好，但会同时改动 CourseAuthoring Interface、HTTP 合同、恢复语义和持久化事务，超出本次体验修复范围。可在后续控制链重构时单独实施。

## 3. 状态语义

前端显示状态与领域消息严格分离。

```ts
type LocalTurnStatus =
  | 'submitting' // 用户已点击，服务端尚未受理
  | 'thinking' // 请求已开始，尚未收到 AI 正文
  | 'streaming' // 已收到部分 AI 正文
  | 'complete' // 已由服务端权威快照确认
  | 'failed'; // 请求或生成失败，可恢复或重试
```

规则：

- 临时状态只属于前端 View Model，不进入共享领域合同、Repository、统计事实、全局学习档案或画像证据。
- “正在思考中……”是状态文案，不是 AI 消息正文，不计为评估回合，不写入历史记录。
- AI 起始引导语是稳定的产品引导，不是模型生成结论，不计为评估回合或画像证据。
- 只有服务端返回的用户消息和 assistant 消息才是权威 `OutlineMessage` 或正式学习消息。
- 相同操作进行中时禁用重复提交；界面反馈与幂等键共同防止重复命令。

## 4. 主页到学习档案创建页

### 4.1 路由交接

主页不再等待 `createOutlineSession` 完成后跳转。提交有效主题后立即导航到 `/courses/new`，通过 React Router location state 传递一次性的 `AuthoringStartIntent`：

```ts
type AuthoringStartIntent = Readonly<{
  topic: string;
  courseMode: CourseMode;
  materialFile?: File;
}>;
```

主题不写入 URL。建档页接收意图后立即开始现有创建命令；创建成功后用 `outlineSessionId` 替换当前 URL，并清除一次性交接状态。

### 4.2 首屏内容

建档页首次渲染立即显示：

1. AI 起始引导语；
2. 用户在主页提交的学习主题；
3. assistant 状态“正在思考中……”。

创建接口返回后，服务端消息快照替换临时用户消息与思考状态，不产生重复消息。阅读研讨携带的文件仍在建档页完成上传；上传和 AI 回复分别显示进度，不阻塞页面进入。

### 4.3 失败与刷新

- 创建失败：保留主题和模式，用户消息标记发送失败，显示重试入口，不返回主页。
- 页面刷新且已有 `outlineSessionId`：按现有恢复流程读取服务端快照。
- 页面刷新但创建尚未得到 `outlineSessionId`：若 location state 仍存在则重试同一开始意图；不存在时显示可恢复的创建失败状态，不构造虚假服务端会话。

## 5. 学习档案创建对话

用户点击发送后，同步完成以下前端动作：

1. 读取并冻结本次输入；
2. 立即把用户消息追加到对话；
3. 清空输入框；
4. 立即追加“正在思考中……”状态；
5. 禁用重复发送，开始 `appendMessage`。

服务端返回并完成 `loadSession` 后，以权威消息列表替换临时消息。若发生版本冲突或请求失败：

- 用户临时消息保留并标记失败；
- 原文本恢复到输入框，允许修改或重试；
- assistant 思考状态移除并替换为明确失败提示；
- 不把失败临时消息计入已完成评估轮数。

## 6. 候选大纲生成

用户点击“生成候选大纲”或“重试生成”后，在等待 `requestCandidateGeneration` 返回之前就必须：

- 按钮进入 `aria-busy=true`，文案切换为“正在生成…”；
- 禁用重复点击；
- 右侧候选区域立即显示“正在生成候选大纲…”；
- 全局页头状态同步显示生成中。

任务受理后继续使用现有流式 Markdown 追加。首次生成时显示候选占位；已有候选调整时保留旧候选可读，并在其上方显示更新中状态。请求受理失败、流中断、超时和结构校验失败继续使用现有不同失败口径，均保留重试能力。

## 7. 正式课程学习对话

用户点击发送后立即：

1. 把用户输入追加为本地临时消息；
2. 清空输入框；
3. 显示 assistant“正在思考中……”；
4. 将会话置为生成中并开放现有停止生成入口；
5. 调用 `sendMessage`，受理后连接现有流。

收到第一个 `message.delta` 后，思考状态原位转为流式 Markdown，不新建第二个 assistant 气泡。任务完成后读取服务端快照并替换临时消息。若请求尚未受理便失败，恢复用户输入并标记发送失败；若流在受理后失败，保留已发送用户消息和已收到的部分 AI 内容，显示可恢复状态。

页面恢复到一个已有活动任务时，在连接流之前也显示“正在思考中……”，避免恢复阶段出现空白。

## 8. 可访问性与视觉规则

- 对话容器使用 `aria-live="polite"`，处理中状态使用 `role="status"`。
- 操作按钮在请求开始的同一渲染周期设置 `aria-busy` 和禁用状态。
- “正在思考中……”沿用当前项目暖白、陶土色、低饱和状态体系，不新增另一套 AI 视觉身份。
- 思考状态可使用轻量动态省略号，但必须尊重 `prefers-reduced-motion`。
- 状态文案必须与正文有可区分的视觉层级，不能让用户误认为它是已经生成并保存的 AI 内容。

## 9. Module 与 Interface

本次不新建后端 seam。前端建立一个小而稳定的即时反馈 Module，用于把本地状态投影成对话可见项：

```ts
interface PendingTurnProjection {
  beginUserTurn(markdown: string): PendingTurnView;
  beginAssistantWait(turn: PendingTurnView): PendingTurnView;
  appendAssistantDelta(turn: PendingTurnView, markdown: string): PendingTurnView;
  fail(turn: PendingTurnView, reason: PendingTurnFailure): PendingTurnView;
}
```

该 Module 隐藏临时 ID、状态文案、失败回填和流式占位切换。页面只负责发出动作并在服务端快照到达时完成 reconcile。若实际代码中只有两个简单调用点，Implementation 可以保持为纯 reducer/helper，不引入额外 Adapter。

## 10. 已确认测试 seam

测试只通过以下公开 Interface 观察行为：

1. `HomePage`/`HomeRoute`：提交后导航立即发生，未等待 `createOutlineSession` Promise；
2. `AuthoringPage`：通过 `CourseAuthoringClient` fake 控制挂起、成功和失败，观察首屏消息、思考状态、候选状态和权威快照回填；
3. `SessionPage`：通过 `LearningClient` fake 控制任务受理与流，观察用户消息立即出现、思考状态原位转流式正文及失败恢复；
4. `CourseAuthoringRoute`：验证一次性 `AuthoringStartIntent` 被消费并在获得 `outlineSessionId` 后替换 URL；
5. 现有端到端课程建档和正式课对话路径：验证真实路由下无空白等待、无重复消息、无重复命令。

不测试 reducer 私有分支，不 mock 页面内部 helper，不通过读取 Repository 旁路验证前端行为。

## 11. 验收标准

- 所有列入范围的按钮在点击后 100ms 内出现可见反馈；该指标由前端同步状态保证，不依赖网络速度。
- 主页提交后不等待建档接口即可进入学习档案创建页。
- 用户消息在点击发送后立即可见，AI 正文未到达前始终存在明确思考状态。
- 第一个流式片段到达时原位替换思考状态，不能出现重复 assistant 气泡。
- 服务端快照回填后不重复显示临时消息。
- 失败时用户输入可恢复，失败临时状态不进入统计、回合计数或画像证据。
- 候选大纲请求受理前、流式生成中和失败后均有明确且互斥的页面状态。
- 正式课程对话、建档对话和恢复活动任务遵守同一交互顺序。

## 12. 文档同步规则

实现时同步更新：

- 《课程创建通用流程与功能逻辑规则》的主页交接、建档对话和候选生成状态；
- 《课程学习与 Review 功能逻辑规则》的正式课程对话状态；
- 《基础模块功能等价清单与回归基线》的回归断言；
- 涉及相关界面时更新 UI 功能清单和视觉 sample。

以后任何改变临时消息、思考状态、流式回填、失败恢复或候选生成反馈的需求，必须同步更新本设计及上述受影响规格。
