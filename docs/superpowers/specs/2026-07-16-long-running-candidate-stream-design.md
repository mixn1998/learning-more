# 候选大纲长任务自动展示设计

日期：2026-07-16

## 问题与证据

候选大纲生成任务可能超过两分钟。现有前端在开始监听生成事件后设置 120 秒绝对超时；超时会中断 SSE，随后只回读一次大纲会话。若此时服务端仍在生成，页面会停留在“生成中”，且不会再次订阅。服务端稍后完成并持久化候选大纲后，用户只能手动刷新页面才能看到结果。

2026-07-16 的实际任务记录显示：任务从首个心跳到 `task.completed` 持续约 2 分 18 秒，超过前端 120 秒限制；任务最终正常发出了 `artifact.ready` 和 `task.completed`，因此问题不在服务端漏发终态，而在前端提前停止监听。

## 目标

- 已接受的候选大纲任务持续监听到服务端明确返回完成、失败或取消。
- 任务超过 120 秒仍能在完成后自动展示候选大纲，无需刷新页面。
- 保留用户主动取消、组件卸载、真实连接失败和服务端失败的现有处理。
- 不改变服务端任务生命周期、生成策略、接口协议或候选大纲数据结构。

## 方案

移除 `AuthoringPage` 生成订阅 effect 中的 120 秒绝对超时。任务监听的终止条件改为：

1. 收到 `task.completed`、`task.failed` 或 `task.cancelled`；
2. 用户主动取消生成；
3. 页面离开或组件卸载；
4. SSE 客户端在既有重连次数耗尽后报告真实连接失败。

SSE 客户端继续负责短暂断线重连，服务端心跳继续维持长连接。收到终态后，页面沿用现有候选会话回读逻辑，等待持久化候选 Markdown 可见后更新页面。

不采用简单延长固定超时，因为任何固定时长都可能在更慢任务上复发；也不增加并行轮询，因为 SSE 已提供任务心跳与终态，双通道会增加状态竞态。

## 状态与错误处理

- 长时间正常生成：页面保持“生成中”，连接持续接收心跳，最终按终态更新。
- 用户取消：现有取消命令与本地中断行为不变。
- 页面离开：effect 清理时中断当前连接，避免卸载后写入页面状态；服务端任务生命周期不因此改变。
- 短暂断线：沿用 SSE 客户端自动重连。
- 持续断线：沿用 `generation_interrupted` 错误展示与会话恢复检查。
- 服务端失败或取消：沿用现有失败原因映射和重试入口。

## 测试

新增页面回归测试：使用可控计时器让生成订阅持续超过 120 秒，再发送 `artifact.ready` 和 `task.completed`，断言候选 Markdown 自动出现且订阅没有被前端超时信号中断。

同时运行：

- 候选大纲页面相关测试；
- SSE 客户端测试；
- Web 类型检查。

## 验收标准

- 候选大纲任务耗时超过 120 秒后正常完成，当前页面无需刷新即可显示候选大纲。
- 用户取消和页面卸载仍会中断前端连接。
- 服务端明确失败、取消和持续连接失败仍显示对应反馈。
- 不修改后端接口与任务持久化行为。
