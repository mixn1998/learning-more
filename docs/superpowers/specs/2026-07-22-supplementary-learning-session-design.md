# 补充学习会话设计

## 目标

将补充学习升级为独立、可重复创建的 AI 会话。它复用正式课程的会话交互能力，但不参与正式教学的进度、观察、Review、画像或统计链路。

## 业务边界

- 仅已完成且最终 Review 可用的课节可以开始补充学习。
- 每次点击“开始补充学习”创建一段新的补充学习会话；同一课同时最多存在一段活动会话。
- 固定学习上下文仅包含本课最终 Review 的字符内容，不读取原课程对话、教学账本、学习画像、其他课程或历史补充学习会话。
- 动态上下文仅包含当前补充学习会话中仍然有效的用户消息和 AI 回复。
- 补充学习不执行教学观察，不生成或更新课时 Review，不写入画像证据、教学统计或教学账本。

## 架构

新增独立的补充学习生成编排器。编排器依赖 Generation Runtime，并复用正式课程已经验证的消息持久化、任务状态协调、流式回复投影、重新编辑、重新生成和停止生成基础能力。它不依赖互动教学模块及其教学智能体。

现有补充学习聚合继续负责会话生命周期，并扩展活动生成任务绑定、有效消息记录和并发版本控制。生成任务以补充学习会话 ID 作为 owner，使用独立且已注册的 AI 场景，避免与正式课程任务相互协调或取消。

## 数据流

正常回合：

1. 用户提交补充消息。
2. 服务端原子保存用户消息并绑定新的生成任务。
3. 编排器使用“本课最终 Review 文本 + 当前会话有效历史”组装提示词并提交 Generation Runtime。
4. 安全文本片段按正式课程的流式机制投影到页面。
5. 任务完成后持久化完整 AI 回复并原子清除活动任务绑定。
6. 页面以服务端快照协调最终消息和任务状态。

重新编辑会替换目标用户回合，并撤销该回合之后的有效对话分支；若存在活动生成任务则先取消。重新生成不要求用户重复输入，使用当前最后一条有效用户消息创建新任务。中断、失败、取消和超时任务都必须清除会话绑定，读取会话时也执行终态协调，防止孤儿任务。

## 关闭与重新开始

- 活动会话显示“关闭本轮学习”。
- 点击关闭时立即取消活动任务；仅保留关闭前已经完成持久化的内容，未完成流不得继续提交或回写。
- 关闭操作将会话原子改为 `archived`，之后永久只读并可随时查看。
- 关闭后按钮恢复为“开始补充学习”；再次点击创建全新会话，不续写旧会话。

## 前端交互

- 原始课程会话和各段补充学习会话继续在左侧会话列表中切换。
- 活动补充学习会话使用与正式课程一致的用户消息编辑、AI 生成中状态、流式回复、停止生成、失败提示和重新生成交互。
- 归档补充学习会话不显示输入框和编辑/重试操作。
- 按钮状态由服务端会话状态投影，不能仅依赖页面本地状态。

## 一致性与错误处理

- 所有写操作使用资源版本进行并发保护。
- 关闭与生成完成竞争时，以成功提交的关闭事务为边界；关闭后到达的生成结果不得写入。
- 服务端快照是任务状态和消息内容的唯一事实源，前端拒绝旧版本快照覆盖新状态。
- Generation Runtime 的失败、取消和超时状态需自动协调到补充学习会话。
- 不再执行现有的补充学习画像 checkpoint；已有归档记录保持可读，不追溯删除已产生的历史画像数据。

## 验收标准

- 补充消息可以获得 AI 回复，双方消息均持久化，刷新页面后仍可恢复。
- 固定提示词上下文只能检出本课最终 Review 文本。
- 重新编辑、重新生成、停止生成和流式投影行为与正式课程一致。
- 关闭正在生成的会话会立即停止任务，且不会发生迟到回复回写。
- 关闭后记录只读，再次开始会创建新的独立会话。
- 补充学习全过程不会创建教学观察、教学账本变更、Review 任务或画像证据。
