# 教学节点激活时序设计

## 问题

当前教学控制协议允许在完成一个知识点的回复中，同时把相邻下一知识点设为 `learning`。此时下一知识点尚未出现任何讲解内容，课程线索却已经显示“正在学习中”。这不是界面文案问题，而是教学账本把“已选定下一教学目标”和“已经开始讲解”视为同一状态。

## 目标

节点状态必须描述已经发生的教学事实：

- 下一知识点可以提前成为教学游标，以便后续生成知道从哪里继续。
- 仅选定游标不表示教学已经开始，知识点仍保持 `pending`。
- 下一知识点的生成真正启动后，界面可以立即显示正在讲解。
- 生成成功后，权威账本依据本轮结果写入 `learning` 或 `completed`。
- 生成失败时，界面恢复待讲解，权威账本不留下提前激活的状态。

这项调整不增加模型调用、数据库往返或教学进度同步步骤。

## 状态语义

`activeKnowledgePointRef` 表示教学游标：当前回复所属的知识点，或下一次生成准备进入的知识点。

知识点 `progress` 表示已经发生的教学事实：

- `pending`：尚未出现属于该知识点的讲解。
- `learning`：已经开展讲解，但知识点尚未完成。
- `completed`：必要讲解已经完成，且没有阻塞该知识点的未处理理解问题。
- `skipped`：学习者明确跳过该知识点。

因此，`activeKnowledgePointRef` 指向 `pending` 节点是合法的“已选定、未开始”状态，不应投影成“正在学习中”。

## 教学时序

### 完成当前节点

当回复只完成当前知识点、没有展开下一知识点时：

1. 当前知识点进入 `completed`。
2. 教学游标可以移动到相邻下一知识点。
3. 下一知识点保持 `pending`。
4. 界面继续显示下一知识点“待讲解”。

### 开始下一节点

当学习者触发继续讲解时：

1. 生成任务沿用已经选定的教学游标，并把消息归属到该知识点。
2. 生成任务开始后，界面用当前生成任务的知识点归属即时显示正在讲解，不等待额外同步。
3. 回复成功完成后，服务端验证并写入 `learning`；如果该回复已经充分完成该知识点，也可以直接写入 `completed`。
4. 若生成失败，临时界面状态消失，知识点仍为 `pending`，可直接重试。

### 已开始节点的后续回复

已为 `learning` 的知识点继续保持现有行为。其后续讲解、互动、澄清和完成判断仍由教学智能体依据真实对话与教学目标决定。

## 服务端约束

教学控制协议不再要求“完成当前点后把下一点设为 `learning`”，改为：

- 可以把教学游标切换到相邻下一节点。
- 未在本轮可见回复中展开的下一节点必须保持 `pending`。
- 本轮讲解所属节点可以由 `pending` 进入 `learning` 或直接进入 `completed`。
- 不允许把既未被本轮消息讲解、也不是原有 `learning` 状态的节点标记为 `learning`。

状态校验器应接受“知识点阶段 + 游标指向 pending 节点”的过渡状态，同时继续拒绝跨越节点、非相邻切换、多节点同时完成和终态倒退。

## 界面投影

课程线索以权威账本的 `progress` 为稳定状态来源：

- `pending` 显示待讲解。
- `learning` 显示正在学习。
- `completed`、`skipped` 沿用现有终态表现。

生成进行中时，界面可以使用已有的生成任务知识点引用作为临时即时状态。该临时状态不写入权威账本，生成失败后自然撤销。

## 兼容性与失败处理

- 不迁移或重投影既有课程数据。
- 已经处于 `learning` 的会话继续按原状态运行。
- 新规则从后续教学回复开始生效。
- 生成失败、停止生成和重试不会推进知识点事实状态。
- 教学进度同步继续使用原有账本和任务框架，不增加新的持久化阶段。

## 验证

自动化验证覆盖：

1. 完成当前节点并选定下一节点时，下一节点仍为 `pending`。
2. 下一节点的首条讲解回复能够从 `pending` 进入 `learning` 或 `completed`。
3. 非相邻游标切换和未讲解节点的提前 `learning` 被拒绝。
4. 界面在上一节点结束后显示下一节点待讲解。
5. 下一节点生成启动时即时显示正在讲解，生成失败后恢复待讲解。
6. 既有 `learning` 节点的继续讲解、完成和同步行为不回归。
