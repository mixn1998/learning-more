# 删除学习画像下游链路设计

## 目标

完整移除当前版本的用户可见学习画像和教学个性化消费链路，同时保留全局用户档案层及其上游数据生产能力。

## 保留范围

- 原始学习事实、教学观察、冻结检查点、Review 与历史统计。
- 用户档案候选证据及其来源引用。
- 思维行为 Episode、跨会话分析、语义档案核心、统计快照和档案版本。
- 用户档案的证据提炼、失效与重建能力。

现有 `portrait-evidence` 存储目录属于历史命名下的用户档案候选证据仓库，继续保留。

## 删除范围

- 学习画像页面、历史页画像 Tab、`/profile` 兼容入口与前端画像客户端。
- 画像刷新、当前画像与画像版本接口。
- 画像生成、证据打包、校验、版本仓库、刷新协调器和每周调度器。
- 教学个性化摘要生成、缓存、读取及其向互动教学提示词的注入。
- 课程删除后的画像刷新状态和界面文案。
- `Portrait*` 公共契约、画像 OpenAPI 内容、视觉样稿与当前产品文档中的画像功能声明。
- 本地 `portraits` 数据、`personalization-digests` 数据，以及 `taskKind=learning-portrait` 的生成任务记录。

## 架构调整

当前 `LocalProfileRuntime` 拆除画像与教学个性化职责后，仅保留用户档案生产、查询、恢复和检查点消费。互动教学上下文不再包含 `personalization` 字段，也不再渲染个性化提示段。

画像接口不提供兼容空响应，而是从路由注册中移除；前端也不再导航到这些地址。用户档案内部接口继续存在，供数据维护与未来功能使用。

## 异常与验证

- 启动与教学不再依赖个性化摘要或画像投影就绪状态。
- 用户档案恢复失败仍按现有降级规则处理，但不影响画像功能，因为画像链路已不存在。
- 验证历史统计与日历保持可用、课程删除不再返回画像刷新状态、教学提示词不含个性化背景、画像路由与 UI 不可达，以及用户档案数据文件未被删除。
