# Deterministic Plan Flow Design

## Goal

计划流完全不调用 AI。它使用课程、课节、前置依赖、开始日期、学习日、每日目标时长、策略和已有排期等结构化输入，确定性地产生可预览、可确认的学习排期，并让排期创建、取消和确认立即反映到页面。

## Architecture

规则计算位于服务端 planning 模块。`requestPreview` 物化上下文后，调用纯规则函数生成 `PlanSuggestion[]`，复用现有校验和冲突检测，再保存为 `preview-ready`。HTTP 层不等待 generation runtime，不解析模型输出；确认仍通过现有事务一次性写入日程。

计划流继续沿用当前请求和响应结构，`generationTaskId` 暂存确定性计算标识以保持内部持久化与契约兼容，但不对应 AI 任务。以后可在单独的契约迁移中删除该遗留字段。

## Scheduling Rules

1. 排除已完成、已放弃以及在“保留已有日期”模式下已经排期的课节。
2. 对待排课节执行稳定拓扑排序：前置课先于后续课；同层保持课程和课节输入顺序。
3. 从开始日期起枚举被选择的学习日，默认每天从本地时间 19:00 开始安排。
4. 课节不可拆分。每日目标时长是软上限：单节超过上限时仍整节安排；否则当天累计达到上限后转到下一个学习日。
5. 避让所有未移除的已有日程和锁定项；发生重叠时将候选课节移动到当天最后一个冲突项之后，若因此不适合当天软上限则转到下一学习日。
6. `balanced` 按拓扑顺序均匀推进；`focus` 在满足前置依赖的前提下优先连续完成同一课程；`priority` 保持所选课程输入优先级。三种策略都必须产生可重复结果。
7. 无法满足前置依赖、日期或时间约束时返回既有 `plan_preview_invalid`，不降级到 AI。

## Data Flow

`PlanFlowPanel` 结构化输入 → planning HTTP route → `PlanFlowService.requestPreview` → 上下文物化 → 确定性规则生成建议 → 既有建议校验与冲突检测 → `preview-ready` → 用户确认 → 单事务写入 schedule。

普通日程的创建、移动、锁定和取消只修改日程及事件，不触发下一课 AI 推荐。前端收到成功响应后直接更新本地列表；取消操作必须过滤已移除项，不能把 removed tombstone 留在可见列表中。

## Error Handling

- 结构化输入非法或不可排期：返回 `plan_preview_invalid`。
- 基础日程在预览后变化：确认时继续返回版本冲突，要求重新预览。
- 页面命令失败：保留用户输入并展示可重试错误；不出现 AI 不可用、生成超时或模型输出非法提示。

## Verification

- 单元测试覆盖稳定拓扑排序、学习日、每日软上限、已有日程避让、策略稳定性和无 AI 提交。
- 服务端集成测试证明计划预览和日程命令不产生 generation task，且响应不受慢 provider 影响。
- 前端回归测试证明取消排期后无需刷新即可从可见列表移除。
- 部署后在真实页面计时验证：点击取消后页面立即显示“待规划”，刷新后状态一致。
