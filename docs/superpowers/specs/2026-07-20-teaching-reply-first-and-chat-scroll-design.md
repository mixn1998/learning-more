# 正式教学即时流式与对话滚动边界设计

## 目标

同时修复两个直接影响正式学习体验的问题：

1. 正式教学当前必须先生成并校验隐藏教学状态，用户正文只能在生成末段集中出现；调整为单次模型调用中的“用户可见回复在前、隐藏教学状态在后”，让正文尽早流出。
2. 正式课程与补充学习当前可能由整个对话列承担滚动；调整为仅消息记录区内部滚动，并在进入或切换会话时默认定位最新消息。

本次不增加模型调用，不改变教学自由度、课程责任、教学账本语义、Review 证据口径或历史消息追加原则。

## 正式教学响应协议

结构化教学响应固定为以下顺序：

```text
<learning-more-reply>{用户可见 Markdown}</learning-more-reply>
<learning-more-control>{完整 JSON 教学状态快照}</learning-more-control>
```

服务端流解析器在识别到可见回复区块后，按安全 Markdown 边界立即发布 `message.delta`。普通段落按完整句子或稳定边界发布；行内公式、展示公式、代码围栏、表格和 `math-plot` 等不可拆渲染单元仍等待自身闭合，不等待隐藏教学状态。

隐藏教学状态只有在控制区块完整闭合、通过 Schema 解析并通过教学业务校验后才可以更新教学状态账本。可见回复的流式投影不得直接推进知识点、检测、讨论或闭环状态。

## 提交与竞态边界

一次模型生成在解析后分流为两个互不反向干扰的业务链路：可见回复进入会话消息链路，隐藏教学状态进入账本同步链路。服务端仍占用当前学习会话的活动任务绑定，直到两条链路都得到明确结果；这只用于避免下一轮读取尚未落账的状态，不得让账本失败撤销或降级已经完整闭合的教学回复。

正常完成顺序为：

1. 流式发布可见回复的安全片段；
2. 解析并校验完整隐藏教学状态；
3. 保存完整 AI 回复制品；
4. 提交正式 AI 消息；
5. 应用教学状态指令；
6. 写入完成帧并解除活动任务绑定。

消息已经提交但账本写入中断时，沿用现有恢复机制，从同一已完成生成任务重放隐藏指令，不重新生成正文，也不重复提交消息。

## 停止、失败与恢复

- 用户停止生成时，保存已经展示的正文为 `interrupted` AI 回复，不应用隐藏教学状态。
- 可见回复区块已经完整闭合，但尾部控制区块缺失、JSON 非法或教学业务校验失败时，正文仍以 `complete` 独立持久化；账本同步单独标记为失败并保持原教学进度，不将其伪装成内容生成失败。
- 未完成回复可在对话历史中查看，但不构成完成教学、掌握证据、Review 输入或学习行为统计依据。
- 页面刷新、SSE 断开或服务重启后，使用持久化任务与会话绑定恢复；已显示的未完成正文不得消失，已提交的完整消息不得重复。
- 只有正文自身断流或用户主动停止时，历史回复才保留 `interrupted` 技术状态并允许重新生成；单纯账本同步失败不得要求用户重新生成已经完整的教学内容。

## 对话滚动区

桌面端正式课程工作区采用固定视口内布局：

- 左栏顶部教学状态与底部输入框固定在对话卡片内；
- 只有中间消息记录区设置 `overflow-y: auto`；
- 右侧知识点与计时区域维持独立布局，不受左栏消息长度挤压；
- 消息区使用 `overscroll-behavior: contain`，避免滚动到边界后带动外层页面。

课节记录中的补充学习对话采用相同结构：会话列表、输入框和消息区各自承担明确布局责任，只有消息区滚动。窄屏下恢复自然页面流，避免形成高度过小的嵌套滚动区。

## 最新消息定位规则

- 首次进入已有正式学习会话时定位到最新消息；
- 新建或切换到某条补充学习会话时定位到该会话最新消息；
- 用户发送新消息时强制跟随到最新位置；
- AI 流式追加期间，仅当用户仍位于底部附近时自动跟随；
- 用户主动向上阅读历史后不强制拉回，继续显示“回到最新消息”入口。

## 验证范围

服务端回归测试覆盖：

- 控制区块尚未开始时，可见回复已经产生安全流式片段；
- 账本在控制区块完成并校验前保持不变；
- 完整响应只提交一次消息并只应用一次指令；
- 正文断流或停止会保留未完成正文且不推进账本；尾部缺失或非法控制不影响完整正文，只使账本同步进入失败/恢复路径；
- 数学公式与 `math-plot` 不以残缺片段发布。

前端回归测试覆盖：

- 正式课程和补充学习的消息区是唯一纵向滚动容器；
- 顶部状态与输入区不随消息记录滚动；
- 首次进入和切换会话定位最新消息；
- 用户上翻后新流式内容不抢夺阅读位置，可手动回到最新消息；
- 桌面与窄屏布局均无不可访问的输入或操作区。
