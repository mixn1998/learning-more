# 发布内容去重设计

## 目标

减少“当前版＋上一版”同时保留时的重复磁盘占用，不改变现有版本激活、完整性校验、回滚和启动路径。

Node.js 运行时是本地发布产物，不进入 Git。源码仓库只保留获取、校验、共享和清理运行时的实现。

## 发布结构

发布根目录保留版本目录，并新增按内容寻址的共享区：

```text
releases/
  .shared-runtime/
  .shared-content/
    code/
    visual/
    native/
  <active-build-id>/
  <previous-build-id>/
```

版本目录仍表现为完整、可独立启动的发布包。共享文件通过同卷硬链接出现在版本目录的原路径；运行进程无需理解共享区。

共享类别：

- `code`：JavaScript、CSS、HTML及相应不可变构建文件。
- `visual`：图片、SVG、图标和字体。
- `native`：原生 Node 模块及 WASM，包括 PDF 处理依赖。
- `runtime`：Node.js 可执行文件，沿用现有专用共享池。

版本专属的 `release-manifest.json`、共享内容清单、启动配置及校验元数据不共享。

## 暂存与激活

候选版本复制到暂存目录后：

1. 对符合共享类别的文件计算 SHA-256。
2. 将内容写入对应共享池；已有相同哈希时复用现有文件。
3. 用共享文件到候选原路径的硬链接替换候选文件。
4. 生成版本级共享内容清单，记录类别、相对路径、哈希和大小。
5. 完成现有运行时共享后，原子重命名为正式版本目录。
6. 按既有流程启动、健康检查并激活。

候选文件与共享池必须位于同一卷。共享、链接或清单写入失败时，候选激活失败，当前版本保持运行。

## 生命周期

当前版和上一版的共享内容清单共同构成受保护引用集合。清理旧版本后，删除未被受保护版本引用的共享对象。

清理必须满足：

- 只管理具有合法发布清单的版本。
- 不追踪或修改用户数据。
- 不依赖硬链接计数决定业务引用，以版本清单为准。
- 共享池中的临时文件可以安全重试清理。
- 当前版与上一版缺少共享清单时，采用保守策略，不删除共享对象。

## Git 边界

仓库忽略：

- `node_modules/`
- `runtime/`
- `node.exe`
- `*.node`
- 本地发布、共享池和激活工作目录

源代码目录中确有业务含义的 `runtime` 命名空间继续通过现有白名单保留。发布流程负责从本机 Node 环境复制并校验 `node.exe`，Git 历史不保存该二进制。

## 验证

验证集中在发布边界：

- 相同内容跨两个版本只占用一个物理文件。
- 版本目录仍可独立按原路径启动。
- 激活失败不影响当前版本。
- 回滚到上一版不依赖已删除内容。
- 删除旧版本后，仅回收无引用共享对象。
- Node 运行时及发布二进制不会成为 Git 跟踪文件。

按当前发布包估算，两版内容相同时，在现有 Node 运行时共享基础上，还可避免约 49.8 MiB 重复占用：代码与视觉资产约 23 MiB，原生 PDF 依赖约 26.8 MiB。
