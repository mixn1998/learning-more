# 草稿大纲恢复状态修复设计

## 背景与问题

主页“选择课程”弹窗中的未确认大纲卡片会携带 `outlineSessionId` 进入现有的 `/courses/new` 路由。该路由对应的 `AuthoringPage` 默认以新建课程空白态开始渲染，再异步读取已有大纲会话。因此，恢复完成前会错误显示完整的“创建课程”表单；恢复请求失败时也缺少专用失败态，页面会继续停留在该表单。

这不是新的课程创建页面需求。本次只修复已有草稿会话的恢复状态，不重新设计或修改新建课程界面。

## 目标行为

- 点击未确认大纲卡片后，继续恢复对应的原有大纲建档会话。
- 当 URL 含有 `outlineSessionId` 时，首屏只显示“正在恢复大纲建档…”。
- 恢复成功后显示现有的大纲建档工作台，并保留会话主题、消息、候选大纲和材料等服务端状态。
- 恢复失败时显示明确错误信息和“返回主页”操作。
- 失败态不得退化为新建课程表单，也不得创建新的 `OutlineSession`。
- 不含 `outlineSessionId` 的正常新建课程入口保持现状。

## 实现边界

保留现有 `/courses/new?outlineSessionId=...` 路由和主页卡片目标，不新增路由。`AuthoringPage` 根据 `initialOutlineSessionId` 区分两类入口：

1. 无会话 ID：沿用现有新建课程空白态。
2. 有会话 ID：先进入独立的恢复中状态；请求成功后进入工作台，请求失败后进入恢复失败状态。

恢复中和恢复失败状态位于 `AuthoringPage` 内部，不改变 `CourseModeSelector`、新建课程表单或大纲工作台的视觉结构。

## 错误处理

- `getOutlineSession` 拒绝或返回不可用结果时进入恢复失败态。
- 失败态显示“无法恢复大纲建档”和“返回主页”按钮。
- 点击返回按钮调用现有导航回调进入 `/`。
- 不自动重试、不自动新建会话，避免把旧草稿误变成新建流程。

## 验证

- 延迟的恢复请求期间，只能看到恢复提示，不能看到“创建课程”、主题输入框或课程模式选择器。
- 恢复成功后，现有工作台恢复测试继续通过。
- 恢复失败后显示错误和返回按钮；点击后导航到 `/`，且未调用 `createOutlineSession`。
- 主页草稿卡片仍携带正确的 `outlineSessionId`。
- 不带会话 ID 的新建课程页面保持原有测试结果。
