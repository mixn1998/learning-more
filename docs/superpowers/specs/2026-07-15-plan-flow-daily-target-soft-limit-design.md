# 计划流每日目标软限制修复设计

## 问题

计划流把“每日目标时长”同时当作单节课的硬上限。默认目标为 45 分钟时，只要待规划课程包含预计 50 分钟的课节，模型按课节预计时长生成的合法建议就会被服务端拒绝为 `plan_preview_invalid`，导致计划流无法生成预览。

## 决策

每日目标时长是排期偏好，不是单节课硬上限。课节保持原子性，计划流允许单节课预计时长略高于每日目标，不自动缩短课节、不静默修改用户设置，也不拆分课节。

服务端继续严格校验：

- 课节与课程标识属于本次计划流；
- 每个待规划课节恰好有一条建议；
- 时间区间和时区有效；
- 开始日期与学习日符合约束；
- 建议之间不重叠；
- 前置课节顺序正确。

服务端不再用每日目标拒绝单条建议。提示词明确称其为“软目标”，避免模型为了满足不存在的硬上限而缩短课节。

## 错误与重试

结构无效、日期无效、学习日无效、重叠和依赖错误仍返回 `plan_preview_invalid`。该错误不通过重复相同请求解决；前端已有的一次自动重试只覆盖结构化 `retryable: true` 的传输或运行时错误。

## 验证

新增服务回归测试：每日目标 45 分钟、课节预计及建议时长 50 分钟时，预览应进入 `preview-ready`。保留现有测试，确保日期、学习日、重复课节、重叠与依赖校验没有放宽。

使用当前真实课程和 Codex CLI 重跑原始 HTTP 复现，期望由 `409 plan_preview_invalid` 变为成功的 `preview-ready`，并在界面端完成计划预览。
