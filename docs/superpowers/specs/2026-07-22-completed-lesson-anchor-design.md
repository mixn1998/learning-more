# 已完成课时锚点与新版大纲语义去重设计

## 1. 背景与问题

课程 `course_66e4b768-3329-4e82-be99-cd4f01e79f07` 在发布新版大纲时暴露了一个身份连续性缺口。旧版模块一的两节课已经完成，学习会话、最终 Review 和完成事实均仍然存在；但新版候选以新的语义键、目标和知识点重新描述了相近内容。发布逻辑只会在课节语义完全相同时沿用旧 `lessonId`，又没有强制要求已完成课时必须继续出现在新版中，因此创建了两个新课时，并把两个已完成课时退为历史只读。

这不是前端显示错误。当前活动大纲确实引用了新的 `lessonId`，而两个已有完成事实的旧 `lessonId` 不再属于课程的活动课节列表。

## 2. 决策

已完成课时是后续大纲版本中的不可删除锚点。

1. 已完成课时必须出现在此后每一版确认大纲中。
2. 必须沿用原 `lessonId`、`LessonDefinition`、完成状态、原始学习会话和最终 Review。
3. 已完成课时的标题、学习目标、核心知识点及整体课义均冻结，不允许通过改名或改写重新绑定完成证据。
4. 新候选中与已完成课时课义重复的课时不得同时存在，即使标题、概要、关键词或语义键换了说法。
5. 后续课时若依赖被去重的新课时，依赖必须改指向对应的已完成课时。
6. 无法可靠判定沿用或重复关系时，候选不得发布；系统保留当前正式大纲并给出可重试的候选校验失败。

未开始、学习中和已放弃课时继续遵守既有版本绑定与移除规则。本设计不把所有历史课时都变成不可删除内容。

## 3. 方案比较

### 方案 A：只加强生成 Prompt

把已完成课时写入 Prompt，并要求模型保留和去重。改动较小，但模型仍可能遗漏、改写或产生近义重复，不能形成“无论如何都保留”的领域保证，因此不采用。

### 方案 B：只按标题或关键词做确定性匹配

发布速度快，也容易测试，但只能识别同名课时或明显的知识点重合，无法识别“换一套课时介绍说法”的语义重复，因此不采用。

### 方案 C：完成课锚点、语义沿用解析与发布硬门禁

生成前向模型提供结构化的已完成课时锚点；候选生成后解析新旧课时的沿用、重复和新增关系；发布前由服务端再次验证全部已完成课时均已沿用且不存在重复项。任何不确定或冲突都会阻止发布。该方案采用。

## 4. Module 与 Interface

### 4.1 CompletedLessonAnchorReader

`CourseAuthoring` 通过一个只读端口获取课程的已完成课时锚点，不直接读取学习会话或 Review 的内部文件结构。

每个锚点至少包含：

- 稳定 `lessonId`；
- 原 `semanticKey`；
- 所属 `outlineVersionId`；
- 标题、学习目标、核心知识点和前置课时；
- 原模块身份、模块标题和相对顺序；
- 完成事实引用。

该端口只返回真正处于 `completed` 生命周期的课时。“存在一些学习证据”不能替代完成判定。

### 4.2 CompletedLessonLineageResolver

输入已完成课时锚点和新候选课时，输出：

- 每个锚点在候选中的沿用位置；
- 与锚点语义重复、应删除的候选课时；
- 需要重写的前置依赖；
- 无法确定的冲突。

解析采用分层策略：稳定语义键和明确身份优先；规范化标题、目标及知识点用于确定性匹配；只有确定性规则不足时才调用 AI 语义解析。AI 解析结果必须通过结构、唯一性和完整性校验，不能直接修改 Repository。

### 4.3 OutlineRevisionGuard

发布命令进入事务前执行最终门禁：

- 每个已完成锚点恰好沿用一次；
- 沿用项使用原课时身份和冻结课义；
- 没有候选课时与已完成锚点形成语义重复；
- 模块课时列表和前置依赖只引用最终保留的课时；
- Markdown 投影与结构化候选包含相同的课时集合和顺序。

失败时返回稳定错误 `completed_lesson_anchor_conflict`，不得保存新 OutlineVersion、LessonDefinition、课程引用或排期清理结果。

## 5. 候选生成与发布数据流

1. 打开大纲调整会话时，读取当前正式大纲和全部已完成课时锚点。
2. 生成 Prompt 明确列出冻结课时的规范结构和原模块位置，要求后续内容围绕这些锚点调整。
3. 候选输出完成后，沿用解析器建立新旧课时关系。
4. 已完成锚点作为权威定义写入规范候选；语义重复的新课时从规范候选删除。
5. 被删除课时的前置依赖改指向对应锚点；无法形成唯一映射时终止候选。
6. 根据规范候选形成用于预览的 Markdown 和差异投影。
7. 用户发布时再次运行发布门禁，然后在现有原子事务中保存新 OutlineVersion、真正新增的 LessonDefinition 和课程活动课时列表。
8. 只有未被最终活动大纲保留的非完成课时才进入现有历史只读与排期清理流程。

## 6. 前端差异语义

差异界面不再把已完成课时显示为“新增”或普通“内容调整”。沿用锚点显示“已完成 · 原样沿用”。被语义去重的新候选课不进入最终候选课节列表，可在候选校验说明中汇总为“已合并到已完成课时”。

发布按钮只在完成课锚点校验通过后可用。校验失败时说明是哪一节已完成课被遗漏、改写或产生重复，不要求用户理解 `lessonId`、语义键或后台分析术语。

## 7. 当前课程恢复

当前课程通过正常的大纲修订事务创建一个新的不可变版本，不修改已经保存的旧 OutlineVersion：

1. 恢复 `lesson_66e426d2d3c7fd7da568dcc09575bc50` 和 `lesson_2e3a5dc99cb9451effac646b1ace49e0` 为活动课时；
2. 保留两节课原有定义、完成事实、会话和 Review；
3. 删除新版模块一中与完成课义重复的 `lesson_scarcity_choice` 和 `lesson_context_choice`；
4. 保持新版模块二至模块九的课程内容；
5. 将后续课号从第 3 课开始连续编号；
6. 重写依赖，使后续课时引用两个原完成课时，而不是被删除的重复课时；
7. 重建课程目录、主页汇总、规划上下文和相关推荐快照。

恢复完成后的活动大纲必须以两个旧 `lessonId` 开头，两者继续显示为已完成且可查看原课时记录，不再只出现在历史版本中。

## 8. 错误与恢复

- 语义解析失败：候选保持未发布，当前正式大纲不变，可使用同一输入重新解析或重新生成。
- 完成状态在候选生成后发生变化：发布时重新读取锚点；快照不一致则返回版本冲突并重新生成候选。
- 多个候选同时匹配一个完成锚点：全部视为冲突，不静默选择。
- 一个候选同时匹配多个完成锚点：视为课程拆并歧义，阻止发布。
- 快照重建失败：新大纲事务保持成功，继续提供权威课程数据并后台重试读模型重建；不得回退课时身份。

## 9. 测试边界

### 领域与应用测试

- 候选遗漏已完成课时，发布失败且无写入。
- 候选使用新语义键改写已完成课时，仍沿用原身份或因课义冲突失败，绝不创建替代新课。
- 候选包含多个已完成课时的近义重复项，重复项全部被删除。
- 重复项被删除后，所有前置依赖正确改指向完成锚点。
- 未开始课时仍可按既有规则删除或替换。
- 已放弃或学习中课时继续遵守现有版本绑定，不被误判为已完成锚点。

### 集成与回归测试

- 生产装配必须连接真实完成状态读取端口，禁止回退为恒定 `false`。
- 新版发布后，课程活动 `lessonIds` 包含全部完成锚点且不包含语义重复的新课。
- 课程目录、主页、排期和下一课推荐均读取修复后的活动课时集合。
- 两个原课时的会话、Review、完成统计、日历和画像证据引用保持不变。
- 当前课程恢复场景作为固定数据回归：旧版两节完成课 + 新版换说法的重复课，最终只能保留两节旧课。

## 10. 非目标

- 不修改已完成课时的历史消息或最终 Review。
- 不合并两个不同的已完成课时。
- 不允许用户用新版课义覆盖旧完成证据。
- 不把未开始的所有旧课都强制带入新版。
- 不修改历史 OutlineVersion；恢复只创建新的确认版本。
