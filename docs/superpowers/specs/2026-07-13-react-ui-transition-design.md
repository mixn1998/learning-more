# Learning MORE React UI 转段与像素级迁移设计

> 日期：2026-07-13  
> 状态：已批准，进入分阶段实施计划
> 适用范围：`apps/web`、`packages/ui`、正式 React 视觉测试，以及冻结后的 `docs/UI视觉预览`

## 1. 目标

Learning MORE 从 HTML UI 样稿阶段正式转入 React 产品界面建设。转段先完成一个短收口，再采用“共享基础 + 纵向切片”迁移全部功能域。迁移完成后：

- `apps/web` 是唯一正式产品 UI；
- `packages/ui` 提供稳定的设计 token、布局原语和通用组件；
- 28 个 HTML 样稿只保留为冻结的视觉与交互参考，不再扩展；
- React 页面保持现有真实 API、SSE、领域状态机、幂等和版本保护；
- 28 个权威样稿状态在桌面、平板、移动端形成 84 张截图基线；
- React 页面以全页差异不超过 0.3%、关键组件差异不超过 0.1% 的标准达到像素级接近。
- 正式课程支持不可逆永久删除，并在删除后从主页、课程切换、历史、日历和画像中撤销全部关联贡献。
- 全部 AI 生成内容使用统一内容排版：标题使用黑体，正文中文使用宋体、英文使用 Times New Roman；用户输入、产品控件与结构化统计继续使用产品无衬线字体。

## 2. 已批准的方案

采用“共享基础 + 纵向切片”。先建立 React 设计系统、视觉回归基础和正式 App Shell，再按完整业务闭环逐个迁移。每个切片必须交付可运行产品，不允许以半迁移页面、长期双轨样式或样稿模拟逻辑作为过渡终态。

未采用以下方案：

- 不先建设一个长期不可见的完整设计系统后再统一接页面；
- 不逐页复制 HTML、内联样式和模拟交互；
- 不新建第二套前端工程；
- 不继续扩大 HTML 样稿体系。

## 3. 权威输入与冻结规则

### 3.1 权威输入

- 产品与领域语义以 `CONTEXT.md`、`PROJECT_CONTEXT.md` 和 `docs/` 下专项规则为准；
- 课程永久删除的业务语义以 `docs/设计文档/课程永久删除功能规则.md` 为准；
- 路由、真实状态和数据边界以当前 React、共享合同和服务端公开 Interface 为准；
- 视觉层级、布局、样式和交互表现以 `docs/UI视觉预览` 中 28 个当前 HTML 样稿为迁移参考；
- 样稿与领域规则冲突时，领域规则优先，React 视觉 Fixture 必须表达真实领域状态。

### 3.2 HTML 冻结规则

短收口完成后，`docs/UI视觉预览` 进入冻结状态：

- 不新增页面、业务状态、交互路径、视觉变体或模拟数据模型；
- 不把 React 新功能反向实现到 HTML；
- 仅允许修复阻断基线生成的确定性问题、断链或明确的视觉基准错误；
- 任何允许的冻结后修复必须同时说明 React 映射与截图基线影响；
- README 和项目上下文必须明确 HTML 是只读参考，不是生产代码和后续设计工作区。

冻结前允许且必须完成一次 AI 内容字体同步：只调整当前 28 个样稿中 AI 生成内容的排版选择器与共享字体 token，不新增页面、状态、交互或模拟数据。84 张权威基线必须在该同步完成并通过三视口审计后生成。

### 3.3 等价编号治理

课程永久删除是独立的回归断言。既有 `EQ-COURSE-04`“总 Review 失败隔离”和 `EQ-COURSE-05`“总 Review 固定输入”保持稳定；课程永久删除使用新编号 `EQ-COURSE-06`。等价矩阵从 74 条调整为 75 条，所有架构文档、计划、检查器和发布门禁中的固定总数必须在同一变更集中同步，禁止保留重复 `EQ-COURSE-04`。

## 4. 像素级视觉基线

### 4.1 覆盖范围

28 个 HTML 样稿分别在以下固定视口生成权威基线：

- 桌面：`1440×1000`；
- 平板：`1024×768`；
- 移动端：`390×844`。

总计 84 张全页迁移基线。每个 HTML 状态必须在视觉映射清单中对应一个确定的 React 路由、Fixture 名称、准备步骤和稳定断言。多个样稿可以映射到同一路由的不同真实页面状态，但不能合并掉样稿表达的用户可见状态。

删除规则新增的映射固定为：

- `正式课程大纲.html`：正式大纲默认状态，包含与普通导航分离的“删除课程”危险操作区；
- `课程永久删除确认.html`：同一正式大纲路由打开风险确认弹窗后的状态，不建立新的产品路由；
- `主页.html?simDeletedCourse=...`：只用于理解样稿中的删除成功提示；正式 React 通过真实删除结果重定向主页，不读取该模拟查询参数。

84 张 HTML 基线之外，React 长期回归还必须覆盖五个删除相关动态状态：确认提交中、删除失败可重试、删除成功主页提示、画像更新中、画像更新失败可重试。五个状态均覆盖三个视口，共增加 15 张 React 关键状态基线；它们执行关键组件 0.1% 差异阈值，不增加 HTML 样稿或 HTML 全页基线。

版本化证据统一放在 `tests/visual/`：状态映射、HTML 基线和 React 基线进入 Git；每次执行生成的 actual、diff、trace 和报告进入 `artifacts/visual/`，不作为权威基线提交。

### 4.2 确定性环境

视觉测试统一使用：

- 仓库锁定的 Playwright 和 Chromium/Edge 版本；
- 固定操作系统字体栈和字体加载完成条件；
- 固定时区、语言、颜色方案和缩放比例；
- 固定 Mock Provider、Fixture 数据、ID、时间和分页游标；
- 关闭 CSS 动画、过渡、光标闪烁和非确定性自动轮播；
- 等待字体、网络请求、图片和页面稳定标记完成后截图。

截图前必须验证 `document.fonts.check('16px "Times New Roman"')`、`document.fonts.check('16px SimSun')` 与 `document.fonts.check('18px SimHei')` 均为真；任一字体不可用时视觉测试直接失败，不允许静默使用不同字体生成或更新权威基线。

动态时间、内部 ID 和随机内容通过 Fixture 固定。不得通过大面积遮罩、隐藏正文或替换关键模块规避视觉差异。

### 4.3 差异阈值

- 全页截图：`threshold: 0.15`，`maxDiffPixelRatio: 0.003`；
- 关键组件局部截图：`maxDiffPixelRatio: 0.001`；
- 横向溢出、正文裁切、控件遮挡、不可读文字、缺失焦点样式和死按钮：零容忍；
- 截图差异报告必须保留 expected、actual、diff 三份证据。

初始权威基线来自冻结 HTML。某个 React 状态通过迁移验收后，同时保留 HTML 原始基线和 React 长期回归基线。HTML 基线证明迁移忠实度，React 基线保护后续产品回归。

禁止无审查批量执行 `--update-snapshots`。基线更新必须说明变化原因、受影响状态和三视口结果，并作为独立可审查变更提交。

## 5. React 模块边界

### 5.1 `packages/ui`

`packages/ui` 只负责纯视觉基础，不读取路由、不调用 API、不持有课程业务规则：

- 设计 token：颜色、字体、字号、行高、间距、圆角、阴影、层级和断点；
- 布局原语：Page、Stack、Grid、Sidebar、Panel、Toolbar；
- 通用组件：Button、Card、Badge、Tabs、Dialog、Toast、Field、Select、EmptyState、StatusBanner；
- AI 内容排版原语：AiContent；
- 课程模式视觉身份：统一 CSS Variables 与 `data-course-mode`；
- 全局语义状态：成功、警告、错误、只读、降级和重建。

课程模式色只能表达来源身份，不得覆盖成功、警告、错误、已放弃、只读等全局语义色。

### 5.2 `apps/web`

- `routes/*`：解析路由参数、加载页面数据、处理页面级导航；
- `features/*`：持有业务组件、页面 ViewModel 和局部交互状态；
- `client/*`：继续使用当前真实 API Client 与 SSE Client；
- `state/*`：继续管理命令幂等、版本保护和 page instance；
- `layouts/*`：组合正式 App Shell、全局导航与运行状态入口。

不新增全局状态库。只有确实跨路由共享且无法由服务端权威状态重建的数据，才允许进入现有状态层。

课程永久删除属于正式课程功能域：危险操作区、确认弹窗和删除命令编排位于课程 Feature；Dialog、危险按钮和 Toast 仍由 `packages/ui` 提供纯视觉能力。共享 UI 不知道 Course、Review、排期或画像删除语义。

### 5.3 全部 AI 生成内容的字体规范

`packages/ui` 提供唯一的 `AiContent` 原语和 `.lm-ai-content` 类。正式 token 固定为：

```css
:root {
  --lm-font-ai-heading: SimHei, "黑体", "Microsoft YaHei", sans-serif;
  --lm-font-ai-serif: "Times New Roman", SimSun, "宋体", serif;
  --lm-ai-prose-size: 16px;
  --lm-ai-prose-line-height: 1.8;
  --lm-ai-prose-weight: 700;
  --lm-ai-block-gap: 0.75em;
  --lm-ai-section-gap: 1.5em;
}

.lm-ai-content {
  font-family: var(--lm-font-ai-serif);
  font-size: var(--lm-ai-prose-size);
  line-height: var(--lm-ai-prose-line-height);
  font-weight: var(--lm-ai-prose-weight);
  font-kerning: normal;
  letter-spacing: normal;
  overflow-wrap: anywhere;
  text-rendering: optimizeLegibility;
}

.lm-ai-content :where(h1, h2, h3, h4, h5, h6) {
  font-family: var(--lm-font-ai-heading);
}
```

正文栈把 Times New Roman 放在第一位，使英文、拉丁数字和常用西文标点优先使用 Times New Roman；该字体缺失的中文字符回退到 Windows 宋体 SimSun。AI 标题不继承正文衬线栈，统一使用 SimHei/黑体。正式运行平台是 Windows，不以其他平台的近似字体生成权威截图。

必须使用 `AiContent` 的内容包括：

- 学习起点评估中的 AI 消息；
- AI 生成的候选大纲、正式大纲正文和调整建议；
- 正式学习会话中的 AI 消息与渐进式 Markdown；
- AI 生成的规划建议或计划流说明；
- 阶段 Review、最终课时 Review、课程主题总 Review 和上周学习回顾；
- AI 生成的学习画像标题、摘要、洞察正文与证据说明；
- 未来新增的任何 AI 生成 Markdown、富文本或长篇说明。

以下内容不使用该衬线排版：

- 用户输入、用户消息气泡和用户填写的主题；
- 导航、按钮、标签、状态、Toast、表单说明和统计数字；
- 服务端错误、诊断信息和内部运行状态；
- Markdown 中的 `code`、`pre`、`kbd`、`samp` 与代码编辑区，这些内容继续使用项目统一等宽字体。

AI Markdown 标题统一使用黑体并加粗，层级固定为：`h1 28px/1.35`、`h2 22px/1.4`、`h3 18px/1.45`；正文、列表、引用和表格正文统一 `16px/1.8/700`。段落、列表、引用、表格和代码块之间使用 `--lm-ai-block-gap`，标题与前一内容区使用 `--lm-ai-section-gap`；首尾多余外边距归零，列表缩进、表格单元格内边距与窄屏换行由 `AiContent` 集中定义。代码块保持常规字重。切片 1 依据三视口样稿和 0.3% 门禁统一微调这些 token，不在单个 Feature 内覆盖字体、字号、行高或间距。

## 6. 数据流与写入规则

读取数据固定经过：

`API/SSE → Route 编排 → Feature ViewModel → packages/ui 原语`

写操作固定经过：

`用户操作 → Feature 命令 → use-command-attempt/API Client → 服务端结果 → 重新拉取权威状态`

React 不复制服务端领域状态机，不以按钮禁用状态作为防重提交的唯一保障，不从样稿 JavaScript 搬运模拟 Repository、生成任务或时间状态。

所有进入 Feature ViewModel 的 AI 生成 Markdown 或富文本必须由 `AiContent` 包裹后渲染；是否属于 AI 生成内容由数据来源和字段语义决定，不使用文本内容、语言或 DOM 位置猜测。

课程永久删除的写入链路固定为：

`正式大纲危险操作 → 风险确认 → 幂等 DeleteCourse → 原子/可恢复级联删除 → 主页重定向与成功提示 → 历史投影重建和画像重算`

React 只展示服务端权威删除结果和后续重建状态，不自行从本地列表逐项模拟删除。删除提交后按钮进入 `aria-busy` 和禁用状态；重复提交必须复用同一命令身份。

视觉测试使用独立、确定性的 Fixture Harness，将固定 ViewModel 传给同一批 Feature 组件。生产代码不得增加 `demoMode`、样稿开关或只为截图存在的业务分支。

## 7. 共享页面状态与错误处理

所有页面统一支持：

- `loading`；
- `empty`；
- `error`；
- `degraded`；
- `rebuilding`；
- `version-mismatch`。

错误处理遵守以下规则：

- 请求失败后保留用户尚未提交的输入；
- 幂等重试复用同一次命令身份；
- 版本冲突显示权威新状态和安全恢复路径；
- SSE 重连先恢复服务端快照，再继续消费事件；
- 协议不匹配阻断写操作；
- Dialog 打开后焦点进入并限制在弹窗内，关闭后返回触发控件；
- 页面必须保留返回路径，失败遮罩不得永久阻断界面。

课程永久删除额外遵守：

- 入口位于正式大纲独立危险操作区，允许进行中、可关闭和已关闭课程使用；
- 弹窗只提供“取消”和“永久删除”，不要求输入课程名称；
- 提交中禁止重复操作，且删除开始后当前课程会话失去写入权；
- 删除失败时弹窗保留课程与全部原数据，显示可重试错误并允许取消；
- 删除成功后跳转主页，显示“课程及关联记录已永久删除”；
- 删除成功后，主页继续学习、课程切换、历史统计、学习日历和画像不得继续展示已删课程；
- 画像重算中或失败时只显示更新状态，不得回显已删除课程的证据或结论。

## 9. 每个切片的完成门禁

一个切片只有同时满足以下条件才完成：

- React 单元和交互测试通过；
- 对应真实 API E2E 通过；
- 课程永久删除切片覆盖取消、重复确认、进行中/已关闭课程、失败原样保留、成功后跨页面撤销和画像重算失败隔离；
- 对应全页截图差异不超过 0.3%；
- 对应关键组件截图差异不超过 0.1%；
- 无横向溢出、文字裁切、死按钮、未处理 Promise 或控制台错误；
- 所有 AI 生成内容均由 `AiContent` 渲染，标题计算字体为 SimHei 且加粗，英文正文为 Times New Roman、中文正文为 SimSun，正文计算字重为 700，代码计算字体为统一等宽字体且保持常规字重；
- 键盘路径、Dialog 焦点陷阱和关闭后焦点恢复通过；
- `pnpm verify` 保持绿色；
- 上一切片已验收 UI 不回退；
- 规格、视觉映射清单和项目上下文同步更新。

截图失败不得通过无说明更新基线解决。业务失败不得以静态 HTML、假数据或绕过真实 API 的方式隐藏。

## 10. 测试层级

- `packages/ui`：组件行为、ARIA、键盘和 token 契约测试；
- `apps/web`：Feature ViewModel、交互、错误恢复和路由测试；
- E2E：真实 Web/Server、临时数据根和 Mock Provider 的业务闭环；
- Visual：HTML 迁移对比和 React 长期回归两组截图；
- 静态审计：断链、死按钮、溢出、排版边界和禁止扩展 HTML 的规则；
- 全仓门禁：格式、Lint、类型、Schema、架构、等价矩阵、测试和构建。

视觉测试失败时输出可定位的状态名、视口、实际差异比例和差异图。业务 E2E 与视觉测试分开报告，避免视觉失败掩盖功能错误。

课程删除 E2E 必须从正式大纲发起真实命令，验证取消零写入、重复确认幂等、关联删除原子性、删除后主页重定向，以及主页、课程切换、历史、日历和画像全部不再引用该课程。不得用前端过滤结果替代服务端读取验证。

AI 排版测试必须覆盖中文、英文、中英混排、Markdown 标题、段落间距、列表、表格、引用、行内代码和代码块。浏览器断言读取计算样式、间距 token 和字体可用性；静态审计扫描所有已知 AI 输出入口，任何未使用 `AiContent` 的入口使门禁失败。

## 11. 非目标

- 不改变课程创建、学习、Review、课程关闭、规划、历史或画像的领域语义；
- 不把课程永久删除实现为关闭、归档、软删除、回收站或可恢复隐藏；
- 不重新设计后端架构或建立第二套 API；
- 不将 HTML 直接作为 React `dangerouslySetInnerHTML`、iframe 或静态页面嵌入；
- 不为了像素接近复制样稿中的模拟状态机；
- 不追求跨操作系统和跨浏览器的逐像素一致；正式视觉基线只针对项目锁定的 Windows Chromium/Edge 环境；

- 不把产品 UI、用户消息或统计数字整体切换为衬线字体；不把代码内容改为宋体或 Times New Roman。

## 12. 实施计划拆分

本设计覆盖多个可独立拒绝或验收的功能域，不写成一个不可审查的大计划。实施按以下子计划连续推进，每个子计划都引用本设计并继承全部全局门禁：
