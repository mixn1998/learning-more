# Learning MORE React UI 转段与像素级迁移设计

> 日期：2026-07-13  
> 状态：设计方向已批准，待书面复核  
> 适用范围：`apps/web`、`packages/ui`、正式 React 视觉测试，以及冻结后的 `docs/UI视觉预览`

## 1. 目标

Learning MORE 从 HTML UI 样稿阶段正式转入 React 产品界面建设。转段先完成一个短收口，再采用“共享基础 + 纵向切片”迁移全部功能域。迁移完成后：

- `apps/web` 是唯一正式产品 UI；
- `packages/ui` 提供稳定的设计 token、布局原语和通用组件；
- 27 个 HTML 样稿只保留为冻结的视觉与交互参考，不再扩展；
- React 页面保持现有真实 API、SSE、领域状态机、幂等和版本保护；
- 27 个权威样稿状态在桌面、平板、移动端形成 81 张截图基线；
- React 页面以全页差异不超过 0.3%、关键组件差异不超过 0.1% 的标准达到像素级接近。

## 2. 已批准的方案

采用“共享基础 + 纵向切片”。先建立 React 设计系统、视觉回归基础和正式 App Shell，再按完整业务闭环逐个迁移。每个切片必须交付可运行产品，不允许以半迁移页面、长期双轨样式或样稿模拟逻辑作为过渡终态。

未采用以下方案：

- 不先建设一个长期不可见的完整设计系统后再统一接页面；
- 不逐页复制 HTML、内联样式和模拟交互；
- 不新建第二套前端工程；
- 不继续扩大 HTML 样稿体系。

## 3. 权威输入与冻结规则

### 3.1 权威输入

- 产品与领域语义以 `CONTEXT.md`、`PROJECT_CONTEXT.md` 和 `docs/` 下专项规则为准；
- 路由、真实状态和数据边界以当前 React、共享合同和服务端公开 Interface 为准；
- 视觉层级、布局、样式和交互表现以 `docs/UI视觉预览` 中 27 个当前 HTML 样稿为迁移参考；
- 样稿与领域规则冲突时，领域规则优先，React 视觉 Fixture 必须表达真实领域状态。

### 3.2 HTML 冻结规则

短收口完成后，`docs/UI视觉预览` 进入冻结状态：

- 不新增页面、业务状态、交互路径、视觉变体或模拟数据模型；
- 不把 React 新功能反向实现到 HTML；
- 仅允许修复阻断基线生成的确定性问题、断链或明确的视觉基准错误；
- 任何允许的冻结后修复必须同时说明 React 映射与截图基线影响；
- README 和项目上下文必须明确 HTML 是只读参考，不是生产代码和后续设计工作区。

## 4. 像素级视觉基线

### 4.1 覆盖范围

27 个 HTML 样稿分别在以下固定视口生成权威基线：

- 桌面：`1440×1000`；
- 平板：`1024×768`；
- 移动端：`390×844`。

总计 81 张全页基线。每个 HTML 状态必须在视觉映射清单中对应一个确定的 React 路由、Fixture 名称、准备步骤和稳定断言。多个样稿可以映射到同一路由的不同真实页面状态，但不能合并掉样稿表达的用户可见状态。

版本化证据统一放在 `tests/visual/`：状态映射、HTML 基线和 React 基线进入 Git；每次执行生成的 actual、diff、trace 和报告进入 `artifacts/visual/`，不作为权威基线提交。

### 4.2 确定性环境

视觉测试统一使用：

- 仓库锁定的 Playwright 和 Chromium/Edge 版本；
- 固定操作系统字体栈和字体加载完成条件；
- 固定时区、语言、颜色方案和缩放比例；
- 固定 Mock Provider、Fixture 数据、ID、时间和分页游标；
- 关闭 CSS 动画、过渡、光标闪烁和非确定性自动轮播；
- 等待字体、网络请求、图片和页面稳定标记完成后截图。

动态时间、内部 ID 和随机内容通过 Fixture 固定。不得通过大面积遮罩、隐藏正文或替换关键模块规避视觉差异。

### 4.3 差异阈值

- 全页截图：`threshold: 0.15`，`maxDiffPixelRatio: 0.003`；
- 关键组件局部截图：`maxDiffPixelRatio: 0.001`；
- 横向溢出、正文裁切、控件遮挡、不可读文字、缺失焦点样式和死按钮：零容忍；
- 截图差异报告必须保留 expected、actual、diff 三份证据。

初始权威基线来自冻结 HTML。某个 React 状态通过迁移验收后，同时保留 HTML 原始基线和 React 长期回归基线。HTML 基线证明迁移忠实度，React 基线保护后续产品回归。

禁止无审查批量执行 `--update-snapshots`。基线更新必须说明变化原因、受影响状态和三视口结果，并作为独立可审查变更提交。

## 5. React 模块边界

### 5.1 `packages/ui`

`packages/ui` 只负责纯视觉基础，不读取路由、不调用 API、不持有课程业务规则：

- 设计 token：颜色、字体、字号、行高、间距、圆角、阴影、层级和断点；
- 布局原语：Page、Stack、Grid、Sidebar、Panel、Toolbar；
- 通用组件：Button、Card、Badge、Tabs、Dialog、Toast、Field、Select、EmptyState、StatusBanner；
- 课程模式视觉身份：统一 CSS Variables 与 `data-course-mode`；
- 全局语义状态：成功、警告、错误、只读、降级和重建。

课程模式色只能表达来源身份，不得覆盖成功、警告、错误、已放弃、只读等全局语义色。

### 5.2 `apps/web`

- `routes/*`：解析路由参数、加载页面数据、处理页面级导航；
- `features/*`：持有业务组件、页面 ViewModel 和局部交互状态；
- `client/*`：继续使用当前真实 API Client 与 SSE Client；
- `state/*`：继续管理命令幂等、版本保护和 page instance；
- `layouts/*`：组合正式 App Shell、全局导航与运行状态入口。

不新增全局状态库。只有确实跨路由共享且无法由服务端权威状态重建的数据，才允许进入现有状态层。

## 6. 数据流与写入规则

读取数据固定经过：

`API/SSE → Route 编排 → Feature ViewModel → packages/ui 原语`

写操作固定经过：

`用户操作 → Feature 命令 → use-command-attempt/API Client → 服务端结果 → 重新拉取权威状态`

React 不复制服务端领域状态机，不以按钮禁用状态作为防重提交的唯一保障，不从样稿 JavaScript 搬运模拟 Repository、生成任务或时间状态。

视觉测试使用独立、确定性的 Fixture Harness，将固定 ViewModel 传给同一批 Feature 组件。生产代码不得增加 `demoMode`、样稿开关或只为截图存在的业务分支。

## 7. 共享页面状态与错误处理

所有页面统一支持：

- `loading`；
- `empty`；
- `error`；
- `degraded`；
- `rebuilding`；
- `version-mismatch`。

错误处理遵守以下规则：

- 请求失败后保留用户尚未提交的输入；
- 幂等重试复用同一次命令身份；
- 版本冲突显示权威新状态和安全恢复路径；
- SSE 重连先恢复服务端快照，再继续消费事件；
- 协议不匹配阻断写操作；
- Dialog 打开后焦点进入并限制在弹窗内，关闭后返回触发控件；
- 页面必须保留返回路径，失败遮罩不得永久阻断界面。

## 9. 每个切片的完成门禁

一个切片只有同时满足以下条件才完成：

- React 单元和交互测试通过；
- 对应真实 API E2E 通过；
- 对应全页截图差异不超过 0.3%；
- 对应关键组件截图差异不超过 0.1%；
- 无横向溢出、文字裁切、死按钮、未处理 Promise 或控制台错误；
- 键盘路径、Dialog 焦点陷阱和关闭后焦点恢复通过；
- `pnpm verify` 保持绿色；
- 上一切片已验收 UI 不回退；
- 规格、视觉映射清单和项目上下文同步更新。

截图失败不得通过无说明更新基线解决。业务失败不得以静态 HTML、假数据或绕过真实 API 的方式隐藏。

## 10. 测试层级

- `packages/ui`：组件行为、ARIA、键盘和 token 契约测试；
- `apps/web`：Feature ViewModel、交互、错误恢复和路由测试；
- E2E：真实 Web/Server、临时数据根和 Mock Provider 的业务闭环；
- Visual：HTML 迁移对比和 React 长期回归两组截图；
- 静态审计：断链、死按钮、溢出、排版边界和禁止扩展 HTML 的规则；
- 全仓门禁：格式、Lint、类型、Schema、架构、等价矩阵、测试和构建。

视觉测试失败时输出可定位的状态名、视口、实际差异比例和差异图。业务 E2E 与视觉测试分开报告，避免视觉失败掩盖功能错误。

## 11. 非目标

- 不改变课程创建、学习、Review、课程关闭、规划、历史或画像的领域语义；
- 不重新设计后端架构或建立第二套 API；
- 不将 HTML 直接作为 React `dangerouslySetInnerHTML`、iframe 或静态页面嵌入；
- 不为了像素接近复制样稿中的模拟状态机；
- 不追求跨操作系统和跨浏览器的逐像素一致；正式视觉基线只针对项目锁定的 Windows Chromium/Edge 环境；
- 不在本轮引入新的 UI 框架或全局状态库。

## 12. 实施计划拆分

本设计覆盖多个可独立拒绝或验收的功能域，不写成一个不可审查的大计划。实施按以下子计划连续推进，每个子计划都引用本设计并继承全部全局门禁：

1. 转段短收口、HTML 冻结、视觉基线基础和 React 设计系统；
2. 主页、课程创建与正式大纲；
3. 课程规划与计划流；
4. 正式学习、Review 与课节记录；
5. 历史统计、周回顾、学习日历与学习画像；
6. 运行中心、81 张视觉基线全量收口与发布门禁。

前一个子计划通过完整门禁后才能进入下一个。后续计划不得重新解释已经批准的视觉阈值、组件边界、数据流或 HTML 冻结规则。

## 13. 最终完成条件

转段目标只有在以下证据全部成立时完成：

1. HTML 样稿已冻结且项目文档不再把项目描述为等待编码；
2. `apps/web` 覆盖七个功能域和全部已确认用户可见状态；
3. `packages/ui` 提供获批的共享基础且无业务依赖；
4. 27 个 HTML 状态全部存在 React 映射；
5. 81 张 HTML 对比基线和 81 张 React 长期回归基线均可重复生成；
6. 全页差异不超过 0.3%，关键组件差异不超过 0.1%；
7. 全量 React、E2E、视觉、键盘、焦点和三视口验证通过；
8. `pnpm verify`、视觉门禁和发布相关检查全部绿色；
9. 不存在依赖 HTML 样稿才能完成的生产用户路径；
10. 不存在继续扩大 HTML 样稿体系的活跃计划或未完成入口。
