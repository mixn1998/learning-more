# 无检测课程教学语义设计

## 目标

正式课程不再以“检测、通过、掌握判定”组织教学。知识点后的问题是非强制互动邀请，原“综合检测”调整为一次可参与、可跳过的“综合应用”。教学推进依据教学责任是否完成以及相关疑问是否得到处理，不以用户回答正确或连续正确作为门禁。

## 统一业务语义

- 知识点提问是互动邀请，不是检测。用户可以回答、提出其他相关思路、继续追问或明确跳过互动。
- 用户回答用于发现理解缺口并调整解释，不产生“通过/未通过”状态。
- 教学智能体完成当前知识点的必要讲解并处理相关疑问后，可以小结并推进；不得等待两次正确回答。
- 全部知识点完成或跳过后进入综合应用。综合应用只提供一次跨知识点迁移任务，用户可回答或跳过。
- 综合应用回答不足时进行纠偏和解释，但不再次追问同一应用任务；随后进入讨论答疑。
- 课程闭环仍保持“讨论答疑 → 用户明确没有其他问题 → 最终总结 → 可结束本课”。
- 学习行为和理解表现仍由教学观察及 Review 链路记录，不作为教学账本的通过门禁。

## 运行时兼容

- 新生成协议使用 `comprehensive_application`。
- 历史持久化状态中的 `comprehensive_check` 在读取和解析边界归一化为新阶段，不要求批量重写旧会话。
- 旧 `verificationSignals` 与 `verificationStreak` 数据只为历史读取兼容保留，不再驱动知识点完成或阶段推进。
- 新回复不再要求生成验证信号；理解缺口和深入讲解需求继续通过既有难点信号链路记录。

## 提示词与上下文

- 以人工调整后的正式课程提示词快照为运行策略来源。
- 清除“知识点检测、理解检测、检测通过、综合检测”等旧教学措辞。
- 按快照取消近期学习者信号、相关 Review 摘要和相关学习材料三个运行时注入段；保留固定个性化背景、课程邻接探索、真实对话和权威教学账本。
- 课程语言风格继续跟随大纲目标、课程内容与互动形式。

## 前端与文档

- 学习线索节点显示“综合应用”；完成态显示“综合应用已完成”，跳过态显示“跳过综合应用”。
- 知识点进度继续使用 `pending / learning / completed / skipped`，不显示通过或未通过。
- 教学观察、产品现状文档和运行态快照统一使用新语义。

## 验证

- 协议解析接受新阶段，并兼容旧阶段。
- 用户未回答知识点互动时不会被正确次数门禁阻塞。
- 综合应用完成或跳过后可以进入讨论答疑。
- 历史 `comprehensive_check` 会话可以正常恢复和投影。
- 提示词快照与实际组装文本不再出现教学意义上的“检测/通过”残留。
