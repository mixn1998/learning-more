# 历史统计工作区回退修复设计

## 视觉基线

历史统计页以 `docs/UI视觉预览/06-历史统计与学习画像/历史统计.html` 为视觉与信息架构基线。生产页面继续使用真实接口数据，不复制样稿中的演示数值。

## 问题

新版 `HistoryStatisticsWorkspace` 已实现样稿结构，但 `HistoryPage` 只有在统计数据和主页课程目录同时成功时才渲染它。课程目录请求失败会让整页回退到旧版通用历史页面，导致原始事件 ID、ISO 时间线、旧指标卡与“重试失败模块”暴露出来。

## 目标行为

- 统计数据可用时始终渲染样稿对应的历史统计工作区。
- 课程目录数据失败只影响“历史课程”区域，不改变整页结构。
- 指标、趋势和参与事实继续由统计、日历与历史事实计算。
- 缺少课程目录时，不展示原始课程或课节 ID；历史课程区域显示局部错误说明。
- 日历和画像页的现有路由与行为不变。

## 实现

- `buildStatisticsSnapshot` 接受可选的主页课程目录，并在缺失时用事实自身的 `courseId` 计算可用指标。
- `buildStatisticsCourses` 在目录缺失时返回空课程列表。
- `HistoryPage` 的新版统计工作区只依赖统计数据，不再依赖课程目录成功。
- `HistoryStatisticsWorkspace` 接收可选的目录错误信息，在历史课程面板内显示“课程目录暂不可用”。

## 验证

- 模拟 `getDashboard` 失败且统计接口成功时，仍显示“历史统计”、范围筛选、指标、趋势和课程面板。
- 同一场景不出现旧版“学习时间线”。
- 课程面板显示局部目录错误，不显示原始 ID。
- 目录成功时的课程筛选、排序和打开课程行为保持不变。
