# 正式课程生成性能优化设计

## 目标

在不降低重点、难点教学深度，不破坏公式、Markdown、任务恢复与教学账本一致性的前提下，降低正式课程 AI 回合的首段等待和正文结束后的收尾等待。

当前 30 个真实成功回合基线：首段 P50 29.0 秒、P90 34.0 秒；正文流式 P50 5.4 秒；正文结束至任务完成 P50 7.4 秒；总耗时 P50 41.3 秒。

## 设计

1. 教学控制协议增加版本 2 的稀疏指令。模型只返回本轮发生变化的阶段字段、知识点字段和新增难度信号；服务端基于当前教学账本物化为完整状态，再沿用现有门禁校验。版本 1 完整快照继续兼容历史任务和恢复流程。
2. 稀疏指令必须具备幂等性。重复应用同一指令不得增加难度信号或回退已完成节点；知识点引用仍由服务端按照大纲验证。
3. 可见回复继续先于隐藏控制指令输出，句子/段落级流式和 Markdown 安全边界保持不变。
4. 生成任务记录可计算的分段时间：提交、Provider 开始、首个 Provider 增量、Provider 完成、消息提交与投影完成。性能测试使用真实任务日志的同一定义。
5. Codex app-server 启动与前端投影轮询只做不改变业务语义的固定耗时优化；如果持久进程复用不能保证并发隔离和取消语义，则不以牺牲可靠性换取约 1～3 秒收益。

## 验收

- 版本 1、版本 2 指令均可解析、校验、应用和恢复。
- 版本 2 未提供的字段保持账本当前值。
- 版本 2 控制输出不再要求返回所有知识点，典型控制 JSON 明显短于完整快照。
- 现有教学闭环、跳过、难点计数、暂停生成和恢复测试保持通过。
- 类型检查通过，并以激活版本的真实教学回合重新测量分段耗时。
