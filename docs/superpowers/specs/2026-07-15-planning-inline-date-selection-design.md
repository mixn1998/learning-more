# 课程规划行内日期选择设计

## 目标

课程规划页面初次打开时不默认选中“今日”，而是展示全部可规划课节。课节排期改为行内原生日期选择器，用户选择日期后立即保存，不再打开日期弹窗。

## 用户行为

- 初次进入课程规划时，七天日期列表没有任何选中项。
- 未选择日期时，主列表展示全部待规划、已安排和已逾期课节。
- 用户主动点击某个日期后，主列表才按该日期筛选。
- 每个课节行直接显示原生日期输入控件。
- 未排期课节的日期输入为空；已排期课节显示当前排期日期。
- 日期输入的最小可选日期为规划锚点日期（今日）。
- 用户选择日期后立即创建或移动排期，不需要再次确认。
- 排期成功后不自动改变左侧日期筛选，避免列表上下文突然变化。
- “取消排期”和“预览”行为保持不变。

## 组件与状态

### PlanningWorkspaceView

- `selectedDate` 初始值由 `anchorDate` 改为空字符串。
- 删除日期弹窗相关的 `scheduleTarget`、`draftDate`、`openSchedule` 和 `saveSchedule` 状态与渲染。
- 课节行中的日期触发按钮替换为受控的 `<input type="date">`。
- 增加按课节标识的临时日期、保存中状态和错误状态，确保异步保存期间输入值稳定，失败时可恢复原日期。

### PlanningDateFilter

- 初始选择由今日改为空字符串。
- 空选择表示展示全部候选课节。
- 日期和“待规划”仍保持互斥筛选行为。

## 数据流

1. 用户在课节行选择日期。
2. 组件立即记录该课节的临时日期并禁用当前日期输入。
3. 未排期课节调用 `onCreate`；已排期课节调用 `onMove`。
4. 成功后由父组件更新权威排期数据，组件清除临时状态。
5. 失败后组件清除临时日期、恢复权威日期，并在当前课节行显示错误。

## 错误与并发

- 保存过程中只禁用当前课节的日期输入，其他课节仍可操作。
- 同一课节保存中不接受重复日期变更。
- 保存失败不打开全局弹窗，不改变筛选，仅在对应课节行展示可理解的错误提示。
- 现有版本冲突与排期锁定逻辑继续由 `PlanningPage` 的 `onCreate`、`onMove` 实现负责。

## 测试

- 初始状态没有日期处于按下状态，并展示全部候选课节。
- 点击具体日期后只展示该日期的课节。
- 点击/修改日期输入不会创建日期对话框。
- 未排期课节选择日期后立即调用 `onCreate`。
- 已排期课节选择日期后立即调用 `onMove`。
- 保存失败后恢复原日期并显示行内错误。
- `PlanningDateFilter` 初始展示全部候选，主动选择后正确筛选。

## 非目标

- 不实现自定义日历组件。
- 不改变排期默认学习时间和预计时长计算。
- 不改变取消排期、计划流、课节预览或服务端排期契约。
