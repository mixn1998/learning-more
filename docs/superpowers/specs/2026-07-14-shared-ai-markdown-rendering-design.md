# 共享 AI Markdown 渲染边界设计

> 日期：2026-07-14  
> 状态：已确认设计，等待实施计划  
> 范围：课程创建、正式教学、Review、周报、学习画像、历史记录及后续新增 AI 输出页面

## 1. 目标

所有用户可见的原始 AI 文本统一经过安全 Markdown 渲染，不再由页面自行决定把模型输出当普通字符串还是 Markdown。标题、段落、列表、引用、表格和代码块使用同一套语义排版；删除现有 AI 专属宋体、Times New Roman、黑体和正文全局粗体设定，AI 内容继承产品字体体系。

本改造只改变表达层，不改写模型内容，不增加生成调用，不增加输出修复模型，也不使用格式 Prompt 限制模型的教学自由度。

## 2. 已确认问题

课程创建页面将助手消息作为 `AiContent` 的普通 `children` 传入。该分支不调用 `ReactMarkdown`，因此模型返回的 `**加粗**`、列表标记和段落换行被当成普通文本显示。与此同时，共享样式把 AI 正文设为衬线字体和 700 字重，页面又存在多处 AI 标题/正文专属字体覆盖，最终形成大段、粗重且层级不清的视觉结果。

共享组件已经具备 `ReactMarkdown + rehype-sanitize`，问题在于边界可被绕过，并非缺少 Markdown 能力。

## 3. 设计原则

1. **原始 AI 文本只有一个渲染入口。** 任意来自生成任务、Review、周报、画像或历史消息的 Markdown 字符串必须传给共享 `AiContent` 的 `markdown` 属性。
2. **结构化结果与原始文本分开。** 已通过领域 Schema 解析为标题、卡片、指标或模块数组的结果继续使用 React 结构化布局，但不得借用原始 Markdown 渲染接口。
3. **安全先于表现。** Markdown 不启用原始 HTML；继续使用 `rehype-sanitize`，禁止脚本、事件属性和危险协议进入 DOM。
4. **排版约束在前端，不进入 Prompt。** 模型可以自由选择标题、段落、列表、引用和表格，前端只负责一致呈现，不要求固定章节或固定模板。
5. **页面只管布局。** 业务页面可以调整容器宽度、背景、边框和颜色，不得重新定义 AI 正文的字体族、基础字重或 Markdown 元素间距。

## 4. 组件边界

### 4.1 `AiContent`

`AiContent` 变为原始 Markdown 专用组件：

- 必须接收 `markdown: string`；
- 统一调用 `ReactMarkdown`；
- 继续挂载 `data-ai-content="true"` 和 `.lm-ai-content`；
- 不再接受普通文本 `children`，从类型层阻止未来绕过 Markdown 渲染；
- 空字符串生成空内容容器，不自行补写业务文案。

### 4.2 结构化 AI 展示容器

课程候选大纲、课程 Review 等已经解析为结构化字段的页面不需要把 JSX 再转换成 Markdown。它们使用独立的 `AiSurface` 展示容器，仅提供 AI 内容区域的通用可访问性和布局类，不执行 Markdown 解析，也不接受未解析的模型字符串。

这一区分保证：

- `AiContent` 出现时一定代表安全渲染后的 Markdown；
- `AiSurface` 出现时一定代表领域层已经验证过的结构化结果；
- 普通字符串不能借任一接口伪装成已经安全处理的 AI 内容。

## 5. 数据流

```text
原始生成 Markdown
  -> 业务合同/持久化（内容不改写）
  -> AiContent(markdown)
  -> ReactMarkdown
  -> rehype-sanitize
  -> 共享 Markdown 语义样式

结构化 AI 结果
  -> Schema/领域规则校验
  -> 结构化 ViewModel
  -> AiSurface + React 组件
```

禁止增加以下路径：

- 模型输出后再调用模型整理格式；
- 用正则重写模型段落或自动插入标题；
- 页面直接使用 `dangerouslySetInnerHTML`；
- 页面直接输出未解析的 AI Markdown 字符串。

## 6. 统一视觉规则

### 6.1 删除规则

删除共享和页面级的以下 AI 专属设置：

- `--lm-font-ai-heading`；
- `--lm-font-ai-serif`；
- AI 正文全局 `font-weight: 700`；
- 课程创建、正式教学、历史记录、Review 和画像中对上述变量的覆盖或引用。

代码字体继续使用 `--lm-font-code`，因为等宽字体表达代码语义，不属于 AI 身份化字体。

### 6.2 保留的语义层级

- AI 正文继承产品字体，基础字重为 400，使用统一可读字号和行高；
- `h1/h2/h3` 仅通过字号、字重和上下间距形成层级，不切换字体族；
- 相邻段落、列表、引用、表格和代码块使用统一块间距；
- 列表恢复规范缩进，列表项之间留出轻微间距；
- 引用使用左边线、浅背景和适度内边距；
- 表格允许横向滚动或在容器内换行，不撑破页面；
- 行内代码和代码块使用等宽字体并保持可复制性；
- 首个元素无额外顶边距，末个元素无额外底边距。

## 7. 页面迁移范围

必须审计并迁移：

1. 课程创建评估消息和候选调整消息；
2. 正式教学实时消息、停止后的部分消息和历史教学记录；
3. 阶段 Review、最终 Review、课程 Review；
4. 周报摘要与正文；
5. 学习画像摘要、洞察和证据说明；
6. 大纲调整对话；
7. 后续所有通过共享 UI 包展示的原始 AI 文本。

静态占位文案不是 AI 输出，应使用普通产品组件，不再包在 `AiContent` 中。

## 8. 错误与边界行为

- Markdown 语法不完整时按 CommonMark 的容错结果显示，不进行二次生成；
- 原始 HTML 被忽略或净化，不作为富文本能力开放；
- 超长单词、链接和代码不得撑破容器；
- 空 Markdown 不显示伪造占位内容，业务页面按自身状态显示加载、空态或失败态；
- 流式 Markdown 在生成中允许暂时不闭合，后续增量到达后自然恢复结构。

## 9. 验收标准

1. 截图中的 `**token 是哪一种**` 显示为加粗文本，不显示星号。
2. 四类 token 显示为真正的列表，每项独立成行且有统一缩进与间距。
3. 选项 A/B/C/D 不再与上一段挤成一行；若模型输出为列表，则按列表呈现。
4. 所有 AI 页面不再使用 AI 专属宋体、Times New Roman、黑体或正文 700 字重。
5. `<script>`、事件属性和危险 HTML 不进入 DOM。
6. 类型检查能够阻止把原始字符串作为 `AiContent` children 传入。
7. 课程创建、正式教学、Review、周报、画像和历史记录的组件测试覆盖 Markdown 标题、粗体、列表和引用。
8. 全量 typecheck、lint、unit test、构建和相关 Playwright/视觉测试通过。

## 10. 明确不做

- 不要求模型遵循固定回答模板；
- 不增加 Markdown 格式修复 Agent 或观察器；
- 不把普通用户消息改成 Markdown 富文本；
- 不支持任意 HTML、外部脚本或交互式嵌入；
- 不因排版统一改变课程创建、教学观察、教学账本或 Review 的业务状态。
