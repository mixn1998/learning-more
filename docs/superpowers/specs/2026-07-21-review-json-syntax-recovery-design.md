# Review JSON 语法自动恢复设计

## 目标

Review 生成结果包含可恢复的 JSON 语法错误时，由解析器自动修复并继续生成 Review，避免因单个括号、逗号、引号或转义错误导致整份结果作废。

## 边界

- 首次仍使用原生 `JSON.parse`，保持正常路径不变。
- 首次解析失败后才进入语法修复。
- 修复器只调整 JSON 语法，不补写 Review 字段、不改写文本内容、不生成证据引用。
- 修复结果必须重新通过现有 `ReviewDocumentSchema`、预期 `kind` 和后续输出校验。
- 修复或契约校验失败时保持现有 `review_output_contract_invalid`，不自动重新生成。

## 实现

在 Review writer 内增加独立的深模块解析函数：先提取首个 JSON 对象范围，再尝试严格解析；失败时调用保守语法修复器，并重新解析。解析出的对象统一交给现有 Zod 契约校验，调用方接口和任务数据流不变。

优先采用项目内的确定性修复器，覆盖结构括号失衡、尾随逗号、缺失分隔符和常见字符串转义错误。修复器不得依据 Review 业务语义猜测字段内容。

## 验证

- 合法 Review JSON 原样通过。
- 本次真实故障形态（根对象提前多关闭一个 `}`）可恢复。
- 无法安全修复的截断内容仍失败。
- 修复后缺少必填字段、kind 错误或字段类型错误仍被契约拒绝。
- Review writer 的公开接口和成功结果行为不变。
