# Learning MORE 基础模块功能等价清单与回归基线

> 文档角色：自动化等价检查的机器可读兼容基线，不再承担项目当前功能设计说明。当前产品事实以 [`项目2.0现状/01-功能设计层.md`](./项目2.0现状/01-功能设计层.md) 为准；本文件中的 `EQ-*` 行继续与 `架构方案/equivalence-matrix.yaml` 同步，供架构工具读取。

## 1. 文档目的

本文保留从旧 `learning-demo` 迁移时形成的可观察行为断言。它现在只用于自动化回归和兼容性核验，不表示所有旧项目结构、页面或术语仍属于当前产品。

旧项目基线：内部迁移资料，不随公开仓库分发。

本文同时作为：

- 新项目范围清单；
- 模块重写验收标准；
- 旧项目对照测试来源；
- 课程学习流重构后的防回归基线。

## 2. 等价原则

### 2.1 必须等价

- 相同用户操作产生语义一致的结果；
- 相同有效输入遵守一致的业务不变量；
- 空状态、加载、失败、重试和恢复路径完整；
- 已完成学习事实能够被历史、日历、画像和课程表一致消费；
- AI 不可用时不会破坏已保存数据或让页面永久卡死；
- 页面刷新、切换模块或服务短暂中断后，可恢复的状态能够恢复；
- 用户可见文案不泄露内部字段、Prompt 合同或模型推断术语。

### 2.2 不要求等价

- 文件结构、函数名称和旧接口路径；
- 旧 `Project → Topic → Curriculum → Lesson` 数据模型；
- 原生 JavaScript DOM 控制方式；
- 旧 CSS、旧视觉样式和像素级布局；
- 旧思维模式字段、旧建档字段和旧 JSON 课程合同；
- 旧项目为兼容历史数据保留的分支。

### 2.3 明确排除

- 灵感放送及其缓存、临时课、收藏、预热和历史分支；
- 标准建档表单、建档草稿和补充字段接口；
- `learningStructureMode/structureMode` 思维模式标签系统；
- 旧课程正文预生成、检测题和旧 LearningRecord 主流程；
- 旧项目数据的运行时兼容读取。

## 3. 新项目中的公共事实来源

所有基础模块不得直接读取课程学习模块内部状态，只消费共享合同中的学习事实与读模型。

核心事实事件至少包括：

```text
OutlineSessionCreated
CourseCreated
OutlineVersionConfirmed
LessonSessionStarted
LessonSessionPaused
LessonAbandoned
LessonRestored
LessonSessionCompleted
InteractionPrompted
InteractionResponded
InteractionSkipped
ReviewCreated
ReviewFinalized
RecommendedLessonChanged
CourseClosed
SchedulePlanned
ScheduleChanged
ScheduleCancelled
PlanFlowCreated
PlanFlowPaused
PlanFlowResumed
PlanFlowReplanned
PlanFlowDeleted
SupplementarySessionArchived
```

页面访问、玩法入口点击、AI Provider 切换、生成耗时、网络和错误等属于产品或运行遥测，不属于学习事实事件，不得进入全局学习档案。

统一读模型至少包括：

- `CourseSummaryReadModel`：正式课程、标签、课节、进度和推荐课节；
- `LearningHistoryReadModel`：已完成课节会话与 Review；
- `LearningHistoryStatsReadModel`：统计、分布、趋势和证据覆盖；
- `LearningCalendarReadModel`：按本地自然日聚合的完成记录；
- `GlobalLearningProfileReadModel`：全部学习统计快照、指标时间序列、画像候选证据、Artifact 索引、证据 backlog 和画像版本引用；
- `LearningPortraitReadModel`：当前成功画像版本的自由标题、自由摘要、数量不定的自由洞察和可展开复合行为证据链；
- `LearningScheduleReadModel`：未排期、已排期、今日、逾期、完成和取消条目；
- `GenerationTaskReadModel`：生成任务的排队、运行、进度、耗时估计和取消状态；
- `AiRuntimeStatusReadModel`：Provider、模型、可用性、配置和诊断信息。

## 4. 应用壳与首页

### 4.1 首页稳定结构

首页继续保留三类主区域，允许统一升级视觉：

1. 左侧玩法栏；
2. 中央主要工作区；
3. 课程表与课程规划区域。

首页必须提供：

- 直接输入“想学什么”的对话式课程创建入口；
- 继续学习入口；
- 历史记录入口；
- 课程表视图与课程规划视图切换；
- 当前 AI Provider 状态入口；
- 服务异常时的重连/自愈入口。

首页不再显示独立的“创建档案”或“创建课程”按钮。顶部学习计划区直接提供主题输入框和“开始学习起点评估”提交操作：

- 用户只输入自然语言主题，不填写学科、阶段、时长、思维模式或知识范围；
- 空输入不得提交；
- 提交后立即进入“学习档案创建 / 学习起点评估”页面，不等待 OutlineSession 创建请求完成；首屏同步展示固定起始说明、原始主题和思考占位，随后与服务端权威会话对齐；
- 此时不创建正式 Course；只有最终大纲确认后才创建正式课程；
- 历史记录与继续学习入口继续保留，但视觉层级低于主题输入主操作；
- 未完成的评估/大纲会话可从首页恢复，不与正式课程进度混淆。

### 4.2 继续学习状态

- 没有正式课程时，引导用户开始创建课程；
- 有学习中课节时恢复暂停学习后保留的原始可写会话；没有学习中课节时进入推荐课节；已放弃课节不作为默认继续入口，只能由用户显式恢复；
- 不存在未完成且未放弃的可继续课节时，不伪造学习任务，转为创建新课程、扩展课程或管理已放弃课节；
- 未确认的大纲会话独立显示为“待完成课程创建”，不混入正式课程进度；
- 继续学习的判断基于新 `CourseSummaryReadModel`，不依赖旧综合复习节点。

### 4.3 页面状态恢复

- 刷新后恢复当前正式课程、当前课节或待完成大纲会话；
- 玩法输入草稿与已提交运行态分离；
- 已提交成功的草稿自动清除；
- 当前生成任务恢复时显示真实服务端任务，不伪造本地进度；
- 无法恢复的旧临时状态应明确说明并回到安全入口。

### 4.4 主页与历史记录页布局保持

- 主页保留现有的全局状态栏、顶部学习计划区、左侧玩法栏和右侧课程表/课程规划主体布局；
- 历史功能区保留标题操作区、历史统计/学习日历两个同级 Tab，以及两个独立视图的主内容结构；
- 学习日历保留左侧月历与右侧选中日期详情的双区布局；
- 允许统一升级颜色、字体、间距、圆角、边框、阴影、图标和状态层级；
- 不以视觉美化为由改变组件位置、主要尺寸关系、操作入口或信息层级；
- 响应式下可以重排，但桌面端必须保持现有组件结构的识别连续性。
- 桌面端左侧玩法栏、课程规划日期栏和上周回顾日期栏使用粘性定位，随页面或右侧内容滚动保持可见；
- 左侧栏自身高于可视窗口时才允许左栏内部滚动；移动端取消粘性并回到正常文档流。
- 桌面端课程规划页和上周回顾页的左右两栏必须共享同一可视高度，顶部与底部视觉对齐；左侧七天日期卡在可视高度内均匀铺满且不产生内部滚动，只有右侧内容超出时允许栏内滚动。
- 移动端转为单列后取消等高与栏内滚动约束，由内容自然撑开页面。

## 5. 左侧玩法栏

### 5.1 入口结构

主页设置八个同级玩法壳：

1. 头脑风暴；
2. 论证交锋；
3. 案例研习；
4. 商业洞察；
5. 流程拆解；
6. 决策分析；
7. 交叉探索；
8. 阅读研讨。

灵感放送不再显示，也不保留隐藏入口。

所有玩法壳入口必须：

- 可从首页进入和返回；
- 当前只负责导航和身份传递，不预设玩法业务规则；
- 通过唯一 `courseMode` 标记入口身份；
- 创建正式课程前不得提前写入 `Course`；
- 不再通过思维模式字段驱动课程结构；
- 后续专项设计确认后，才接入统一课程创建会话。

### 5.2 八个同级玩法壳

以下八个入口在新项目中处于同一层级、具有相同性质：

1. 头脑风暴；
2. 论证交锋；
3. 案例研习；
4. 商业洞察；
5. 流程拆解；
6. 决策分析；
7. 交叉探索；
8. 阅读研讨。

当前阶段只定义共同的壳能力：

- 在左侧玩法栏拥有独立名称、说明、图标和视觉身份；
- 点击后进入对应的课程创建入口；
- 入口向统一课程创建流程传递唯一 `courseMode`；
- 可以显示“尚未设计”或设计中的安全状态；
- 可以返回主页，不产生正式课程或学习事实；
- 不复用旧项目任何玩法内部流程作为默认实现。

当前阶段明确不继承：

- 旧玩法专属表单及固定字段；
- 旧思维模式映射；
- 旧课程类型、阶段和时长映射；
- 旧玩法专属 Prompt 与 JSON 输出合同；
- 旧临时课程、直接建档、转档案或玩法历史逻辑；
- 旧检测题和课节特殊规则；
- 旧玩法产生的画像写回规则。

八个玩法均复用通用课程创建与学习流，通过整体、非强制玩法意图区分主体验；四类设计观察面不得成为运行时字段、课程模块、阶段、固定课节类型或 Prompt 执行清单。玩法层不维护方法清单，具体教学方法由 AI 自主决定。详细规则见《八大玩法功能规则》。

## 6. 课程表

### 6.1 条目来源

课程表从所有正式课程的 `LessonDefinition`、课节生命周期和已完成状态生成条目，不读取学习对话正文。已放弃课节不进入当前待办课程表，但其既有排期与状态变更历史不得删除。

每个条目至少包含：

- `courseId`、`lessonId`；
- 课程名、课节名；
- `disciplineTag`、`topicTags`；
- 预计时长；
- 计划日期；
- 状态；
- 计划流来源、锁定状态和超目标状态。

### 6.2 状态规则

必须支持：

- `unscheduled`：未排期且未完成；
- `scheduled`：未来日期；
- `due_today`：计划日期为今天且未完成；
- `overdue`：计划日期早于今天且未完成；
- `completed_today`：今天完成；
- `completed`：已完成；
- `cancelled`：取消排期。

课程规划的“排期状态”不直接保存上述读模型状态，而只对可排期课节实时派生并显示为三类：

- `待规划`：无计划日期；
- `已安排`：计划日期为今天或未来；
- `已逾期`：计划日期早于今天。

已完成与已放弃课节不进入课程规划的待排期列表；`completed`、`cancelled` 等历史读模型状态仍保留给历史统计、日历和审计，不得被课程规划的显示状态覆盖。

未排期且已完成的条目不进入待办课程表，但仍进入历史和日历。

课节生命周期与排期状态是两个维度，不得混用：

- `in_progress` 统一显示为“学习中”，对应一条可恢复的可写学习会话；可排期、进入计划流和作为推荐候选；
- `abandoned` 不可进入新排期、计划流或推荐候选；
- 放弃已有排期的课节时，当前有效排期转为取消并注明课节放弃原因，不删除排期历史；
- 恢复课节后不自动恢复旧排期，由用户重新排期或重新加入计划流。

### 6.3 展示与筛选

- 支持课程表日历视图和课程规划视图；
- 周课程表的每个日期格直接展示当天安排的具体课节名称，不只显示数量；
- 周历日期卡使用更高的稳定高度，优先完整显示最多五节具体课名；超过五节时显示“还有 N 节”；
- “今日学习”区域展示当天全部具体课节列表，并可从列表直接进入对应课节；
- “今日学习”使用单列紧凑列表，课节数量为奇数或达到五节时不产生空白卡位；
- 当天五节课程应完整显示五行；周历与今日列表合计超过可视高度时，允许右侧课程区整体纵向滚动；
- 左侧玩法栏在右侧课程区滚动时保持稳定；日期卡和今日列表内部不各自制造嵌套滚动条；
- 课程表课节卡必须整体可点击：未开始课节先打开核心知识点导航预览；学习中课节恢复暂停学习后保留的原始可写会话；已放弃课节打开恢复学习导航，并在确认后解除原始会话冻结；已完成课节打开只读课节记录；
- 核心知识点导航预览只读取确认版大纲中的 `LessonDefinition.coreKnowledgePoints`，不得临时重新生成；仅打开或关闭预览不得产生学习历史；
- 已完成课节的记录页顶部提供“学习对话 / 课时 Review”两个同级 Tab，分别保留原始主学习对话和权威 Review Markdown；
- 完成态入口统一使用“点击查看课节记录”，不使用“查看 Review”或其他变体误导为单一内容；
- 日期格与今日列表必须使用同一 `LearningScheduleReadModel`，不得出现名称或数量不一致；
- 支持状态筛选、课程筛选和月份切换；
- 课程规划页保持左侧未来七天、右侧课节池的双栏结构；
- 课程规划页桌面端左右栏等高且底边对齐；左侧未来七天卡片等分铺满栏高并保持稳定，右侧课节池内容超出时内部滚动；
- 左侧未来七天的日期卡整体可点击，并作为右侧课节池的日期筛选器；当前选中日期必须保持明确高亮；
- 点击日期卡后，右侧立即按课节的计划日期筛选；无安排日期显示带具体日期的空状态，不保留上一日期的结果；
- 日期筛选与“排期状态 + 主题标签”筛选是两种互斥模式：选择日期时清空栏位筛选，操作任一栏位筛选时取消日期选中；不得把日期条件与栏位条件叠加为交集；
- 未排期课节不属于任何日期，用户选择“待规划”状态时清除日期限制并显示未排期课节；
- 课程规划筛选使用“排期状态 + 主题标签”，不得保留思维模式筛选；
- 主题标签筛选读取课程的一至三个 `topicTags`，同一课节可被任一所属标签命中；
- 支持从条目打开对应正式课程或课节；
- 空状态明确区分无课程、无排期和筛选无结果；
- 状态统计至少包含总数、今日、逾期、已计划、未计划和已完成。

### 6.4 单课节排期

- 用户可为任意未完成且未放弃的课节选择日期；
- 未排期课节使用“点击安排学习日期”入口，不直接显示空白日期格式；
- 点击“点击安排学习日期”或已排期日期直接展开紧贴按钮的非模态日期选择层；选择日期立即更新排期，关闭选择层不改变原排期；
- “取消排期”只在课节已有计划日期时显示，未排期课节不得出现该操作；
- 课程规划中的“预览”复用课节导航弹窗的视觉模板和核心知识点结构，但不提供“开始学习/打开课程”按钮，仅允许关闭并返回规划页；
- 手动修改计划流条目后，该条目标记为锁定；
- 取消排期只取消当前课节，不删除所属计划流；
- 写入需串行，避免并发覆盖；
- 排期成功、取消和失败均有明确反馈。
- 取消排期后课节立即恢复待规划状态和“点击安排学习日期”入口，不弹出二次确认框。
- 课程规划提供“清空排期”，以排期集合版本执行原子批量取消；保留排期历史和取消原因，不删除完成事实，版本冲突时不得部分清空。

## 7. 计划流

### 7.1 四步向导

保持四步逻辑：

1. 学习节奏：开始日期、每日分钟数、学习日、逾期重排规则；
2. 选择课程：只列出存在未完成且未放弃课节的正式课程；
3. 排期策略：均衡推进、专注完成、按优先级；
4. 预览确认：显示日期、课节、时长、超目标和固定条目。

预览只计算不写入；确认后才批量写入。

每日分钟数统一应用于全部已选学习日；快捷项为 15、30、45、60、90 分钟，另支持不低于 15 分钟且以 15 分钟递增的自定义值。每周预计时长实时等于选中学习日数量乘以每日分钟数，并以“小时 + 分钟”展示。

### 7.2 排期不变量

- 同一课程严格按正式大纲课节顺序排期；无显式先修边时也不得跳过尚未完成的前置课节；
- 不拆分单节课；
- 单节超过每日目标时允许单独排入并标记 `overTarget`；
- 已完成、已取消、手动锁定条目不参与普通重排；
- 未来已有日期默认保留；
- 只有用户显式开启逾期重排时，逾期未完成条目才重新进入候选；
- 排期找不到有效学习日时失败，不写入部分结果；
- 时长缺失时使用课程默认值，并在预览显示回退警告。

### 7.3 生命周期

- 创建：保存计划流并原子写入全部分配；
- 暂停：不再自动调整，已有排期保留；
- 恢复：继续处理剩余未完成且未锁定条目；
- 重排：只修改未来、未完成、未锁定的所属条目；
- 删除：删除该计划流产生的未来未锁定排期，历史完成事实保留。

### 7.4 向导与管理界面

- 计划流从课程规划页以固定大弹窗进入，不跳转到独立页面；背景课程规划页保持可识别但不可操作；
- 弹窗保持“头部—四步导航—当前步骤内容—底部操作”四段稳定结构；
- 头部、步骤导航和底部操作固定，只有当前步骤内容区在内容超出时内部滚动；
- 四步分别为“学习节奏、选择课程、排期策略、预览确认”，不得继续使用旧“学习档案”术语；
- 学习日使用七个等宽可点击单元；选择课程使用整体可点击课程卡；三种排期策略使用等高单选卡；
- 选择课程步骤只展示仍有未完成且未放弃课节的正式课程；仅剩已完成或已放弃课节的课程不以禁用卡占位；
- 可选课程超过四门时继续使用桌面双列卡片网格，不分页、不扩张弹窗高度，由当前步骤内容区统一滚动；
- 课程列表顶部提供粘性工具栏，至少包含课程搜索、学科/领域筛选、“只看已选”和实时选择汇总；工具栏随课程卡滚动保持可见；
- 移动端课程卡改为单列，筛选工具栏取消粘性并按单列排列；
- 预览顶部展示开始日期、预计完成日期、课节数和总时长，下方按日期展示每日课节、分钟数、超目标与固定排期标记；
- 预览超过六个学习日时不分页、不截断，按本地自然周分组继续展示全部日期；日期卡在桌面端三列、中等宽度两列、移动端单列；
- 长计划由当前步骤内容区统一滚动，预览标题与汇总指标可在内容区顶部粘性保持；周分组标题、日期顺序和计划结束位置必须明确；
- 前端不得沿用旧版“只取前十四天”等硬截断；确认前用户必须能够检查计划流返回的全部排期日期；
- 关闭或取消向导不得写入排期；确认按钮只在预览步骤出现，并明确“确认后才写入”；
- 创建成功后回到课程规划页，以计划流管理卡展示状态、每日目标、学习日、课程数、剩余课节和预计完成日期；
- 已确认计划流只提供“撤回排期”；暂停、恢复、重新排剩余和删除计划流不属于当前业务面；
- 首次确认保存该批自动排期写入前快照；撤回只恢复该批计划流自动排期，不修改无冲突手工排期；批次内排期被手工修改或恢复时发生排期冲突，整批撤回必须失败且不产生部分写入；
- 计划流中的课节被放弃后立即退出剩余排期集合，既有排期转为取消并保留历史；恢复课节不会静默重新加入原计划流，须由用户重新选择或重新排期；
- 移动端字段、课程卡、策略卡和预览卡改为单列，步骤导航可横向滚动，底部操作顺序保持稳定。

## 8. 历史记录与历史统计

### 8.1 历史记录信息架构

历史功能固定为历史统计、学习日历两个同级 Tab、两个视图和两个独立页面资源，不提供课程聚合式“历史回顾”页面。

进入历史页时加载历史事实；进入统计 Tab 时加载统计读模型。加载失败不影响返回首页。

### 8.2 统计事实层

至少提供：

- 已完成课节数；
- 已关闭课程数；
- 已完成课节累计实际学习时长；
- 活跃学习天数；
- 最近学习时间；
- 当前连续和最长连续学习天数；
- 学科分布、主题分布、课程模式分布和课程投入分布；
- 结构化关键互动发起数、用户回应数、跳过数、有关键互动课节占比和关键互动回应率；
- Review 覆盖率；
- 日、周、月趋势；
- 历史课程清单所需的课程状态、完成/放弃处置、实际学习时长和最近完成时间。

统计区只回答“发生了什么”，不直接输出人格判断。

“提问总数”“每课平均提问数”和“有效回复数”不是纯事实口径：自由对话中的提问和有效性需要语义判断，因此不得进入历史统计。用户主动提问及其内容特点只能作为画像候选证据参与复合分析。

### 8.3 统计快照与全局学习档案同步

- 历史统计和全局学习档案读取同一套事实投影和口径版本，不得分别扫描原始数据；
- 《历史统计与学习画像数据源定义清单》中的全部学习统计都必须同步进入全局学习档案，不以前端当前是否展示为条件；
- 每项统计必须保存累计值、日/周/月时间序列、近期/中期/长期窗口、维度、样本量、排除项、完整性、计算时间和来源游标；
- 历史统计前端只选择已确认的可复算事实展示；全局用户档案保留其独立的上游事实口径；
- 运行遥测、页面访问、Provider、延迟、错误和写入权细节禁止进入全局学习档案；
- 单项统计只能作为事实背景，不能直接升级为机制洞察或稳定偏好。

### 8.4 学习周报

- 汇总上一完整自然周最终完成的课节数、领域分布，以及根据课节标题和一句话摘要归纳的主要学习成果；未完成或已放弃课节不进入完成口径，时长、暂停、互动、教学观察和画像等数据不进入周报；
- 完整周固定为本地时区的周一 00:00 至下周一 00:00；服务端调度器在每周一 00:00 自动生成上一完整周报告，不依赖用户打开页面；
- 同一周使用稳定周键保证幂等，重复启动或重试不得生成多份并列报告；
- 无数据时显示稳定空状态；
- 生成中显示状态；
- AI 失败时保留上一版并允许重新生成；
- 周报只基于已记录事实，不补造学习活动；
- 上周学习报告使用可展开/收起组件，整个标题栏可点击并支持键盘操作；
- 学习周报仅出现在“上周学习回顾”界面，不放置在主页；
- 周报进入页面时默认收起；收起态显示周范围、生成状态和 `+`，展开态显示 `−` 与不超过 300 字的单一学习成果概括，不显示空的“下周建议”分栏；
- 展开状态属于短期 UI 状态，不影响报告生成、存档或历史事实。

### 8.5 上周学习回顾页

- 保持左侧上周七天、右侧周报与已完成课节列表的双栏结构；
- 上周回顾页桌面端左右栏等高且底边对齐；左侧上周七天卡片等分铺满栏高并保持稳定，右侧周报与课节列表内容超出时内部滚动；
- 左侧上周七天的日期卡整体可点击；点击后右侧只显示该本地自然日实际完成的课节，选中态与右侧日期必须一致；
- 上周回顾的日期筛选依据实际完成时间，不依据计划日期；无完成记录时显示该日期的空状态；
- 上周日期筛选与“学科/领域标签 + 主题标签”筛选是两种互斥模式：选择日期时清空两个标签筛选，操作任一标签筛选时取消日期选中；不得把日期和标签条件做交集；
- 左侧日期只展示实际完成的课节，不展示仅排期未学习的课节；
- 右侧筛选使用“学科/领域标签 + 主题标签”；
- 学科/领域筛选读取唯一 `disciplineTag`，主题筛选读取一至三个 `topicTags`；
- 不显示、不保存、不兼容思维模式筛选；
- 已完成课节卡整体可点击并直接打开对应双 Tab 只读课节记录，不经过“打开课节记录”的二次确认弹窗；
- 课节记录页顶部只提供“返回主页”，底部只提供“返回课程大纲”；该页负责切换和阅读已有原始/补充会话，不提供新建补充学习入口；
- 周报展开状态、生成中、失败重试和上一版保留规则继续生效。
- 课程规划与上周回顾复现旧项目的用户交互能力框架，但不继承旧前端接口：筛选、日期联动、改期、取消、课节预览、计划流入口和打开课节记录等行为需要保留；旧 `data-*` 标记、控制器方法名、请求参数和状态枚举不作为新项目合同。

## 9. 学习日历

- 使用本地自然日和 `YYYY-MM-DD` 聚合；
- 学习日历只记录实际已完成的课节，不展示仅已排期但尚未学习的课节；
- 已放弃课节不产生完成事实，不进入学习日历或上周已完成课节列表；有有效证据时，其当前唯一的阶段 Review 保留在所属正式课程中并在最终闭环后被最终 Review 覆盖；无有效证据时不保留学习会话或 Review；
- 学习日历的日期网格直接展示当天具体课节名称，不得只使用圆点表示有学习记录；日期格空间不足时优先展示前两节名称，再显示剩余数量；
- 今日待学习课程不会因为计划日期是今天而出现在学习日历；只有完成事件产生后，才进入对应日期；
- 默认展示当前月，支持月份切换；
- 每日显示完成课节数和实际学习时长；
- 选中日期后显示当日完成课节列表；
- 当日历史课节卡整体可点击，打开对应双 Tab 只读课节记录；
- 主页“今日学习”列表中的待学习课节卡整体可点击，先打开与课节导航一致的核心知识点窗口；只有用户点击“开始学习”后才进入学习流程，关闭窗口不创建会话或历史；
- 同一天多课节全部保留；
- 空月份和空日期显示明确空状态；
- 日历只消费完成事件，不依据计划日期伪造完成事实。

## 10. 学习笔记

- 课时右侧提供本课笔记；控制区与实际时长移至对话顶部。
- 一次保存形成一条独立笔记，自动快照保存时间、学科、课程和课节。
- 保存后输入区清空，既有本课笔记继续可见；失败保留本地草稿。
- 笔记可逐条编辑、删除，并在首页“学习笔记”入口按学科、课程整理。
- 课程删除不删除笔记；笔记依赖自身元数据快照继续可读。

## 11. 学习事件、档案候选证据与遥测分流

- 事件采用追加写，不覆写历史；
- 每条事件有版本、时间、类型、来源、目标和净化后的 payload；
- 学习事件记录课程创建、课节开始/暂停/放弃/恢复/完成、关键互动发起/回应/跳过、Review、排期、计划流和补充学习归档；
- 历史打开、页面访问、玩法入口点击和 AI 切换属于产品或运行遥测，不能进入全局学习档案；
- 写事件失败不得阻断用户主操作；
- 事件中的长文本和敏感字段需裁剪/净化；
- 候选证据只在稳定检查点从受控来源增量提炼，允许输出零条，并必须绑定精确来源引用和来源组；
- 当前版本不生成学习画像，也不把档案证据消费为教学个性化输入。

## 12. AI Provider 状态监控与切换

当前运行时支持以下真实 Provider 配置：

- API-compatible：`baseUrl`、`model` 和 SecretStore 中的 `apiKey` handle；请求使用 Chat Completions SSE。
- Codex CLI：安全 argv 启动；模型、显示名、默认推理强度和允许档位均从当前 CLI/账号实时目录读取，界面不补造静态型号。
- 运行中心支持验证后切换和“一键重连”；重连会重新检查当前 Provider 并刷新状态。
- 自动 fallback 只在首个有效 delta 前执行；收到输出后不跨 Provider 拼接。

### 12.1 状态胶囊

全局显示：

- 当前 Provider；
- 当前模型；
- 已连接/未连接；
- 检查中与切换中状态；
- 可读诊断信息。

点击后打开设置面板。

### 12.2 Provider 管理

至少复现：

- Mock：用于确定性流程测试；
- Codex CLI：选择允许的子模型、重新连接、启动并检查；
- OpenAI/API-compatible：填写地址、模型和 API Key，验证成功后切换；
- 当前 Provider 健康检查；
- 切换过程中禁止并发切换；
- 验证失败时保留原 Provider，不产生半切换状态；
- API Key 不写入普通项目文件或前端持久化；
- 可配置 fallback，但 UI 必须能说明当前实际 Provider。

### 12.3 统一运行中心界面

- 顶部同时保留“AI 接口”和“本地服务”两个独立状态胶囊，不能合并为一个模糊的总体状态；
- 点击任一胶囊打开同一个运行中心，并自动定位到“AI 接口”或“本地服务”Tab；
- AI Tab 展示当前 Provider、模型、可用性、最近检查和实际运行 Provider，并使用等高卡片呈现 Mock、API-compatible、Codex CLI；
- 同一时间只展开一个 Provider 配置区；切换失败时保留原 Provider 和用户输入；
- 健康、检查中、未配置和失败必须同时使用状态点与文字表达，不能只依靠颜色；
- AI Provider 异常与本地服务异常必须独立展示：本地服务健康不代表 AI 可用，AI 异常也不应把本地服务标记为失败；
- 运行中心内容超出时只滚动面板内容区，背景页面、标题与 Tab 保持稳定。

## 13. 前后端一键重连与自愈

### 13.1 实例身份

- 运行时配置由唯一模块解析；
- 服务监听成功后写 manifest；
- manifest 至少记录 instanceId、PID、端口、项目根目录、配置指纹、buildId 和启动时间；
- 健康检查必须同时验证实例、端口、根目录和配置指纹，不能只检查 HTTP 200；
- 旧实例不能删除新实例 manifest。

### 13.2 重连流程

- 用户可点击全局服务状态发起重连；
- 如果页面由旧服务提供，允许调用本地启动/检查动作；
- 重连后轮询健康状态，有次数与超时上限；
- 恢复成功后刷新 AI 状态；
- 版本不一致时支持同步前端版本并刷新；
- `file://` 页面不猜测端口，必须给出明确启动提示；
- HTTP 页面默认同源，不隐式回退到硬编码旧端口。

### 13.3 Watcher 自愈

- 配置变化触发一次受控重启；
- 不并行拉起多个服务；
- 端口被外部进程占用时停止重试并给出诊断，不强杀；
- 启动失败使用有上限的退避；
- 防止重启风暴和孤儿实例；
- 启动、停止、状态、重启命令使用相同实例校验规则。

### 13.4 本地服务状态与自愈界面

- 本地服务 Tab 展示实例身份、PID/端口、项目根目录、buildId、配置指纹、Watcher 和最近检查时间；
- 健康核验逐项展示 HTTP 响应、实例与 manifest、项目根目录、前后端版本和端口所有权，不得只显示“准备就绪”；
- 自愈过程固定显示“核验实例、重连服务、等待健康、刷新 AI”四个阶段，并区分未开始、进行中、完成和失败；
- 一键重连、同步前端版本和重新诊断是不同操作，不得使用一个含义不明的“修复”按钮替代；
- 版本不一致时优先提示同步前端版本；服务断开时提示一键重连；端口被外部进程占用时显示诊断并停止自动重试；
- 自愈结果保留最近诊断记录，但只展示安全信息，不暴露密钥或敏感环境变量；
- 本地服务恢复成功后自动刷新 AI Provider 状态，并分别更新两个顶部胶囊；
- 使用缓存渲染页面时明确标记“非实时状态”，不能把最后一次缓存显示为当前健康。

## 14. AI 生成任务、加载与指标

### 14.1 任务调度

- 每种生成任务拥有稳定任务键；
- 重复请求可按任务类型选择 join 或 reject；
- 全局 AI 任务遵守并发上限；
- 课节对话、Review、画像和玩法生成不能互相覆盖；
- 任务支持 queued、running、completed、failed、cancelled、timeout；
- 用户刷新或离开时可取消指定任务组；
- 取消和超时产生稳定错误码。

### 14.2 动态估时

- 无历史时使用操作基线；
- 有足够历史时使用历史分位数校准；
- 对外提供预计总时长、剩余时长、进度、样本数和置信度；
- 估时超出时显示“仍在处理中”，不得倒退或伪造完成；
- 成功、失败、取消和超时均进入指标记录。

### 14.3 加载界面

- 显示当前操作名称、阶段、进度和预计时间；
- 消息发送和候选生成等局部操作必须在点击当帧提供就地反馈：用户消息即时出现、AI 区显示思考占位、候选区和按钮显示生成中；不得等服务端受理后才进入忙碌态；
- 服务端受理失败时恢复输入或原可操作状态；本地乐观消息、固定起始说明、思考占位和按钮忙碌态不得持久化，也不得进入统计、全局用户档案或画像证据；
- 页面重挂载后可从服务端任务恢复；
- 不可恢复时显示可操作提示；
- 关闭加载界面不等于取消任务，取消必须是显式动作；
- 不使用无限等待且无状态反馈的遮罩。

## 15. 本地存储、离线与国际化

### 15.1 本地存储

- 只保存短期 UI 草稿、筛选和可恢复选择；
- 服务端事实不得只存在浏览器；
- 提交成功后清理对应草稿；
- 草稿解析失败时安全回退，不阻断页面；
- 新项目使用独立 key 前缀，不读取旧项目 key。

### 15.2 离线与服务不可达

- 首页可使用最后一次安全缓存渲染基础壳；
- 明确显示服务不可达；
- 不把缓存状态伪装成实时事实；
- 恢复连接后重新拉取服务端读模型；
- 写操作失败时保留用户尚未提交的输入。

### 15.3 国际化与显示安全

- 用户可见文本由统一国际化资源管理；
- 缺失 key 有可读回退；
- 防止乱码、损坏标签和未绑定按钮；
- 所有 AI Markdown 在渲染前净化；
- 内部枚举、Prompt 字段和英文实现术语不得直接展示。

## 16. Repository seam

新项目初期使用本地文件 adapter，但领域模块只能依赖 Repository interface。

至少定义：

- CourseRepository；
- OutlineSessionRepository；
- LessonSessionRepository；
- ReviewRepository；
- LearningEventRepository；
- ScheduleRepository；
- PlanFlowRepository；
- MaterialRepository；
- PortraitEvidenceRepository；
- GlobalLearningProfileRepository；
- PortraitRepository；
- RuntimeManifestRepository。

本地文件 adapter 负责目录、JSON/Markdown、原子替换、文件锁和损坏恢复。未来数据库 adapter 必须通过同一合同测试。

## 18. 验收方法

每项等价能力至少包含：

1. 纯领域规则测试；
2. Repository 合同测试；
3. 后端集成测试；
4. React 页面交互测试；
5. 一条端到端主路径；
6. 一条失败/恢复路径。

旧测试不得原样搬运并继续断言旧文件内容或 DOM 字符串。应把旧测试表达的用户行为重新写成共享合同和可观察结果测试。
